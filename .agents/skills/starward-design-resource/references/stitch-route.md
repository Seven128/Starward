# Starward 的 Stitch 补充

先读包内 [Stitch operations](../../../../node_modules/project-tiny-context-harness/assets/skills/design-resource/references/stitch.md)。操作选择、未知结果恢复、原稿获取和交付沿用上游，本文件补充 Starward 的 CLI 连接、输入与观察方式。

小程序每次打开或续改 Stitch 前，先从[现有 Screen Contract 的 Stitch 入口](../../../../project_context/areas/main/screen-contracts/wechat-miniapp.md#stitch-design-authority)取得当前项目，沿受影响 owner 核节点、状态、采用范围及实际可编辑源。历史本地导出不作基线；跨分支当前源以 Stitch 为准，不反向覆盖别人的修订。不在 Skill 写死项目 ID。

## 官方 Stitch CLI

可以复用 Google Labs 发布的 [`@google/stitch`](https://www.npmjs.com/package/@google/stitch)，其 `stitch` CLI 与 `stitch mcp start` 均是同一 Stitch 服务入口。宿主没有可用 MCP、或 CLI 适合本次上传/导出时直接使用 CLI，无需安装另一个 Agent 或自建适配服务；网站回退遵守项目 Browser/Chrome 规则。Chrome 安装的网站应用本身不代表已有本地 MCP。

- 优先复用已安装或缓存的 CLI，必要时在用户授权范围内临时使用发布包；不将开发工具加入产品依赖，不改无关编辑器配置。先读当前 `--help`、所需子命令 `--schema`，不要从某次版本复制模型枚举或假设参数。`mcp install` 可能默认改多个编辑器，不能因只需调用 CLI 就执行它。
- `stitch status --json` 只证明认证状态；通过 `stitch get project <当前入口ID> --json` 核实际 ID/标题，再核受影响 screen。**微信小程序**沿 当前 Screen Contract 的 Stitch 入口、小程序 DESIGN/Screen Contract 操作，不借原生 App 或同名历史项目替代。读取、上传、生成、导出与采用分别记录，枚举接口口径不一致也不能据此删除内容。
- 认证沿 CLI 当前支持的 OAuth/官方 API key 与其凭证存储。复用已授权账号，必要的 Google 登录用支持的浏览器操作；只在实际缺少 MFA/外部授权时请求用户。OAuth 能读项目却对 HTML 上传返回403时，重新登录不一定改变权限；可在已有授权范围内改用官方设置提供的 API key，并经 CLI 保存到其本机凭证配置。新建持久凭证遵守宿主授权规则，不顺带安装编辑器/MCP配置。凭证只在内存中传给官方入口，不进入提示词、参数示例、日志、资源包或 Context，不用 `status --token` 输出令牌。账号登录成功仍须核目标项目实际访问。
- 参考图用当前 `upload screen` 支持的文件上传，并保返回的 screen 身份；文字中的本地路径不算图片输入。设计简报可随生成 prompt 提供，只有确实需要新增/应用设计系统时才用 `upload design`，不顺带改共享项目其它页面主题。用 `generate screen` / `generate variant` 等当前实际能力；真实输出、可编辑源及交互支持分开检查。
- Windows 经 `npm`/`cmd` 转发长 JSON 可能丢引号。若明确返回提交前 `INVALID_JSON_PAYLOAD`，改用已发现的官方原生入口 `node <已安装或缓存的CLI入口> ...` 与文档支持的 `--prompt` 等参数，或当前 CLI 支持的结构化输入；文本从 UTF-8 文件读入变量，避免拼进 shell 命令。依上游及本文件的安全重试限制处理，不能把参数修正变成未知写入重提。
- 若服务已返回成功/输出 ID，随后出现 `UV_HANDLE_CLOSING` 等本地退出异常，分别保留服务结果与 CLI 退出值，读回返回的具体资源；不要把非零退出等同未提交并再生成。超时或断线沿上游有界读回，保全部实际生成结果。导出使用真实返回的 HTML/截图资源；静态、可运行与原生实现不互相冒充。
- **一端不通就换另一端。** 对本次所需操作，MCP/CLI明确失败、或有界观察持续没有有效进展时，主动切官方网页版；网页版实际不可用时，切已验证的MCP/CLI，复用同一项目、原画板及已完成成果，不守着失效入口空等，也不因轮询上限尚未用完而继续无效等待。只有新原因/新状态能使重试有区分力时才回到原端。未知写入跨端先查原资源/操作，不点击第二次生成或重新发送同一修订；仍不可判定则保UNKNOWN并推进独立工作，报告具体能力缺口。
- CLI返回可单独读取的screen不一定已出现在项目画布实例或`find screens`列表，枚举遗漏不证明未生成。跨端恢复时实际核同项目的Agent log、画板标题/身份和导出，保留原超时结果与恢复后的新身份；能读回具体结果后再决定是否需要新的不同修订。
- 网页多行提示词优先用受支持的粘贴接口一次填入，核对草稿完整、目标画板和提交按钮后只提交一次；不要把带换行的长文当逐键输入，换行可能触发发送。若界面已拆分提交，停止追加，核对已经发出的段落与返回结果；不再重发完整文制造重复输出。实际分段与全部产物记在任务资源中，不把输入预期冒充服务实际接收内容。
- 核当前身份、跨端新结果或上传回读时，若当前CLI支持`--no-cache`，使用它排除旧本地枚举。下载后核实际HTML标题/内容、图片格式与可运行能力；HTTP成功、文件扩展名及`downloadUrl`不证明拿到设计源，登录重定向页和无脚本静态源都不能当完整交互稿。官方返回的 `stitch.googleapis.com/...:download` 可能需要同账号 API key，且响应为含 `dataString` 的 JSON；先核 HTTPS 和精确官方主机再按实际格式解码，不把 JSON 包装当 HTML，也不向跳转后的其它域名传凭证。上传迁移可用解码后内容与实际提交源的一致性确认完整保留；普通实现不因此新增每次镜像/哈希门槛。其它缺口换官方网页ZIP或已验证导出，保失败状态，不盲改凭证/重复生成。
- 清理能力按当前实际 CLI/MCP schema 核实；只有 `delete project` 时不能用它代替删 screen。单节点删除不可用时转网页已确认节点的 Delete，不猜批量接口、不整表覆盖 `screenInstances`，避免覆盖并行分支。Stitch 网页 Delete 可在服务端保留 `hidden:true` 实例供撤销/历史；以实际 Delete 动作及活动画布读回说明完成范围，不误称永久擦除，也不把直接改 hidden 字段冒充 Delete。按明确 ID 核本批节点和受保护节点；名称带相同业务词不证明属于本批。多选后先读实际选中 ID，再删除，不默认修饰键已选成功。
- 当前`upload screen`支持HTML及图像，可在原稿保全、改动明确的前提下，把本地必要适配或实际渲染的状态总览回传同一授权项目。分别标注Stitch原稿、本地适配、静态运行快照和回传节点；上传成功不使适配冒称提供方原稿，也不使静态快照变成原生组件或交互验收。只核本次文件与返回身份，不顺带写`--route`或修改其它页面。
- 上传HTML先用当前CLI支持的`--dry-run`核输入与过滤警告。若把`--sk-`等CSS变量名误识为secret，先确认所有匹配确属设计变量，再一致更换CSS命名空间，保留凭证过滤；未知匹配不能绕过。认证状态有效、项目可读仍不证明所有写入能力获权：某一格式403时保明确失败和无缓存项目读回，改用已验证格式或网页能力；图像回传应明确是静态总览，不宣称完整可编辑HTML已同步。

## 输入、观察与收敛

- 按 [设计方法](design-method.md) 和 DESIGN.md 小程序 §1.3，把首屏重心、比例/密度、对象卡片、图标质感及适用交互组织成正向输入。业务图保留信息职责，视觉参考指出具体区域和用途；不把整张未认可候选当作风格规范。参考必须通过真实支持的上传/粘贴到达 Stitch，文字中的本地路径不是上传。
- 首稿用一致的手机内容视口查看，保留原始导出尺寸；不借设备外壳、装饰背景或不同缩放美化比较。产品画面外放候选名、比较说明与代表数据的非实时说明，产品画面内保留真实需要的信息结构。平台、字级、命中和状态范围从当前 owner 读取。
- 原请求包含精致页面时，在同一方向内主动修订已发现的整体比例、阅读层级、控件质感和状态连续性问题，再交付用户；数量/预算仍遵循当前任务。修改输入区分用户原话与 Agent 检查发现，明确保留项。探索期间临时保留原稿和修订用于核对，按[资源生命周期](../../../../project_context/context-maintenance.md#design-resource-lifecycle)定稿收敛和清理；不能把本地修复算作 Stitch 一次生成效果。
- 生成或修改结果不确定时，严格沿用上游读回与有界恢复，不因超时重复提交。已确认提交前失败，修正具体原因后最多一次安全技术重试；再次失败就报告。该限制不缩短仍在执行操作的正常读回，也不替代服务当前恢复规则。
- 用任务临时目录保存本次必要的输入与结果；长期资源仅在 Stitch，任务只保有用结论/身份/失败证据。模型/模式、用量、HEAD/哈希仅在比较或追溯需要时记录；未知模型为 `unknown`，未知用量为 `null` 并说明。复做旧 Codex A/B 方法试验时才沿用原模型一致性与记录要求，默认设计工作不受旧试验门槛约束。
- 定稿清理沿[资源生命周期](../../../../project_context/context-maintenance.md#design-resource-lifecycle)核准范围和实际依赖；复用已有明确删除授权，不重复确认。完整可编辑内容、动效和必要状态在远端读回后才退休唯一临时源。只处理授权节点，保其他分支/页面；失败不能以静态图、隐藏或本地删除冒远端收敛。
- 同步核对分别看具体 screen 的完整源与项目中的活动画布实例。二者可能暂时不一致：后续画布更新中实例缺失不等于完整源已丢失。先读回身份、内容和当前成员，保其未知原因；能复挂原节点时复用，能力确实缺失而需恢复导入时说明原因，只恢复已核同一内容，重新核当前入口及其他节点。不要因非零退出、枚举遗漏或页面空白重复生成。保必要临时源到远端内容完整成立，回收本地唯一源前保存许可/实际产品证据；定稿后不把临时 QA 截图转成长期仓库镜像。
- 只使用当前任务授权的工具与额度，遵循项目试用/预算边界；工具选择不扩大付费、公开分享或生产迁移权限。需要 Figma 时做独立下游转换，沿用既有引用与检查器。

# Starward astronomical imagery

把真实天文照片中的星体或连续天区，制成可在云观星按位置、尺度和LOD叠加展示的素材：保留真实结构、弱外围、几何、颜色含义与来源，使照片底色/边界和照片恒星不破坏整体星空。透明形式由实际合成合同决定，星云软晕、暗尘带和内部暗区都是需保留与复核的内容。

本技能覆盖**合规天文影像供给、按需处理与接入**，不是默认全批精修。来源按需分批获取，每个就绪批次即可预检、分流，不等待全库下载；供给与像素处理保持独立职责，通过现有来源声明、候选和复核合同衔接。

**SXT只是适用素材的去星环节。** 实际Scene预检在昂贵加工之前，能直接显示的原图/成品不先做去星、PSD或NXT；去星误删/残留、背景与噪声、局部修复按需进入原指南。星团、已分辨星系、月球/行星等不能一律套去星。采用的具体来源、工具与合同仍由各Context/源码owner持有。

项目 AGENTS、用户要求和当前唯一方案控制范围；本技能不新增采购、外联、发布或方案修改权限。流程成立就批量应用，真正例外留队列。

## 何时加载

判断任务是否涉及“天文图像 → 云观星显示素材”这条生产链，而不是只匹配SXT或抠图关键词。寻找/批量获取合规天文影像、接入已有成品、提取星云主体、查黑框/残星环/弱结构丢失、修处理缓存或顺序、验证素材融合，均加载本技能。只查天体坐标/星表、改姿态/时间计算、普通页面UI或通用缓存，以及制作海报/封面、普通照片抠图，不自动加载；若其中实际涉及此生产链，再按影响读取。

## 遇到未知机制时主动调研

出现下列任一情形，先补同机制的成熟资料，再开始下一次昂贵加工或扩大接入：

- 输入的颜色/线性状态、覆盖、结构类别或尺度超出既有配方适用范围，现有经验不足以决定方法。
- 实际结果反驳当前假设，或下一次尝试说不清新依据、预期变化和如何判定，只剩重复推理/盲调参数。
- 为消除底色、残星或接缝而损失弱结构，或文件通过但真实Scene仍失败，当前方法未解释这个矛盾。
- 准备新增工具/模型或自建复杂算法，却未核可复用的成熟方法及其适用条件。

已知原因的普通修复、输入格式错误和仍适用的已验证批次按原规则处理。先查已沉淀资料；条件未变且已足够回答，不重复上网选型。条件有变化或仍有实质缺口时主动外部调研，无需用户再提醒。

1. **把现象变成可回答的问题。** 固定原输入/颜色状态、实际消费者和失效尺度，分清来源缺口、模型误删、背景梯度/噪声、颜色与合成、几何、编码/采样问题。文件预览与实际 Scene 不一致时先查消费者，不能继续只改文件。
2. **先查同机制的成熟工作流。** 从 owner 的已查资料开始，只重开有新证据的缺口。查项目官方文档、源码及维护者实例；社区讨论用于定位方法，再核适用版本、输入假设、真实调用和加工/集成成本。得到能区分下一步的适用方法、限制或缺失条件即可收束，不扩成工具大全。工具名相同、一个 blend flag 或漂亮截图不证明整条加工链。
3. **写短的判定依据再试。** 在现有证据记录写清待解问题、参考方法为什么适合此输入、最小代表/反例、必须保留的结构和可决定的读回，以及何时扩批或退出。使用当前已缓存图和输出；不要先为未证明有效的方法建完整 producer、重做全套页面或铺开参数网格。
4. **按结果转移工作。** 有收益且边界清楚才接共享配方并批量应用。未解决或引入损失，保留 FAILED/UNKNOWN 和退出原因；只有新输入、根因或适用成熟方法才重开。来源不足则补源/换源。一个异常不冻结独立适用批次。

## 天文图像的关键区别

- 先分线性观测数据、已拉伸显示 RGB、已有 alpha/缺测的区域。JPEG 转浮点或逆 sRGB 不会恢复观测线性、动态范围或科学噪声模型。
- 供给/缺测 mask、背景估计时的源排除 mask、显示贡献/软蒙版分别有含义。有效黑仍有来源；显示不贡献不能伪装成缺测；目录轴径不自动是真实弱结构轮廓。
- 背景建模、降噪、显示黑位/贡献准备和最终合成是不同职责。扣除平滑背景不保证残余噪声为零；换成 RGBA 或 Screen/Add 也不自动消除非零底色。操作沿[异常与融合指南](references/exceptions-and-fusion.md)，当前采用的显示含义沿[背景Context](../../../project_context/development-workflow/resources-and-artifacts.md#astronomical-background-and-display)。
- 保留整幅工作图、颜色/位深、真实几何和加工顺序；在整图/连续区完成需上下文的处理后生成 LOD。不得用裁边、几何羽化、通用抠黑或生成细节掩盖真实外围缺口。拟采用显示软蒙版时保留独立源支持与可审编辑层，验证弱结构、暗尘带和内部暗区，不把“更透明”单独当质量提升。
- 去星不等于删除所有亮小结构。已分辨星系、星团、致密星云结、中心星和前景恒星不能仅凭亮度同处理。局部恢复必须复核恢复区与周围的纹理/星密度连续性。

## 批量验证与投入控制

全批自动核输入/输出身份、颜色/几何、合同和部分失败；按当前显示标准集中看整图、关键ROI和实际Scene，仅加工分支补相应星层/差异。诊断放大/差分不自动升级为像素级零误差门槛；标准改变时可对精确旧成果另作有范围的新决定，保留旧失败，不为重判重加工。新融合方法用小的实际消费者路径尽早排错，通过后才扩大同机制组。照片星与目录星协调的代表必须确有相应目录星；空场成功不证明协调。

来源、缓存、LOD、Back/退出及资源退休按共享机制在模块/批次节点验证；不为新增同类对象逐个重走完整页面。内容质量结论仍绑定各自素材。先批量修复再跑受影响检查，沿原责任保留目标原生/设备/独审/容量未验项。

记录会影响决策的模型调用、下载/编码复用、处理/复核耗时及相关资源瓶颈。输出、质量决定和适用证据身份不变则复用；诊断成功后导入精确已有结果，不能为了统一回执重新跑模型。

## 主动沉淀，不积累流水账

执行本技能的agent也负责在现有授权内维护本技能。出现可复用收益、反复陷阱、适用边界变化或决定性失败后，在本轮收口前判断是否需要更新；不等用户提醒，不要求每张图或每次调用都改skill。

**准入问题：这条经验会让下一次同机制工作改变动作、避免已发生的错误或省掉重复投入吗？** 若只记录本次对象、参数、耗时或“又失败了”，留任务证据。一次高代价失败也可沉淀明确的适用/退出条件，但只能写证据支持的范围；推测留候选，不能改成自动放行规则。

| --- | --- |
| 适用输入/问题、已确认选择、原因、反例/限制、重开条件、出处及复用入口 | 对应 Context；替换过时结论，未验证建议明确标为候选 |

更新顺序：

1. 先找到现有同机制条目，按“适用条件 → 方法/入口 → 已观察收益 → 不适用或失败条件 → 证据与重评条件”形成最小结论。确认、有限实测和待试候选分别表述。
2. 按上表写入唯一owner。优先修订、合并或替换旧规则；保留旧决定被推翻的原因与证据入口，不追加互相竞争的建议或每颗星体的案例。通用操作才改本技能，项目采用决定不搬进技能。
3. 已能自动执行的稳定步骤收敛到原批处理/校验入口，技能只保留调用、适用边界和例外。新增规则若没有新的决策作用就不加入；篇幅增长先去重/归责，只有独立机制确需按需读取才拆一层引用，不建递归经验目录。
4. 检查与上游要求、Context和实际入口是否一致，移除同责任下已失效的重复指引。修改触发范围时同步description/AGENTS入口，并用实际任务的正例、反例和隐含图像任务走查；修改操作方法时复用对应事实/失败反例核边界。改本文件后运行skill-creator的quick_validate并核链接；格式通过不冒行为或独立验收。

自身更新不能改用户目标、权限或质量标准，不能把已知失败改写成通过。需要改变方案/架构时遵守当前授权；局部经验沉淀不重启前期、不创建第二Goal。没有新知识就保持原文。

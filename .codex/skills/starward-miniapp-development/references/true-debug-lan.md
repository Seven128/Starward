# VPN/TUN 开启时的局域网真机调试

用于换电脑恢复环境或修复真实连接故障。目标是在保留 VPN/TUN 的情况下，让测试手机与电脑的**真机调试开发者工具窗口**直接通信，并使用其中的 Performance / Memory。主用方案已确定；已可用的会话直接复用，不逐项验证所有 profiler 功能。设备授权、截图/输入和源码候选绑定沿[设备 skill](../../starward-wechat-device-verification/SKILL.md)执行。

## 先分清三条通路

| 通路 | 作用 | 不能据此推断 |
| --- | --- | --- |
| 微信真机调试 LAN | 手机连接电脑实际启动的调试服务 | 勾选LAN、生成二维码或USB已连接，不代表已走LAN。 |
| 小程序业务请求 | 获取本地API、运行数据和资源 | 真机调试不自动转发业务API；手机的127.0.0.1是手机自身。 |
| USB或配对的无线ADB | 授权目标的独立观察与操作 | Android无线调试关闭，不代表USB或微信LAN不能使用。 |

复用项目已有的数据准备、API/只读桥及明确配置的USB转发。分别检查必要通路，避免用恢复业务服务的操作处理调试握手问题。

## 选择手机可直达的网络

- 两台设备连接同一个允许设备互通的路由器，是直接的拓扑。相同SSID不保证互通；酒店/访客Wi-Fi可能隔离客户端。
- 如果酒店网络不允许互通，可让**电脑继续连接酒店Wi-Fi和VPN/TUN，再开Windows移动热点，测试手机连接电脑热点**。电脑共享现有Wi-Fi不需要流量卡，但仍取决于本机热点能力与正确的Internet共享。
- 测试手机自己开热点也可作为候选；不把一次失败写成平台永久不支持。手机热点对无线ADB的限制与微信LAN、USB是不同问题。

先确认当前网卡、IPv4、手机所在网段和实际路由，不套用另一电脑的地址：

```powershell
Get-NetAdapter -IncludeHidden | Select-Object Name, InterfaceIndex, Status, InterfaceDescription
Get-NetIPAddress -AddressFamily IPv4 | Select-Object InterfaceAlias, InterfaceIndex, IPAddress, PrefixLength
Get-NetConnectionProfile | Select-Object InterfaceAlias, InterfaceIndex, NetworkCategory
```

**调试二维码应选电脑面向手机的地址。** 手机连电脑热点时，选当前Wi-Fi Direct/热点适配器的IPv4；两台连独立路由器时，选电脑在该LAN的地址。不要固定选酒店WLAN上行，也不要选VPN/TUN、Hyper-V或无关虚拟网卡地址。热点常用的私网地址不是跨电脑的固定合同。

## 电脑热点已连接，但手机无法正常上网

二维码启动仍可能需要微信登录、网络握手及包下载；仅能访问电脑并不足够。保持VPN/TUN，先区分本地连通、公网连通和域名解析：

1. 从已授权手机目标检查到电脑的路径，并对实际目标做有界探测。需要区分蜂窝回退时，将探测绑定到手机当前Wi-Fi源地址，或核对系统的实际默认网络；电脑本机的测试不能替代手机测试。
2. 若公网IP连接可用而域名失败，检查手机实际使用的DNS回复。某些TUN使用虚拟地址映射（例如198.18.0.0/15）；收到这类地址本身并非错误，但手机后续流量也必须进入能解释它的VPN出口。不要把这个现象概括成所有流量均未转发，也不要直接改公共DNS或全局代理。
3. 当Windows热点仍共享原WLAN、而VPN出口与上述DNS/转发路径不匹配时，检查**Windows Internet连接共享（ICS）**。可把现有VPN虚拟网卡作为共享出口、当前热点虚拟网卡作为下行；名称可能是Meta等，以实际适配器为准。操作前保全原共享pair，保留无关共享用途；操作后读回设置并验证手机域名访问及实际默认Wi-Fi状态。只调整本次Windows共享，不更改VPN客户端节点、TUN规则或全局路由。

Windows“移动热点”的来源下拉框在热点运行时可能被锁定；停止本次热点后才能查看。下拉中只有WLAN，不表示VPN虚拟网卡不存在。需要共享该出口时，系统入口是 **网络连接 → 实际VPN网卡 → 属性 → 共享 → 允许其他网络用户连接 → 当前热点网卡**。不要把酒店上行网卡选成家庭网络下行。

先按Windows管理规则检查实际提升令牌，使用获准的管理入口完成可自动处理的操作。启动辅助进程不等于共享已生效；原生接口失败时核实并恢复部分改动。若当前工具无法完成系统面板交互，再交给用户这一小段操作，不让用户重跑整套环境准备。不要为恢复ICS盲目重启网络服务、注册DLL或放宽执行策略。

## 发起并保留正确的调试窗口

1. 复用当前源码对应的完整编译候选和准确导入路径，沿官方skill完成打开、登录和真机调试调用。需要指定测试手机时，使用**二维码真机调试**；“自动真机调试”可能选择桌面微信账号对应的另一台设备。
2. 在二维码界面勾选“局域网模式”，通过“切换IP”选择上述手机可达地址。新窗口、重新生成二维码或切换网络后检查实际选择，不沿用记忆中的IP。
3. **保持独立真机调试开发者工具窗口打开**，可以最小化。该窗口承担本次调试服务；关闭窗口或点“结束调试”会使会话/监听退出。二维码页面、项目编辑窗口和该调试窗口不是同一个生命周期。
4. 官方调用返回超时后先看实际窗口和监听，不能认定操作已取消。二维码可能已经生成；有现存有效二维码就继续这一次，避免重复发起。出现“等待进程”且尚无二维码时，先查IDE项目/工具启动边界，不从手机负载或LAN握手找原因。

如果在二维码出现前被包体限制拦住，沿官方project-config检查本版工具是否支持 `project.private.config.json` 的 `setting.bigPackageSizeSupport`，仅对当前开发候选启用必要的“大包预览/真机调试”。它不修复正式包预算、不授权重建冻结候选。IDE补写生成文件后核对实际差异，按公共owner重新绑定采集身份；不要循环删除生成物来维持旧指纹。

## 手机到实际调试端口的连通性

从当前二维码所用地址、实际对外监听和已核对的DevTools程序/进程确定调试端口。不要把开发工具自身的内部随机端口当LAN服务，也不要固定写死端口；新会话或切换IP可能改变它。进程身份确认后，可用 `Get-NetTCPConnection` 读取其监听和对端。

- 电脑本机可连、手机不可连时，检查手机路由/邻居解析、对应网卡的实际防火墙profile和精确程序规则。没有邻居可达路径时先处理拓扑，不能靠扩大Windows放行来解决酒店客户端隔离。
- Windows显式Block优先于Allow。存在匹配的阻断规则时，只新增Allow可能无效。由已有管理owner备份原规则，必要时建立**当前手机、当前本地地址/接口、实际DevTools程序及实际TCP端口**的有限例外；保留其它地址、端口和IPv6的保护，失败回滚并读回。不要关闭防火墙、整体移除阻断或把所有网卡设为可信。
- 手机到端口的TCP探测成功只说明连接层可达。扫码后再用实际手机对端的持续连接、运行画面/消息和必要的官方运行时读回确认本次会话。不要把DevTools自身的loopback连接当作手机连接；看到“LAN失败、切回广域网”就记录回退，不能认证为LAN。

探测参数以目标工具的实际能力为准，不能照搬桌面netcat的 `-z`。HTTP探测只读取有界状态/响应头，并区分“连接失败”和“连接成功后等待响应超时”；裸 `nc` 的非零退出并不总是未建立连接。

界面可能把连接方式显示为Wi-Fi、其它或暂时未连接。结合实际TCP、手机状态和有用运行时响应判断，不强求某个文字字段。重场景进入时若面板短暂异常而底层连接与手机仍在，保留现场，等待本次加载/一次有界读回；不要立即关窗、重复扫码、换版本或开始叠加采集。持续失败再处理对应边界。

## 使用与换机恢复边界

高内存场景连接可用且所需快照完整导出后，直接进入问题排查；不补做逐项功能验收。Performance/Memory按[性能方法](performance-investigation.md#primary-profiler)选择，关注实际数据而非仅看菜单或计数。

机器路径、SSID/密码、设备身份、当前IP/端口、进程和恢复回执留在本机任务证据。换电脑恢复相同职责和验证方式，不复制旧进程号、地址、私有脚本参数或防火墙规则。保持用户要求保留的候选、Harness和原件；在实际结束会话时，只恢复本次拥有且仍匹配的临时共享/防火墙改动。仍在使用的连接所需配置及后续清理责任应明确交接。

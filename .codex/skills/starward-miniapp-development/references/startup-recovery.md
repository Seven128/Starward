# 工具结果判读与启动恢复

此文是 Starward 项目补充，由官方 compiler / debugger / automator 场景按需配合使用；不是微信官方原文。复用已确认的项目、窗口及登录态；没有新失败证据时不重复环境检查或开窗。

## 先区分回执与实际结果

1. 按当前工具协议区分成功、待完成、失败和未知；进程退出码为0不等于业务成功。优先复用已有官方 observer / device-feedback 的响应解析；直接调用时也要核返回状态。前置失败或结果未知时停止其依赖步骤，待完成操作沿原句柄收结果，不凭路径名或已发起回执继续预览、输入等后续动作。
2. 编译 / 开页工具成功只证明窗口接收动作。先取**省略 `wait` 和 `waitForSelector`** 的 `simulator_screenshot`；按需读取范围受控的 Console。日志是缓存，空结果不能定因，过滤命中也不等于敏感字段已脱除。
3. 按实际状态分流：

| 实际状态 | 下一步 |
| --- | --- |
| 已进入应用 | 小程序用一次 `automation_runtime_info` 核当前页；小游戏按画布流程。随后才使用 selector 等待与交互 |
| 可见编译错误 | 处理具体错误后重新编译；不要用 SDK 调用等待一个尚未运行的应用 |
| 欢迎页 / 初始化页 | 留在启动排查。只在有编译进展或状态变化时做有界观察，不反复发 currentPage、evaluate、导航或带等待截图 |
| 应用可见，但自动化连接超时 | 归为自动化通道未就绪，保留可见应用事实；不据此宣称产品黑屏或运行失败 |

`wait` 与 `waitForSelector` 可能先获取自动化连接；初始截图带等待也可能卡在 SDK 启动，而不是截图本身失败。只有已确认应用运行及自动化可用，才用这些参数等待内容。

动作送达与随后截图/状态回读分别判断。回读失败时，保留动作已发出或结果未知的事实，先重新观察，不能重放整个“动作＋截图”调用来补截图。只有确认动作未执行，或其操作协议明确允许安全重试时，才重发动作。

## 限制重复调用

- 调用前明确本轮观察期限与成功条件；会返回 session / cell / task 句柄时，继续收原句柄，不重发原动作。区分工具的 pending 授权任务与执行宿主仍活跃的调用，沿各自查询接口收结果。
- 首轮只取最小状态证据；未就绪时，不并行排队多个依赖同一 SDK 的调用。一次连接超时后，先分流，再决定是否需要新的调用，避免把多个长超时串成排查流程。
- 区分调用参数/路径错误、执行或抓帧等待失败、观察时效拒绝及用户中止。参数错误先核当前入口文档和实际返回对象；观察过期按原owner重新取得并检查，不能靠延长调用超时、放宽时效或伪造时间戳恢复输入资格。用户中止/拒绝不作技术故障自动重试；一次捕获失败也不证明产品或网络失效。
- 仅在已获准使用桌面Computer Use时，沿当前入口的返回对象选择实际窗口，不混用不同入口的句柄或元素编号。窗口/布局变化、用户介入或观察失效后，重新取得该目标的状态再决定输入；当前几何或截图仍不可用时，不继续发送依赖旧坐标的动作。具体API和窗口恢复沿已安装Computer Use技能，不在本项目复制其协议。
- 观察期限到达不等于远端动作失败或取消。保留尚活跃句柄；没有取消能力时，停止新增依赖调用，继续独立工作。不要把 `Promise.race` 超时包装当成取消。
- 同一欢迎页或连接超时没有新进展时，停止该排查轮次。刷新、重开窗口、清缓存、改基础库或重建服务都要有对应故障证据；等待超时本身不是理由。
- 优先工具文档、已安装官方 CLI 的 `--help` 和公开 SDK。只有缺口会改变下一步且这些入口无法回答时，才做窄范围实现核查；已有调用语义不反复研究。

## 条件恢复：官方自动化启动

仅用于已确认的启动 / 自动化连接故障，**不是每次编译的默认步骤，也不保证成功**。先核对本机官方 CLI 的 `auto --help`，以及当前 SDK 是否提供公开 `connect`；不要为诊断默认安装依赖。

- 复用同一绝对项目路径、已运行 IDE 的 HTTP 端口与现有账号。分配未占用的自动化端口，CLI 参数以本机帮助为准；不要套用历史端口、项目路径或另一项目的配置。
- 不默认传测试 ticket、替换账号、覆盖 projectConfig、重开 IDE 或全局 `quit`。Windows 的 `.bat` 启动和含 `&` 的 query 要正确传参，避免查询被 shell 拆分。
- 将启动作为一次有截止条件的试验，保存必要的非敏感结果。**IDE HTTP 监听、AppID 确认或 CLI 退出码 0 都不证明自动化可用**；需确认自动化端口，并通过公开 SDK 读回当前应用 / 页面。
- 自动化端口未建立、或启动停在同一准备状态，到期限就停止本次试验；仅在核实身份后结束自己启动的 CLI 客户端，保留 IDE 和其它服务。客户端结束不证明服务端动作已取消，结束后只读检查实际画面，不立即再启动。
- 若端口可用，公开 SDK 连接和读回也须有界。脚本结束释放自建连接（`disconnect`）；不要用会关闭开发者工具的 `close` 代替释放。连接成功后确认实际页与待验证输入，不把默认首页当目标页。

## 移交只保恢复所需事实

带 `project`、已确认窗口 / 候选、实际画面或当前页、最后动作及其活跃句柄、未验证项与下一依赖。没有新状态时不继续诊断、不写逐次等待流水账；截图、日志和调用结果只在任务证据中保留。产品验证仍须来自目标运行时的实际结果。

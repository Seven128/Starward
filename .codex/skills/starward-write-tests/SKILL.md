# Starward 测试编写

仅处理用户明确授权的测试编写范围。[AGENTS.md](../../../AGENTS.md#development-execution) 持有授权、比例验证和停止条件；调用本技能不扩大功能、环境或发布权限。

从[当前范围](../../../project_context/global.md)、受影响的产品/实现 owner 和[验证入口](../../../project_context/areas/main/verification.md)确认预期行为、现有测试命令及目标运行时。复用已有框架、夹具和生产适配边界；少量用例不另建测试框架、总入口或报告系统。

## 选择范围与方法

- 先确定要证明的用户结果、关键失败机制和可观察结果，再编写测试。预期来自需求、公开契约或独立可信参考，不复制实现算法自证；不穷尽所有可能失败，也不为常量子串、函数名或源码结构堆测试来代替行为验证。
- 选择能观察目标不变量的最小测试层级。复杂功能和跨组件用户旅程优先用 E2E；纯计算、状态规则或接口合同可用单元/集成测试，不把 E2E 设为唯一机制。已有证据充分时不补重复用例。
- 按不同失败机制选代表场景，使用合理的数据规模和真实状态转换；不机械遍历所有输入、主题、设备与时序组合，也不为满足“中高难度”刻意复杂化场景。
- 使用稳定的行为接口和共享、参数化夹具，执行生产实现。不可控依赖沿既有生产适配边界隔离，说明替代范围；需要证明生产接入时，补实际路径证据，不能用模拟结果冒充。
- 明确的回归用例优先在修复前失败、修复后通过；仅在识别该回归确有必要时使用反证、变异或故障注入。代码已经写好不妨碍补有独立预期的有效回归测试。
- 夹具反复随内部重构破坏时，改进测试边界或共享适配，不恢复过时的生产结构，也不削弱行为断言。超出本次授权的覆盖或基础设施扩展不顺带实施。

## E2E 与结果证据

- 从实际产品入口执行关键用户流程，使用代表性非空数据、关键状态转换和最终结果断言。仅页面能打开、按钮可点、接口返回成功或安全空态通过，不证明复杂功能完成。
- 断言应能识别缺失效果、错误身份、旧结果和相关失败状态；涉及持久化的声明读回实际写入，涉及画面或交互的声明查看目标运行时结果。合理空态可独立验证，但不能替代承诺的有效数据路径。
- 小程序沿[开发技能](../starward-miniapp-development/SKILL.md)和验证 owner 使用 WEAPP/DevTools；仅在设备拥有该行为或验收明确要求时进入真机流程。浏览器仿制页面不能替代小程序结果，既定真机验收也不能被模拟器通过豁免。
- 保存足以复核结果并按相同条件重跑的必要信息：执行入口/命令、关键输入与环境、实际结果和相关证据位置。复用现有报告、读回、截图或 trace；仅为具体证据缺口补材料，不默认全程录像、逐帧截图或生成独立长报告。证据留现有任务/产物 owner，排除凭据和无关私人数据。
- 批量修复后运行受影响检查；相关要求得到证实即停止。缺环境、未执行或失败的部分按实际状态报告，不以绿色数量或降级成功替代完成。

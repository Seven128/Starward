# Interface wording and information hierarchy

Use this for Starward product menus, controls, guidance, states and dialogs. Read the affected Screen Contract and [product preferences](../../../../project_context/product-profile.md#interface-wording-and-information-hierarchy). It is a product-design capability; it does not authorize rewriting unrelated pages, scientific content or legal notices.

Start from the user's next decision: what they can see, what they can do and what will happen. Inventory the actual consumers by responsibility—navigation/actions, guidance, loading/failure/recovery, and facts/sources. Reuse one name for the same action across entry, dialog and return; distinguish actions with different outcomes. Inspect the data and command owners before changing words that imply availability, persistence, visibility, accuracy or permission.

Write the function name as the recognizable task or action, not the implementation. Use familiar verbs and nouns; remove internal terms such as context, publication, resource generation or validation from ordinary controls. Follow the owner's short-name and description limits. For Chinese functional copy, the current preferred shape is a 2–4-character name and a description no longer than 20 characters. Proper names, measured facts, necessary safety details, substantive articles and copyright text have their own content contracts; reorganize their disclosure rather than truncating meaning.

Keep state and recovery together. “加载失败” with “重试” describes a failed request; “尚无资料” describes a real absence; “部分资料未加载” preserves partial results; “更新失败，显示上次资料” preserves age. Do not merge these states into “暂无数据”, hide an unresolved error, or imply that a downloaded image is already visible. Place important limitations next to the fact or decision they qualify; move implementation detail and full attribution into the appropriate read-only explanation.

Design wording and composition together. Give a dialog a clear title, a compact overview, a primary action and quieter alternatives. Group related facts by proximity, align repeated roles, repeat the same visual treatment for the same action, and reserve contrast for priority. Keep close/return reachable while long content scrolls. Use a short disclosure row for sources or detail; the destination retains complete identity, version, attribution and recovery. Avoid turning every sentence into a badge, boxed card or button.

Review the actual rendered screen and a real action sequence. A first-time user should be able to identify the subject, choose the next action and predict its result without reading a paragraph. Check functional-name/description lengths as a writing aid, then read their meaning in context; character counts do not prove clarity. Update affected behavior checks only when the command, state or navigation changes. Keep current page wording in production code and enduring rules in the existing owners; do not create a second text registry or repetitive per-object copy workflow.

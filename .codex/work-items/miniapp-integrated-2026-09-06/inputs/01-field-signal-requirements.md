# 微信小程序 Field Signal I21：当前需求与开发进度完整说明

更新日期：2026-09-06。范围：Starward 仓库中的《今晚去观星》微信小程序。

本说明根据原始未完成工作交接、当前代码、开发记录、测试日志，以及本次重新读取的开发数据库和服务能力整理。它描述产品需求和开发现状，不引入额外工作流或验收文件。开发已在用户要求总结时停止继续操作，本次只核对并编写说明。

## 1. 整体要做成什么

目标是把现有微信小程序继续做成完整、可用、视觉一致的观星出行产品：用户能够在地图发现观星地点，查看客观条件与路线设施，选择时间，进入与地点和时间一致的星图，管理自己的计划、偏好、链接与内容，并提交现场反馈或地点提议。

不是只开发星图，也不是只把十篇文章导入数据库。整个需求覆盖 **5 个功能区域、9 条主要页面路由、62 类控件与交互**，并包括这些页面之间的状态衔接、失败恢复、数据持久化、无障碍和真机行为。

当前属于“已经有相当多代码与局部修复，但完整产品尚未完成”的状态。不能简单归为“没开始”，也不能因为页面能打开或单元测试通过，就称为“开发完成”。目前没有逐控件、逐条件确认全部完成的依据，因此不提供容易误导的整体完成百分比。

## 2. 所有页面共同的要求

### 外观与信息呈现

- 整体小巧、精致、信息密度高，但不能挤压文字和操作空间。
- 日间使用当前选定的纯白体系；夜间有独立暗色体系；观测红光使用黑色与暖红色体系。
- 不回到黄色页面底色、大块深蓝、过大字号、粗边框、卡片堆叠和无意义留白。
- 字号、间距、颜色、圆角、边框和图标以当前项目设计文件为准，不能靠看截图随意猜值。
- 没有合法有效图片时不渲染图片节点，不保留空图片位或假图片占位。
- 普通缺失值显示“暂无数据”；加载中、空结果、过期、部分可用、权限拒绝、错误、不适用和安全提示仍要明确区分。
- 清理对用户没有帮助的实现说明、内部编号、版本说明和重复教学文案；保留真正影响判断与恢复的信息。
- 数据来源、新鲜度和证据能从合适入口查看，不能丢失追溯。

### 适配与操作

- 覆盖 320、375、390、430 CSS 像素等效宽度，以及正常和 200% 文字大小。
- 适配刘海、底部安全区、微信菜单胶囊、软键盘；不横向溢出，不遮住提交和返回操作。
- 操作区域至少达到 88rpx；可见外观可以更小，但邻近点击区域不能互相重叠。
- 支持读屏名称、当前状态、焦点顺序及必要的键盘等价操作。
- 降低动态效果、降低透明度时仍可用。
- 滚动条视觉隐藏，但实际滚动、焦点和辅助操作保留。
- 展开、关闭、返回和拖动连续，可取消、反向和打断；不能靠延时串联造成闪跳或状态丢失。
- 地点、时间、偏好、表单和通知各自只有一套实际状态来源，页面切换不能出现两份不一致的数据。

**当前状态：**已有设计基础和代码投射，不能称为所有页面都满足。用户此前指出的全页面 UI 问题仍需逐页复核；近期实测主要覆盖日间的地图—我的—设置—导入链路，以及部分夜间和红光返回路径。

## 3. 地图、搜索、地点面板和时间

### 3.1 地图与搜索

需要完成：

1. 地图搜索入口进入搜索页后，输入字段的位置、尺寸、颜色和文字起点稳定；前导图标变为返回，不额外添加末尾清除按钮。
2. 自动聚焦、键盘收起、点外部失焦、再次聚焦都正确；收键盘不等于退出搜索。
3. 建议列表紧凑；筛选项即时多选、换行安全，没有重复标题、说明、应用按钮或多余层级。
4. “想去”和“其他观星点”分区展开后保持原位置、焦点和条目身份，不闪动。
5. 有图结果保持可读文字区域；整张卡片是唯一选点动作；无图结果没有空图位。
6. 选择结果回到原地图实例，更新同一个选中地点，并打开该地点的中档面板。
7. 页面返回、系统返回、边缘返回行为一致；拒绝定位仍可浏览，不伪造 GPS。

已有和已做：地图、搜索及面板代码已经存在；Map → My → Import 已多次实际运行。修复过地图通用模板注入空点集造成的原生地图错误，修复后的 Map → My → Map 往返未再观察到该错误。

未完成：搜索键盘与筛选完整路径、全部返回方式、真实正式点选择和完整状态衔接尚无全面验证；普通地点搜索服务当前未启用。

### 3.2 地点信息面板

需要完成：

- 小、中、大三档裁剪同一份、同顺序、同身份的地点内容；显示与档位分别管理，只有大档启用唯一的纵向滚动。
- 首次选点打开中档；点击空地图从当前状态平滑退出；大档不覆盖底部 Map/My 导航。
- 仅 104×40rpx 的把手区域启动面板拖动；轻点、未越过阈值不变档，正文、图片和顶部边缘不能抢拖动。
- 没图时保留紧凑 40rpx 把手带；有合法图片时把手叠在媒体上，从中档到大档先连续展开媒体，再淡出地图工具，反向也一致。
- “概览/天文”切换条固定在可见面板中部，不占正文宽度；点击放大并对齐相应章节，滚动反向更新当前章节。
- “想去/分享/云观星”紧凑等宽；路线、设施、来源、攻略、反馈入口组织清楚。
- 分享、收藏与恢复、外部导航、媒体查看、天文列表、云观星、返回和带地点反馈均走真实行为。

当前状态：实现已经存在，但缺少可用正式点的完整真实旅程，不能说这些动作全部通过。组件与隔离数据测试只能证明部分逻辑。

### 3.3 图层与时间尺

需要完成：

- 底部只能显示地点面板或图层面板之一；图层打开时选择新地点，直接进入新地点中档，不闪回旧地点。
- 图层只呈现受支持的光污染、总云量、观测机会三项，按真实能力显示可用或不可用。
- 图层面板固定高度，不增加多余把手、关闭按钮或重复的观测条件卡。
- 地图、地点内容和全屏星图中的三处曲线时间尺使用一致的拖动方式与时间上下文。
- 横向拖动可预览，释放后吸附并提交，取消后回滚；跨午夜、快速变化和旧请求迟到不会错用时间。
- 时间尺横拖、面板纵拖与地图平移缩放按方向阈值确定归属，不在途中换控制方。

当前状态：有现有时间与状态实现及部分测试；完整三处联动、交叉手势、取消和迟到请求的真实页面验证仍未完成。

## 4. 星图需求与现状

### 已经存在的实质实现

- 使用带版本和校验信息的 **Gaia DR3 离线星表，2048 颗星**，不是随机星点或静态夜空图。
- 天文计算集中在共享天文代码与后端服务，前端负责把天文方向变成画布位置。
- 使用三维透视视窗，当前垂直视场角为 **45°**，按实际画布宽高比投影。
- 视锥外和设备背后的天体被剔除，不把它们硬挤在画面边缘。
- 时间与位置来自选定地点的观测上下文，已有历元、地平坐标、跨日和时间场景方面的测试。
- 已有画布全宽全高修复、同一罗盘方向在失效后重新收到数据时恢复的修复。
- 星表坐标有效、唯一且广泛分布的局部审计已经做过；不能把旧截图的聚集感直接归因于星表全部集中在某一块。

这些主要是在本次续接前已有或已做过局部检查的成果。本次续接没有重新完成一整套真机星图验证。

### 尚未完成或不能声称完成

1. 从真实可用的正式地点面板进入“云观星”，完整验证当前构建，而不是单独打开测试路径。
2. 真正测量画布尺寸、DPR、测量时机、清屏重绘、标签遮挡和全屏安全区，确认没有 CSS 压缩或尺寸尚未就绪的问题。
3. 真机四方位、俯仰、滚转、地平线、天顶、北向与手机背面指向的对应关系。
4. Android/iPhone 传感器轴、正负号、精度、校准、过期数据和恢复差异。
5. 时间预览、提交、取消、快速变化、跨日、背景星与当前目标同一时刻，以及返回地图后地点时间一致。
6. 拒绝权限、校准不足、数据失效时不假装姿态有效；后台、隐藏、返回、卸载后停止监听，恢复前台正确重新订阅。
7. 读屏对象列表、恢复提示与降低动态/透明度条件的真实可用性。
8. 明确可接受的指向误差与实际观测依据；目前没有足够证据声称手机画面与肉眼天空“1:1”。

星表的准确限制：虽然采集条件有 G≤5.5，实际包只取了 2048 条，最暗约 **G=5.007534**，不能称为完整的 5.5 等星表。是否扩展要依据科学与实际显示需要、来源和包体性能，不能为“更密更好看”加入假星。

## 7. 现场反馈与纠错

需求是同一套表单支持两种入口：从正式地点面板进入时继承该地点；从“我的”进入时选择正式地点或新地点。

表单需要依次处理反馈类型、地点上下文、受影响主题、观察时间、叙述、条件性位置、有限数量媒体与权利说明，以及唯一提交入口。

当前已有：页面、服务、媒体/持久化相关实现及部分基础设施测试。

未完成的真实验证包括：

- 两种入口是否确实共用同一表单和草稿，地点继承/切换是否正确。
- 已有地点不请求当前定位；新地点才按许可请求定位，拒绝、撤销和重试不泄露精确位置。
- 图片类型、大小、数量上限、EXIF/位置元数据清理、上传进度、失败重试、移除、取消和切后台处理。
- 达到上限后移除“添加”入口，已成功媒体与草稿身份保留。
- 首个错误能聚焦并滚入视图；软键盘不挡字段和提交；小屏与大字体正确堆叠。
- 防重复提交，同一次重试复用幂等标识；真实写入、回读和重启后待处理记录存在。
- 只显示当前身份的数据，正确区分待处理、通过、拒绝、合并和公开影响。

因此不能把“反馈表单存在”表述为“现场反馈功能完整完成”。

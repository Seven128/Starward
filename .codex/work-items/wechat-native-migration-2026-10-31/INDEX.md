## 先确定迁移量，再安排最小运行验证

迁移方案须先交付一张按**公共责任/不同机制**组织的影响表：当前owner及真实消费者、框架耦合点、可复用/需适配/需改写、既有优化与特例、历史证据、仍适用范围与原因、最小真实运行观察及静态检查。工作量按这些改动估算，不按历史场景数或外部固定维护百分比估算。

| 类别 | 迁移与验证规则 |
| --- | --- |
| 未改动的纯业务/算法/数据责任 | 复用代码及仍适用的科学、数据和行为证据；使用现有静态工具，不恢复已退役测试，不重新验证所有地点、时刻和对象。 |
| 框架绑定、状态投影与生命周期适配 | 在公共owner修订订阅、清理、取消、迟到结果与同步，核类型/编译及受影响的真实路径；不重建Hooks、渲染器或编译输出的自动化测试。 |
| 微信运行时、Map/Canvas/native资源 | 只对变化的运行时边界保必要目标验证。候选可按Map安装/替换/返回、Sky输入到accepted帧及Play→Pause、Sources暂存与普通退出等不同机制分组；最终清单由实际改动决定，不要求历史场景逐个重跑。 |
| 历史特例与平台workaround | 追溯针对的机制：仍成立则保留；仅因Taro/编译器产生的特例先核原生条件。合并或退休须有该机制的直接证据，不按名字、代码量或“现在是原生”批量删除。 |

- **同机制代表覆盖**：相同owner、状态转换、资源接口和输入合同下，一个有判别力的路径可以覆盖普通变体。不同地点、字段、时长、星数、视野和操作排列不自动增加用例；单独保留须说明未覆盖机制、新失败或会改变交付判断的风险。
- **证据范围不外推**：旧Taro目标结果是基线，不能直接给变更后的原生UI/生命周期/资源释放盖章。纯逻辑证据与目标证据分开；未运行变体记机制覆盖，不记实测通过，Android不冒iOS。
- **复用性能成果**：先用已有有效基线、历史回归记录、Profiler/Heap与操作记录；不重建冻结候选、不重录已收资料，不要求重新复现已收口的OOM/F04。迁移造成的真实回归需修复；历史未归因与物理字节未知不自动生成采集任务。
- **不重做选型比较**：不要求同时维护Taro优化版、混合版、全原生版三套完整实现。仅为能改变迁移或验收决定的具体缺口增加对照，足够即停止。
- **页面核查与性能实验分开**：所有受影响页面的基本可用及采用设计一致性需覆盖；昂贵真机/性能采集按机制合并，不由页面数膨胀成全组合矩阵。保持同功能/同质量，不靠降采样、删内容或任意节流制造收益。

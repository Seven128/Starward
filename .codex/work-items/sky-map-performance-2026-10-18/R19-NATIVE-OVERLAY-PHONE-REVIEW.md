## 实际看见什么

拖动中，旧覆盖范围的山脊/阴影与底图一起移动，底图文字、道路仍可辨认；没有观察到整屏地形突然消失、整片黑白闪屏或严重地理错位。换图前后，同一已覆盖地理位置没有明显双倍压暗或突然加深。不过只有这一个短片、有限取样；没有同地理像素的严格 alpha 对照，不能据此证明只有一个原生 ID、逐像素混合正确或原子换图。

新露出的右侧有清晰竖直界线，约占视宽五分之一：底图仍在，地形阴影缺失。该条带在至少媒体 **3.289778–4.144100 秒**的取样中仍可见；到 **4.193833 秒**的取样已填回。原始拖动结束后的相机已停止，而缺口暂时仍在。这个结果与保留旧细图、等待新细图相符，不能写成“平移始终全覆盖”。缺口是已知未解决机制的再现，本次没有证据把它定为新引入的退化。

片段的底部地点面板在末段收起，扩大了地图可见区域；这会改变整屏画面，不能把整屏差分全归为叠层更新。独立后图仍显示已补齐的地图且道路/地形大体一致，但无独立时间关联，不将其当成长时间稳定性证明。

API 的正在追加日志只读了一次，并保存有关资产的有限摘录及当时源文件哈希，没有将整份日志冻结或改写。由于未取得 opaque A5 对应的完整文件哈希/共同钟关联，摘录只作背景，不用于本次端到端耗时归因。

## 方法确认与下一步边界

当前源码在已确认 slot 且 update 方法存在时走同 ID `updateGroundOverlay`，方法缺席才回退双 slot；`pending` 仅在这个同 ID 分支、实际 nativeCommand 调用前发出。API 存在、最终像素及 `native_ack` 本身不足以证明 update。因此追加了对**同一原录像** 3.7–4.25 秒的 34 个密集解码取样，没有新增手机操作：媒体 **4.210700 秒确实显示 `TW 7 native_pending A5 1849ms`**，随后 **4.227256 秒显示 `TW 8 native_ack A5 1883ms`**。注入点只在 `input.label === "地形"` 时发出 TerrainWait。这把本轮地形同 ID update 分支与成功回执落实到实际目标，足以结束方法是否走到的疑问。未导出的数值 ID、光害分支和完整 TerrainWait 行仍保持未知。

不需为方法再采集一遍、另开真机调试或新增诊断系统。密集 marker 接触表和对应媒体时间保存在私有 `dense-marker-sheet.jpg` / `dense-marker-samples.json`。双层 initial-only 父图保护在本包仍保留，因此本片段没有验证旧细图 A → 覆盖新范围的父图 B → 细图 B。

方法确认后，真正待决的最小能力验证仍是既有 PLAN 的这一段有界 A→parent B→fine B 路径：使用已准入图、同时保留地形＋光害、显式观察新露出范围和透明区域。不能仅删除 `initialOnly`，也不能用更长防抖掩盖缺口。持续快速移动/缩小、云层、失败清理、退出后资源退休、GPU/堆保留与无泄漏都不在这段录像的通过范围内。

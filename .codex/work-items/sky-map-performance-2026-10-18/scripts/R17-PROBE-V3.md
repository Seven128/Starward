## Clock and interval contract

`r17-phone-probe-v3-runtime.ts` uses one fixed `Date.now` source for recorder intervals. `clock` exports source, `ms` unit, `wall-elapsed` kind, `monotonic:false`, read availability, nominal 1 ms timestamp granularity, `effectiveResolutionMs:null`, and bounded invalid/backward-read counts. No absolute timestamp or device/account data is exported. A callable global or `wx.getPerformance().now` is not adopted as calibrated or monotonic.

An internal stamp contains only the reading, clock epoch and run number. A failed/nonfinite/noninteger reading or an observed backward read changes the epoch. An interval crossing epochs or runs is unknown; a missing clock endpoint is unknown; a difference above the existing 60-second observation bound is unknown. A difference below 1 ms is `belowResolution`, with `elapsedMs:null`, not zero-cost work. Other valid differences are approximate wall elapsed milliseconds, including scheduling/preemption and observer overhead; they are **not thread CPU consumption**. Forward wall-clock corrections within 60 seconds, and corrections hidden between reads, cannot always be detected. Neither `availability:available` nor `backwardReads:0` certifies a monotonic clock. Source-clock qualification or a target profiler is still needed for finer timing.

Relative event timestamps are relative to the run's initial reading and are present only while that epoch remains comparable. After a discontinuity, subsequent relative timestamps remain null. Later wholly local intervals can become valid again, but a run with an unknown whole window must not be used for aligned rate/delta claims. Zero relative timestamps are legitimate positions at the origin; zero *durations* are unresolved. The actual first-acceptance and consumption booleans remain independent of timing availability.

`now()` now returns an opaque stamp; the legacy hook name `cpuSince(stage, stamp)` accepts only a stamp from this runtime. Existing instrumented sources currently use `measure(stage, work)` rather than direct numeric subtraction. Future instrumentation must not mix this stamp with global/wx clocks or subtract it as a number. Intent and preparation identifiers do not restart at 1 when the recorder restarts: they remain unique for the runtime lifetime, while per-run rings and statistics reset. This prevents a memo envelope retained from an earlier run from falsely accepting or consuming a new run's same-numbered work. At the existing identity limit, allocation fails closed instead of reusing identifiers. Historical v2 identity behavior is preserved, not retrospectively certified.

## v3 output

Schema names are `starward-r17-phone-probe-v3` and `starward-r17-phone-probe-v3-terminal`. They are not shape-compatible relabelings of v2.

- `stageElapsed` replaces the misleading top-level `cpu` name. Each stage and timing distribution has `observedCalls`, `validCalls`, `unknownCalls`, per-reason unknown counts, `knownSubtotalMs`, and statistics over valid samples only. With no valid samples, min/max/percentiles are null. `overflow` and the 2,048-sample limit retain their former meaning for valid samples.
- `linkage.costs.consumed`, `.unconsumed` and `.expiredUnconsumed` each carry `knownSubtotalMs`, `validCalls`, `unknownCalls` and unknown reasons. An all-unknown group can therefore have a zero **known subtotal**, without claiming that total work cost zero. Counts cover every preparation in that group, including unfinished work. A finished-but-failed preparation still has a measured interval if its clock is valid.
- Exported preparation links use `elapsedMs` and `elapsedStatus`; unfinished work is `notObserved`. Expired unconsumed work remains unresolved after eviction and is never promoted into proven avoidable work.
- `window.elapsedMs` may be null and has `elapsedStatus`. Controls no longer require `monotonicClock:true` to retain valid wall-clock-relative event positions. The top-level clock describes the measurement source. Callback timestamps, render/driver/native completion and physical presentation remain different boundaries.
- First accepted identity, supersession, clone inheritance, synthetic-versus-real accepted counts, 15-second metrics/20-second guarded Pause ownership and fixed terminal receipts retain the existing contracts. Timer firings are not reconstructed from export arrival time. The runtime still only measures; the existing controls/product owner performs Pause.

Scalar observations supplied by other owners (`page.latencyTotalMs`, for example) retain **their own producer's semantics and clock**. The v3 clock does not certify or recalibrate those fields. The Page observer must be assessed separately before using its latency as calibrated data; request/completion/pending counts remain useful under their existing scope.

## Collector and compatibility

The existing `r17-phone-probe-collector.mjs` now imports the version-dispatching `r17-phone-probe-v3-protocol.mjs`. No route, file naming or storage semantics changed. The v3 module exports `validateR17PhoneProbeMetrics`, `validateR17PhoneProbeTerminal` and `matchR17PhoneProbeTerminal`, dispatching v1/v2 to their unchanged validators, plus dedicated v3 metrics/terminal validators. It reexports the original route and 32,768-byte limit.

V3 terminal admission requires the already stored matching v3 metrics file: missing metrics is 424; a conflicting receipt is 409; an identical serialized body is an idempotent 200. V2 and v3 terminal schemas cannot be matched across versions. Both receipts consume the existing shared 32-file capacity. Strict allowlists run before path construction; no arbitrary metadata or source payloads are accepted. The collector remains serialized and writes a new file exclusively. Existing stored receipt bytes are never migrated or rewritten.

The v3 validator delegates only unchanged counts/Scene/time/viewport field checks to the original v1 validator, using local empty duration placeholders. These placeholders are not exported and do not convert new observations to legacy receipts. New clock, interval, coverage and terminal semantics have independent strict checks.

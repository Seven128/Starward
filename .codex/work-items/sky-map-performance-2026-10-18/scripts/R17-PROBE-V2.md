## Minimal integration contract

Copy `r17-phone-probe-v2-runtime.ts` into the isolated candidate as `r17-phone-probe-runtime.ts`, replacing `__VARIANT__` with the existing variant. The exported `r17Probe` preserves the v1 `start/stop/status/measure/cpuSince/count/intent/prepared/paintStarted/callback/tiles/sceneFinished/accepted/snapshot` entrypoints and original CPU/time/Scene field meanings. New fields version the metrics schema to `starward-r17-phone-probe-v2`.

1. Before the run, call `configureBinding({mode, buildGeneration, buildSourceSha256})`. Modes are finite: `unknown`, `normal`, `cpu-page-only`, `cpu-text-metrics`, `accepted-action-direct`, `accepted-action-closure`. The SHA is the builder's precomputed parent/source/template binding hash, **not** a self-referential final bundle hash. The actual complete bundle identity remains in the build evidence. `start(caseKey)` captures these scalars and a numeric `windowId`; a later configure cannot rewrite them.
2. The existing `sky-observation-time.publish` instrumentation calls `intent(state)` for each actual new public state object. `intentSequence(state)` retrieves only that exact object's sequence; it never compares `at`. An unrelated object with the same timestamp returns null. A→B→A has three sequences. Publications outside the recording window and expired identities stay unbound.
3. Wrap the **existing** time-presentation memo callback with `prepareStarted(sequence, "presentation", resourceRevision)` and `prepareFinished(token, completed)`. Keep its original dependencies, calls, fallback and product values. Return a task-only envelope `{presentation, token, intentSequence}` from that same memo; expose its original `presentation` to existing consumers. Determine the sequence from the exact public `timeIntent` captured by that memo, its valid binding and an output whose `row.at === requestedAt`. A fallback to committed time gets null sequence. Do not read `observationTime.snapshot()` later in `draw` to guess the prepared input. If no real resource revision can be obtained, pass null. The token measures only that actual memo callback, including its existing fallback if executed; it does not claim catalog, supplement, constellation or total preparation cost. Set `completed=false` in a finally path when the original work throws, preserving the throw.
4. After constructing the same immutable frame and before the existing writer request, call `request(frame, token, sequence)`. Keep the existing `prepared(frame)` call: it is still a writer-request counter, **not** an expensive-prepare count. When `resolveFrame` really clones a frame for live HiPS, call `inheritFrame(clone, original)`. No clone needs to be introduced solely for this probe. Existing `paintStarted(frame)` marks first consumption; only the real successful display-copy/publication boundary calls `accepted(frame, snapshot)`. A token/sequence mismatch discards both associations and increments a mismatch counter. A frozen facade calls `syntheticAccepted(frame)` instead: it never increments actual copy or first-accepted latency counters.
5. Immediately after actual guarded product Play succeeds and the existing measurement starts, call `control("actualPlay", true)`. Capture `scalars("tm", r17CpuTextMetricsStats())`, `scalars("page", r17PageBridgeObservationStats())`, and `scalars("scene", r17CpuPageOnlyStats())` after their original observation resets, and again immediately before metrics seal. Inputs are reduced to exact named count/boolean fields; unknown or absent fields are null. Each owner keeps only first/last scalar captures plus capture count. `scene` here names the **frozen facade owner's lifetime scalars**, not the windowed CPU `sceneFinishes`. 6. Preserve the current 15-second export and 20-second guarded Pause. At 15 seconds, capture final scalars, `control("export")`, then `snapshot()`. First snapshot seals metrics; repeated snapshots are identical and return independent copies.
7. At the existing termination callback, call `control("pauseAttempt")` immediately before invoking the original guarded callback. It contains the same run/binding, fixed metrics-seal scalars and actual controls. It does not copy or revise the 15-second metrics. An absent callback or unobserved result is null, never success. Client retries must reuse the identical serialized body separately for each receipt.

These hooks observe existing scheduling and state. They add no React dependency, cadence, extra RAF or product publication policy. `scopeChanged()` is available for a later explicitly observed resource/Context-scope transition; the current fixed-scene run need not add such a hook or infer a private binding from text.

## Collector interface

`r17-phone-probe-v2-protocol.mjs` reexports the existing route and 32,768-byte limit. It exports:

- `validateR17PhoneProbeMetrics(value)`: strict v1, v2 metrics or v2 terminal shape; boolean, no I/O.
- `validateR17PhoneProbeV2Metrics(value)` and `validateR17PhoneProbeTerminal(value)`: the individual shapes.
- `matchR17PhoneProbeTerminal(storedMetrics, terminal)`: both strict schemas plus equal variant/runId/binding; exact metrics recording-start/seal/window; equal clock; controls may append observations without rewriting previously recorded events. False includes absent metrics. A previously unknown Pause callback result may resolve to boolean without adding an attempt.

Use the same bounded, serialized collector. The root owns the terminal sidecar admission: require the already stored matching v2 metrics receipt, preserve its bytes, and apply the existing exact-body retry/conflict rule independently to `-terminal.json`. A terminal shape validation alone does not prove the metrics arrived. The two files count under the existing total file limit. No new collector service or route is required.

## Semantics and limits

`linkage.latency.intentToFirstAcceptedMs` includes only the first actual accepted result for an explicit intent identity. Its superseded/unsuperseded subsets are separate. Repeated presents are counted separately. The old `timing.intentToAcceptedWallMs` remains the original latest-time-conditional sample and can still repeat; it must not be reported as the fixed metric. Sky-time deltas remain different from elapsed latency. The synchronous Scene callback remains a JS completion boundary rather than a native/GPU/scanout acknowledgement.

Intent/preparation rings hold at most 2,048 scalar records each; retained sample arrays/time sets also cap at 2,048, public identifier sets at eight. State/frame WeakMaps never exceed 256 inserted entries before replacement; they do not retain their keys. Only 32 preparation/intent links are exported (first/last 16 when truncated). No report, frame, public state object, caller closure, text, payload or reference string is retained in these new association structures. Aggregate counters saturate at 1e12. Probe overhead is present and must remain equal between comparison modes.

`unconsumedCpuMs` is known presentation-memo cost with no observed paint consumption **as of metrics seal**, not a proof it can all be avoided. `expiredUnconsumedCpuMs` is explicitly unresolved after ring eviction; it is not added to proven unconsumed cost. Unknown/expired association is counted rather than reconstructed from a timestamp. `resourceRevision=null` explicitly withholds a resource-revision claim. Missing monotonic clock makes new relative times/preparation costs/latency unknown, while independent accepted/consumed booleans still de-duplicate correctly. Old CPU fields retain their Date.now fallback. Terminal observations beyond the finite 60-second relative-clock range become unknown.

Synthetic publication can validly yield `acceptedCopies=0` and zero first-accepted samples. Such a receipt supports only its declared frozen-workload experiment; it cannot establish normal visible interaction latency, rendered correctness, selection or Sources acceptance.

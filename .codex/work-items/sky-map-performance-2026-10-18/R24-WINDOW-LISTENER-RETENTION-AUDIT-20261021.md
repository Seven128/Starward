# r24 WindowInfoChanged listener boundary audit

2026-10-21. Independent, bounded, offline review of the new ordinary-r23 Map warning. This record supplements `R22-SKY-RETENTION-OWNER-AUDIT-20261021.md`; it does not reopen that audit's stellar/Query/Canvas experiments or supersede PLAN/HANDOFF.

## Result and stopping decision

The inspected application and installed Taro resize owners show **no reproducible duplicate-registration or cleanup-identity defect**, and no subscription list that appends a new Sky frame/report callback on each render. No production repair is justified by this warning alone.

The exact emitter implementation behind `[Event] 21 listeners of event WindowInfoChanged have been added, possibly causing memory leak.` remains **unidentified at the platform boundary**. The current 21 members were not enumerated, so this review cannot establish that 21 is a normal bounded set of active consumers. It also cannot establish growth, an obsolete Sky retaining path, or a leak. In particular, counting Taro `useResize` sites as 21 native subscriptions would be incorrect.

The warning was reported by the parent from the ordinary-r23 phone's Map vConsole before entering this candidate's Sky. No before/after listener counts, event-emitter stack, retained graph or comparable post-unmount sample accompanied it. Concurrent BFF HTTP failures are a separate investigation owned by the parent. Stable r22 lost its true-debug connection after Sky entry before any Heap baseline; this audit does not turn that capture failure into a passed leak check.

Stop here under the agreed bound: no profile-directory scan, SDK/dependency patch, listener-limit change, new probe, throttle or feature reduction. Normal Play growth/exit and the full Goal remain unresolved. Reconsider this clue only if a useful current stack or actual listener/retaining evidence becomes available through the existing supported investigation; the warning alone does not require another capture attempt.

An initial wider dependency search was stopped without a hit; it is not a completed inventory of every npm file. The narrower Taro owner searches and source reads above were completed.

This does not establish what the phone's base library or separately cached SDK contains. Neither user profiles nor private protocol/configuration stores were scanned.
- The application inventory contains two direct `onWindowResize` call sites and their matching `offWindowResize` sites. The other reviewed callbacks use page/component lifecycle ownership. Neither this inventory nor the archive search supplies the phone emitter's 21-member roster or the warning threshold's implementation.
- Existing focused card/viewer tests already contain resize listener sets and stale/unmount handling checks. They were inspected as supporting test-owner context, **not rerun or promoted into current native-leak evidence**. No new tests were needed because this review proposes no code change and a local mock cannot resolve the unidentified platform membership.

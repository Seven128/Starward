# 微信小程序唯一实施计划：剩余工作

2026-10-25用户最终范围：当前及未来一段时间只开发微信小程序。已有App实现、未提交成果和中断增量原样保留；App及其专属API不再继续开发或验收。本文件只保留未完成工作，不重复列出已做实现；完成记录与全仓审查映射见[审查实施核对](REVIEW-IMPLEMENTATION-AUDIT-20261025.md)。当前状态、候选和唯一下一步归[HANDOFF](HANDOFF.md)，完整目标见[Goal正文](GOAL-OBJECTIVE.md)。

## 范围、约束与顺序

- 产品入口是 `apps/wechat-miniapp`；其BFF、管理后台及必要共享依赖按真实小程序消费者维护。`apps/mobile`、App专属 `apps/api`、Expo/Android/iOS App工具链和独立App业务均不属于当前任务。微信原生Map、系统选点器和手机真机不等于独立App。
- 只实现已采用设计的局部变动，未涉及的内容、配色、图标、材质、布局和交互保持。实际采用入口和完整依赖由[小程序Screen Contract](../../../project_context/areas/main/screen-contracts/wechat-miniapp.md)及[本轮设计交接](../map-ui-design-2026-10-22/HANDOFF.md)持有；不得借审计重画整套UI或把App界面移入小程序。
- 执行顺序：先使小程序普通运行入口与真实必要数据可核验，收口采用UI和功能正确性，再完成小程序后台/交付的剩余责任。具体阻塞时做独立的小程序事项；不转做App。
- **地形/云量/光害叠层性能、云观星播放/调时性能及相关内存/OOM继续后置。** 它们保留为未完成结果，不以恢复Profiler/LAN/UAC作为当前所有工作的门槛。逻辑正确性、权限、取消/应用和资源安全仍需保持。
- 本机在main开发；保全部dirty成果、私有原件、N05草稿、Harness、r6及冻结代。不得reset/clean/force/stash或另建worktree，不动另一电脑分支，不重复发送已送达R6提醒，不改VPN/TUN。原件上传、采购、部署和公开发布仍遵守各自已明确授权。

2. 正常按钮、公共按压、搜索、来源真实跳转/阅读、紧凑叠层与天文天气，按实际内容与权限状态核对。来源返回保原时间、选择和阅读位置，必要署名/限制/缺失含义不消失。
3. 正常账户/My、真实微信系统选点器的成功确认、取消返回、真实定位允许/拒绝/恢复及精度语义，保当前账号和草稿；不得以App的权限或SQLite结果代替微信结果。

完成证据：实际小程序画面与当前采用资源在可比条件下对照；正常操作有真实数据/状态效果，必要恢复有效。源码标记、静态截图、构建成功及App截图都不能代替此结果。

## P2 地图、图层与返回正确性

责任：现有Map实例/故障session、相机与面板、栅格请求/下载/安装、独立地理云量和原Context事务。复用当前实现，发现实际差异才在其owner修复。

- 选点后打开中档面板，点居于剩余可见地图中央；粗视野按较长可见地面维度约4km校准，已有更细视角保留。用户手势后不反复抢中心，快速改选/布局变化/迟到响应不移动旧目标。
- 核地形/夜光/云量真实位置、所选UTC时刻、版本、来源、质量和覆盖。真实零、缺测、未发布、过期及加载失败分别呈现；不涂满未查询云格，不用地点天气替代地图地理云量，不抹掉独立有效的月相/天气。保既有同id单coverage替换与透明合成约束，不用父/细图重叠造成重复染色。
- 连续拖缩、新手势接管加载、图层切换及My隐藏/Sky退出返回时，当前相机保持可操作，有效旧覆盖只在原有效范围保留，迟到结果不能覆盖新范围或更细成品。显示正确性与性能耗时分别判定。
- F04仍需目标微信Map的故障→实例替换→真实恢复和平台资源退休证据。原生操作永不回调时，恢复不能等待同一失败对象；旧实例/文件/回调不污染后继。timeout、JS卸载、一次remount或callback成功都不能冒物理释放，未知资源保持明确且有界。
- 真实H4供给、供应资格和所选小时完整链路仍须建立；只修本次真实输入/目标差异，不重新开发F10接口、已有缓存或已完成的frame/资源接线。

完成证据：选点范围/居中、实际图层配准与时间含义、正常返回及相关故障恢复均从真实目标效果确认；资源未知与仍欠平台能力明确保留。

## P3 云观星正确性与完整交互

责任：现有观测时刻、几何窗口、浏览相机/地景、唯一renderer/writer、accepted帧与名称/拾取/来源消费者。剩余为目标运行结果，不重新做已有职责重构。

- 核地景/夜景间拖动与地平线、背面切换的连续性，淡灰方向提示实际可见；保原构图、真实地景、手动/跟随、捏合、反向与取消。该提示是图示，不冒真实逐树逐楼遮挡测量。
- 六字段、时间尺和播放共用同一精确时间意图。范围内立即预览，跨供给范围走现有受权限/来源校验的几何请求；被替换/取消的预览、旧run/Context/generation或错供给结果不能恢复当前状态。**正常Play可显示同一run、Context和generation内稍早但真实完成的accepted帧，并显示该帧实际时刻；不能要求它等于采样瞬间最新tick而拒绝全部帧。** 停留后的最终预览/目标内容仍对应最新有效停留时刻，UI请求数字不能冒已经绘制的时刻。
- 取消、关闭、hide、账号/Context变化及失败保持已提交状态；仅明确应用更新公共Context。原日期可选域、精确插值、旧客户端默认供给及完整正常Play语义保留，不因局部窗口制造两小时停止或伪造天气内容。保Sky不得晚于现实当前时刻的既有上限；未来规划Context仍归Map，不能为取得样本解除上限。
- 保完整BSC和实际加载SAO、原运动/角度/亮度/星位精度、过渡、地景、名称、拾取与来源身份；来源往返和最终停留时刻的目标内容必须正确。已绘帧、过渡、拾取和来源读者不得被后续工作缓冲覆写。
- 目标核对覆盖非空最大/全天区负载及实际窄视野SAO消费者，按机制选必要动作；响应速度与持续播放内存另归后置D2。

完成证据：真实画面/操作与时刻、对象、取消/应用和来源一致；原有效数值及源码证据复用，不以结构整理关闭性能或OOM。

## P4 小程序后台、管理和恢复的剩余闭环

责任：`workers/miniapp-api`、`apps/admin-web`及现有HTTP/PG/Redis/对象存储/管理客户端。本节仅处理当前协议在实际环境中的剩余闭环，已有实现与历史验证按证据owner复用。

1. **补全审查R6中的管理输入契约判别。** 现有controller有字段检查，但尚缺完整对象形状准入的明确证据。用已有授权/HTTP隔离入口判别null或非对象body是否返回结构化INVALID_INPUT/4xx且零业务写，而非通用500/可重试供应商失败。先核现有完整schema/共享校验；真实缺口成立才沿原owner补窄DTO/schema与受影响HTTP/CLI消费，不另建验证平台，不把静态线索写成已证漏洞。
2. 现用/拟部署环境的管理credential/principal/operation、API与客户端配对、旧无key接口和未知提交恢复仍需实证。旧响应或403不能抹掉此前已知提交/缓存失败；新请求头不能授予身份。只处理实际版本/配置差异。
3. 媒体迁移023–026、真实对象存储、长期worker/Redis故障恢复和账户删除/审核等相应环境的剩余结果，沿原迁移/备份/回滚/队列owner完成。已提交或结果未知的新对象不能盲删，查询失败不是确认不存在，提醒UNKNOWN和既有授权消耗不改变。
4. 真实小程序后台供给、账号、地点/来源及访问资格不足时，明确缺哪一层，不用App专属API或LOCAL_TEST身份替代正式资格。外部账号/权益/采购/发布条件后置准备，已有授权内可恢复依赖先自行处理。

完成证据：真实HTTP/持久读回/队列与对象效果，必要迁移和当前版本消费相符；隔离通过不冒已部署，旧协议未覆盖保持未验。

## P6 小程序交付与环境收尾

## D 后置性能与条件性改造

### D1 地形、云量、光害叠层

恢复此项时，复用已有效的固定窗口、成品、共享读取/取消和安装证据。选一个真实代表动作，将需求、供给/文件就绪与首次有效可见覆盖关联，先区分供应商等待、本方准备和响应后安装成本；缺时间戳仍unknown，嵌套阶段不相加冒总耗时。

保长拖动途中可用覆盖、短手势最终视野、加载中再次拖缩、My隐藏与Sky卸载返回这些不同机制；手势不锁、旧有效覆盖不随意清、最终必要细节必须到位。只按实测瓶颈决定窗口读取、缓存、有限预取、固定云采样锚、分块或worker。分块须保持同内容/总像素的可比试验、配准/接缝/透明度/图层次序、native对象及资源代价；不能把其他地图SDK的API直接当微信支持。

### D2 云观星响应、播放与内存/OOM

输入到首个正确accepted/可见响应，与完整正常播放的内存增长/暂停排空/退出分别验收。复用正常CPU/分配/Heap和完整BSC/SAO负载，区分JS强保留、分配churn、有限工作集与native/GPU资源。修复后回到完整正常路径及原故障时间窗，不把一次快照、PSS下降、局部CPU变快或未闪退当完成。

原生buffer handle已复用；typed buffer/bufferSubData、提前保守剔除、延后拾取、GPU变换、共享准备或调度调整，仅在实际关联成本与所有读者寿命支持时采用。保精确时间、完整星数、incoming星体、过渡/名称/拾取/来源；无历史帧无限缓存、任意FPS上限或近似时间。来源缓存/Query收敛同样先证明实际缺口，不能把传输取消器当重复结果缓存或用内存LRU冒进程死亡恢复。

### 共用停止与选型边界

- 主用真机调试开发者工具，普通预览/Android系统观测仅作实际失败、覆盖缺口或普通运行对照；这指微信小程序。相关环境恢复跟随待决问题，当前不先做Profiler功能矩阵或UAC/重启。
- gen34禁止prepare/build/refresh；gen24 scene-memo暂停，R27同问题停止。无新决定性条件不重做已失败的大Heap、手势时长或相邻disable试验。OOM仍未解决。
- Taroify、Stellarium Web Engine/WASM/GPU、COG/windowed IO等均按实际未满足能力、目标平台、等价结果、包体/维护/许可与成本作窄比较；保当前已选技术栈。包名、必带图标依赖或外部固定数字都不能单独决定采用/否定。没有新换库/换引擎/采购任务；不强行合并App与小程序状态机，不把App专属contracts存储迁移纳入本Goal。
- 每次新增观察必须能改变下一决策；有效证据足够即推进。外部报告的次数、时长、容量和百分比不是新门槛。无法取得必要证据时记录首个失败边界和恢复条件，保结果缺口并继续独立小程序工作。

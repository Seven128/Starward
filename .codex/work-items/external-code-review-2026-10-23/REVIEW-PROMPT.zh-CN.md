1. **架构与模块边界。** 职责是否清楚、依赖方向是否合理，是否存在循环依赖、跨层访问、隐式耦合、职责过多的页面/控制器/服务、名义分层却仍由上层包揽业务的情况。区分真正的边界问题与单纯文件较长；拆分应围绕职责、状态和生命周期，而不是机械按行数切文件。
2. **重复实现与抽象质量。** 是否把应共同演进的业务规则、状态转换、错误/重试/恢复、导航、来源展示、资源生命周期等复制到多个消费者；是否只有一个共享 helper，而调用方仍重复关键策略。指出重复的语义和受影响消费者，提出合适的共同 owner、窄适配器及迁移路径。同时检查不必要的泛化、配置开关、层层转发、过度拆分和自建框架；不为了去重合并不同产品语义、信任边界或生命周期。
3. **成熟库与平台能力的使用。** 哪些自研实现可以合理复用平台能力、成熟组件库或开源方案，哪些自研确有必要。请结合目标运行时、实际版本、定制需求、包体、性能、维护、许可证及迁移成本比较。推荐库时给出具体能力和替换位置，并核实 WEAPP/Taro、React Native 或服务端的真实支持。不要仅因“有自研代码”就判定重复造轮子，也不要把现有约束当作永久拒绝成熟方案的理由。
4. **命名、类型与概念一致性。** 相同概念是否同名同义、不同概念是否被混称；目录/API/字段/错误码/枚举/单位是否一致；是否存在含糊的 manager/helper/service、过多布尔参数、不必要的 any/类型断言、以命名掩盖状态含义等。尤其关注时间、坐标、来源、版本、有效性、缺失与真实零值。
5. **状态、异步与鲁棒性。** 单一事实来源是否清楚；取消、乱序、重复提交、快速切换、旧结果回写、卸载/隐藏/恢复、账户切换、缓存失效、局部失败和重试是否正确。检查锁、事务、幂等、补偿、过期策略和资源释放是否真正位于负责边界，而非仅在 UI 中做防护。
6. **扩展性与可维护性。** 用现实变化检验设计：增加一种数据源/叠层、一类星体、一种资料模板或一个页面状态，需要改多少无关模块？是否依赖大量特殊分支、同类脚本副本或手工同步？也请指出当前规模不值得引入的复杂架构，避免为假想规模建议全面微服务化或推倒重写。

## 专题一：地图叠层完整渲染链路与内存

我们正在处理地形、云量、年度夜光/光害叠层的等待、连续操作和资源问题。请结合实际代码画出从用户拖动/缩放到正确内容显示的链路，检查：视野观测与意图、请求规划、供应/成品读取、服务端处理、传输、共享下载/文件、原生安装/替换、首个有效覆盖、最终细节，以及离页/返回时的退休和恢复。

请重点分析：

- 延迟可能落在哪些真实阶段；哪些可以从代码确认，哪些还缺关键观测；如何区分供应等待和我们自己的重复工作、调度、下载、安装或呈现等待。
- 短手势、持续未松手、跨覆盖、缩小后反向、加载中再次操作、切 My 隐藏、进入 Sky 卸载再返回，是否由正确的 owner 保持最新意图、有效旧覆盖和相机控制权。
- 稳定窗口、分块/整图、父图与细图、缓存/预取、渐进显示、静态/CDN分发是否有更合适的设计；不要默认“瓦片化”或“加缓存”必然获益。要说明平台支持、配准、透明度叠加、缺测、最终细节、请求/存储与原生对象成本。

- 请给出优先级最高的少量优化方向，每项说明代码依据、预期收益所在阶段、需要保持的语义、最小区分性实验和不采用的条件。

## 专题二：云观星正常播放、调时与内存

请检查正常 Sky 路径，而不只看局部绘制函数：时间意图与供给 → 准备与准入 → BSC/实际需要的 SAO → 投影、过渡、名称、图像、拾取 → GPU提交/Canvas复制 → accepted 状态及全部消费者 → 暂停、drain、隐藏、退出和恢复。

我们关心两项独立结果：A，输入到首个正确 accepted/可见结果的响应；B，正常持续播放的内存增长、长停顿、退出与资源释放。请分别分析，不用一项的局部改善证明另一项已经解决。

- 查六字段年月日时分秒、时间轴、Play/Pause及跨供给窗口的一致性；重复准备、失效请求、发布频率、React/数据桥、星体遍历/投影、文字/拾取、GPU buffer/texture 与当前帧缓存各自的责任。
- 查旧 frame/report/geometry/aggregate、React回调、query/cache、异步任务、闭包及native/GPU对象的可能持有者。区分已找到的强引用链、弱见证仍存活、分配churn、保留工作集和进程内存；不能把 WeakMap/缓存的存在本身当作泄漏证据。
- 给出在当前架构内可做的改进，以及确有价值、但需要另行评估的较大方案。成熟天文软件、渲染库和平台机制可作参考，必须说明迁移到当前 WEAPP 运行时的可行性与代价。
- 为关键假设提出能改变下一步决策的最小观测/对照，明确目标、窗口、真实非空负载、判定字段和停止条件。不要建议无条件再跑已失败的高负载远程 Heap/Timeline；若有新的支持条件或替代能力，请说明具体改变了哪条失败边界。

保持最大/全天空、地景、完整需要的 BSC/SAO、精确时间/星位、名称与点选准确性，以及取消/显式应用的原事务语义。不要把减星、任意节流、冻结画面、换成窄视角、短时没崩或更便宜的局部样本当作完整解决。

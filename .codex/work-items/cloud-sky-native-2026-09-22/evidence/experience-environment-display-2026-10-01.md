## 共同显示责任与参考差距

复用已保存的 Stellarium Web 暮光原图和条件，不重新获取月面或更换来源。参考当地 2026-09-30 18:35:53／UTC 10:35:53、22.4826799N／114.5557147E；秒以下未知，时间匹配误差不超过一秒。参考 Arcturus 显示推得方位 280.8807778°／高度 26.4444444°，roll 0 来自默认居中和直立地平的推断，未读取其私有引擎。短边 FOV 40.78913365°对应本实现纵向约85°；参考 CSS 390.4×844、原 JPEG 390×843，本轮软件绘图390×844，不声称所有边缘像素同相机。

原 renderer 把指数映射后的线性散射值又压入 .14／.27／.39 通道上限，低太阳还叠加额外 gamma，造成明显偏暗。新实现保原太阳、ENU、固定散射和曝光，只让指数映射结果经过一次 sRGB 编码，保深色基底、夜间和红光分支。编码系数核对 [W3C CSS Color 4 §19](https://www.w3.org/TR/css-color-4/#color-conversion-code) 的转换示例；它不提供现场大气测量或曝光标定，也没有复制 Stellarium 引擎。

在太阳方位的六条无遮挡参考射线、高度10°–60°上，编码 RGB 的加权亮度绝对误差均值79.13→33.09。修前真实生产软件GPU回归失败，修后通过；该值是有限图像亮度比较，不是物理测光或整场验收。低空仍偏暗，上空仍偏蓝，不能以这次改善关闭参考质量差距。

实际共同 scene／renderer 的26条件包含昼、日落、暮光、夜、红光、全部网格、星座、地景、局部／全天、倾斜视角和M31。14个夜／红光条件的全幅RGBA逐字节保持，所有条件身份／拾取结果保持，正常返回保持；GPU创建量相同，退休后纹理／buffer／program／shader均0，GL错误0。这里未设置原生导航遮挡范围，图像预解码，且不包含SAO、W3、日月行星细档；不能代替普通客户端请求、峰值、手机或全部功能。

同太阳高度−18°、0°、3°分支的两侧±.001°真实GPU采样未出现通道突跳。整场试验与当前源码的太阳算术／控制流一致；其后增加的原生导航表面由独立实际像素回归覆盖，不能把旧完整renderer字节冒作最新字节。

## 原生导航消费者

亮天空在实际开发器暴露白色原生状态字的对比度问题。本页已有 `nativeNavigationInsets()` 是界面测量的单一owner。Canvas复用它的statusBarHeight、capsuleBottom，以两者最大有效值，在全部天空／图片／地景及pending vertices提交后，按实际framebuffer比例清回当前帧深色基底。该表面属于界面，天文相机和地景不变化；不增加纹理、shader或平台轮询。缺失／无效指标不猜造尺寸，scissor在finally撤销，原GL错误／失效守卫继续执行。

实际指标statusBar47／capsuleBottom83、API window390×762／DPR3；此前元素几何390.4×844及实际PNG427×919是各自的观测，不能偷偷当成同一视口。软件回归覆盖DPR1、分数宽度DPR3、状态栏＋菜单、红光、短Canvas钳制和缺失／0／负／NaN回退：修前17,160个导航像素错误，修后导航背景正确，范围外像素保持、scissor无泄漏、GL0／退休资源0。

原生同North／45°／UTC04:00预览的两张实际PNG中，背景采样(80,28)由[168,201,240]变为[9,13,23]，按既有白色原生字契约计算的背景对比度1.71→19.42。排除导航、圆角和系统底条后的421×799有限场景区全RGBA差0。这只证明该界面表面和该场景区域，不是完整可访问性／所有控件／全天图或手机认证。首个验证误把shader基底[8,13,23]要求为原生PNG精确值，因红通道一个编码阶失败；原JSON保留，最终检查只允许每通道≤1阶并要求场景区精确相等，无产品改色。

## Responsibility and recovery review

The semantic dependency repair can proceed in development. ObjectRef, desired level and the owned asset remain the selection, resolution and source boundaries. Canvas revision and visibility remain decoding lifecycle boundaries. A newly acquired asset object still triggers all relevant effects even when its encoded file path is the same; source/publication metadata belongs to the validated discovery snapshot and owned lease, not a mutable catalog wrapper. There is no actual caller mutating that owned asset in place. Frame registration/time coordinates continue to come from the current report independently of image decoding.

Ownership continues to use lease release-function identity, rather than file-path equality. The actual setters preserve a recovery lease while a ready replacement is absent; fine decode failure retains valid coarse imagery and a late coarse image cannot replace ready fine imagery. Hide retires the decoded bitmap through the actual Canvas node/generation owner while retaining the permitted encoded recovery file. New Canvas requires a fresh bitmap. The three dependency repairs do not remove those paths.

The selected request begins a demand before discovery so public-cache clear cannot resurrect an obsolete acquisition. Active and recovery lease retirement subscriptions deduplicate by release identity. Retirement withdraws decoded state, releases owned files and latches ERROR until explicit retry; an entry-copy update must not bypass that latch. Weak native current checks retain the live lease plus Canvas node/generation checks, rejecting obsolete queued work. The dependency arrays do not need to poll `asset.isCurrent()`; the retirement subscription owns that event.

Existing shared native-image loading already centralizes encoded file cache, SHA-based demand/ready reuse and weak native lifetime. Replacing this selected owner wholesale with `useSkyNativeImages` is not a necessary repair: its descriptor-based acquisition API would need an explicit adapter for the selected pre-discovery demand fence, immutable source snapshot, active/recovery dual lease, selected coarse fallback and ERROR/retry semantics. A quick migration would add competing acquisition ownership or lose those semantics. Preserve them if that responsibility is later unified.

# D 当前发布镜像的静态资源 HTTP 与计费输入（2026-09-24）

用当前工作树与 `infrastructure/deployment/miniapp-api.Dockerfile` 构建独立镜像 `starward-miniapp-api:cloudsky-d-http-20260924`，镜像 ID `sha256:58bd0c2eec37784bf37d42e79960ce510cb4eaf0c0111dc80e5eda0b434d83b2`；本地 `docker image inspect` 的 Size 字段为 144,837,772 B，不把它等同上传压缩包或云磁盘占用。镜像配方在构建中断言保留 BSC v2/v3、SAO v2 和土星 OPAL 成品，并移除不纳入商用小程序的 Gaia DR3 pack。以 LOCAL/MEMORY_TEST/LOCAL_TEST、夹具关闭在专属容器和 `127.0.0.1:18790` 启动；`/health/live` 返回 200。此为当前代码的发布镜像内 HTTP，不是商业云部署或目标微信运行时。

可重跑的 [HTTP 探针](../d-release-http-probe.mjs)在此独立端口做真实 GET；完整机器结果为 [JSON](d-release-http-2026-09-24.json)。六类正式固定图（月、火、水、木、土、2MASS 银河）清单均 200、`no-cache`；图片均 200、`public,max-age=31536000,immutable`，响应字节数与 SHA-256 均等于对应清单。逐类把出版哈希换成错误值都返回 404，随后正确资源仍 200 且哈希未变。六图合计响应体 1,262,378 B，六份清单 10,656 B。这是“六图全取一次”的算术场景，不是一次典型用户浏览流量。

W3 宽场清单 5,951 B、properties 512 B，12 个基础瓦片全部 200、每片字节及 SHA 与清单一致，合计 678,144 B；错误出版哈希 404。该 12 片基础层不是 Stellarium 式全天高清光学覆盖，也不能外推 PS1/SkyMapper 云成本。

BSC v2/v3 原始 HTTP 响应体分别为 1,280,196/1,280,199 B；同 URL 携 ETag 重取均为 304、响应体 0 B，错误目录哈希 404。SAO v1/v2 索引各 282,405 B、826 片；各测一片 20,774 B，索引与片的 ETag 重取均 304，错版本哈希 404。`/v2/sky/optical/manifest` 在非夹具 LOCAL 服务返回 404，与商业不准入边界相符；这不替代商业配置/凭证/生产部署验证。

以 v3 BSC、v2 SAO 索引、六图及清单、全部 W3 基础层**强行全部下载一次**，响应体合计 3,520,245 B；不含 SAO 瓦片、星座、其他目录、请求/响应头、TLS、缓存/CDN、重试、压缩和用户访问频率，不能称为整页实际用量或月费。304 只证明服务响应体为零，并不证明零网络开销或命中率。费用仍需要目标真实请求轨迹、在线用户/访问频次、缓存/CDN与云存储配置及供应商账单价格；Agent 开发现金另列，不从这些字节推算。

现有正式部署配方 `compose.yml` 让 Caddy 直接反代同机 API，`Caddyfile` 开启 zstd/gzip，但没有配置 CDN 或对象存储静态资源出口；API、worker、PostGIS、Redis 的容器内存上限分别为 512 MiB、512 MiB、1 GiB、256 MiB，不能当作峰值实测。固定图/W3 的哈希 URL 与 immutable 指令利于客户端/中间缓存，当前不等于已验证微信客户端命中；BSC/SAO 的 ETag 只证明条件请求节省响应体。当前已付上海 Lighthouse 4核/4GB、3 Mbps、40GB SSD、300GB/月套餐是 owner-only 预览足迹，不是未来商业生产容量或新增云观星预算。旧成本研究的 5MB/DAU/天、90% CDN 命中、100GB 文件假设均未由本次探针证明，尤其当前正式配方没有 CDN。

后续可填实测变量的口径：按资源与响应状态分组，`月出口字节 = Σ(200次数 × 实际压缩后响应字节 + 304/错误次数 × 实际报文开销)`；再加 TLS/代理与其它 API、重试，按云厂商实际计费边界核对。`月静态存储 = 当前实际发布文件及版本副本 + 备份/镜像占用`，不能把本地 125,921,895 B 在用源文件库存等同云账单。若引入 CDN，再单列实际命中、回源、请求数及服务费；现在不按虚构90%折减。Agent开发/维护有效时间与项目方参与时间单列，新增使用费仅凭账户可核支出填写，已有订阅额度未知不填零。当前数据可供容量风险推演，但没有生产用户请求分布、Caddy实际线上压缩、平台缓存、峰值并发与账单，无法得出月费或达标容量。

运维观察边界：现有 Caddy 日志按项目隐私规则删除完整 request 对象及响应头，保留状态/时延/字节等总量；现有 `vendor_call_usage` 只计外部供应方尝试，W3/固定图本地服务不进入此账本。因此现有记录不能复原云观星每个资源类别的真实 200/304 请求数或客户端缓存命中，更不能用供应方费用视图代替出口流量账。后继若要做资源类别计量，应在不记录用户URL、地点、查询或原始头的聚合边界设计，经过所有消费者/隐私 owner 检查；不能为了费用审计恢复含敏感 query 的通用访问日志。

专属容器以 `--rm` 启动，验证后已停止并自动移除；当前镜像保留供复核。共享 8787、用户容器、Android、微信开发者工具及活跃 WEAPP 输出均未使用或变更。当前探针不覆盖 POSTGRES 下受账号/地点/时间影响的完整 Sky 报告，已有 C07 独立持久库证据只证明当时版本；下一步需按部署责任复核真实生产配置与成本/容量缺口。

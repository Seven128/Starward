# B1/B4 当前候选搜索、画面星点→资料→来源→定位

沿 HORIZON0928 本地 DevTools 候选与同一公开示例观星点继续观察，Asia/Shanghai 民用 09 月 29 日 00:00（UTC 09 月 28 日 16:00）、手动北向 45°、实际 Canvas 390.4×844 逻辑像素。当前画面可访问状态回读 4121 个真实亮星目录对象，场景帧为 16:00Z。这里仅是官方开发工具上的当前候选消费者证据，不是手机触摸/真屏合成或独立验收。

1. 先从 Sky 返回原 Map 地点并重进，手动查看后没有定位标记。[点选前真实 Canvas 截图](experience-pick-no-marker-probe-2026-09-28.png)为 197×423、91671B、SHA256 `de6cd75aaeed00fae2aa377e276ce52444e96535bb455c4a43a12cba7d6f0e6c`。图片已目视检查；在截图像素 (28,86) 有亮星，换算为 Canvas 逻辑点 (56,172)，附近没有 WXML 命名星标签。
2. 官方 automator 对**视口坐标 (56,172) 执行自然 tap**后，星点资料弹层实际出现 `HR 8853`，类别 `恒星 · HR 8853`，别名 `HD 219623`、V 波段视星等 5.54 mag，当前方位 346.0°/高度 57.7°。使用源码当前手动北向 basis、45°/390.4×844 和弹层已四舍五入的方位高度，`projectSkyDirection` 算得 (55.58,172.44)，距实际点击约 0.60 逻辑像素；这是画面坐标与同一身份/时刻一致的独立几何核对，舍入值不能当作精确天文测量。
3. 弹层中的“来源与许可”实际导航到 `sky/sources/index`；标题副题仍为 `HR 8853`，加载后可见 4 个来源卡，包括 HEASARC 与 Wikidata，没有空/加载占位。该页返回到 `sky/detail/index` 后，弹层仍是 `HR 8853`。再按“定位到星空”，弹层关闭，已绘 45°/16:00Z 未换帧，中心出现 `HR 8853定位标记，查看资料`。这条路从未命名画面星点进入真实资料、来源、定位，未将其他星的资料代入。
4. 诊断中曾对 Canvas 元素逐条注入 `touchstart`/`touchend`，SDK 各返回 success、反馈出现 `end0`，但没有资料弹层；在有 Vega 定位标记及无标记重进两种状态都如此。自然坐标 tap 在无标记状态成功，说明前述低层事件注入不能代表正常点击，也不能据此断定产品点选故障。当前不修改生产拾取逻辑；真机手势、密集天区多候选、其他对象类别及失败恢复仍需目标/代表组合验证。

另在同页已打开的天体列表，通过[官方 SDK 可重跑输入脚本](../scripts/experience-search-withdraw-2026-09-28.mjs)检查旧查询撤回：先让“织女星”稳定出现 Vega，再输入“木星”。输入调用后约 11 ms 的 WXML 采样显示新输入值与旧 Vega 结果短暂并存；约 85 ms 样本为“正在查找”且无 Vega，约 311 ms 样本为 `PLANET JUPITER` 且无 Vega，最终仍是木星。上述毫秒值是 SDK 命令/采样的耗时，不是用户可见帧时或手机中文输入法测量；它说明旧结果没有持续留在新查询下，但一帧附近的旧结果短暂状态仍应在目标交互核对，不能声称“同步瞬时撤回”。关闭列表后回到原45°/00:00手动视角。

本次只增加开发观察与证据，没有生产源码变更、重复构建或以测试数量替代结果。候选 API 为本机 loopback，未推手机；旧 D 手机证据不升级。

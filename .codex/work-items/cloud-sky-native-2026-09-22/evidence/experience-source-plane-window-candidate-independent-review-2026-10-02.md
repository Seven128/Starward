## Ideal mathematical argument

Let `R` be `registration.rows`, `d` be `registration.determinant`, and `D` have the three original unit anchor directions as columns. Then `R = d D⁻¹` and **`D = d R⁻¹`**. The scalar must be the registration determinant: `det(R)=d²`, so `det(R) R⁻¹` would be incorrect. An earlier reviewer message used that ambiguous/wrong notation; this note and the executable review use the corrected formula.

With `B=[1;anchorU;anchorV]` and barycentric weights `t=B⁻¹[1,u,v]`, the original source plane is `s(u,v)=D t`, affine in UV. Its weights sum to one. Consequently `R s=d t`, `sum(R s)=d`, and the original inverse mapping of `normalize(s)` returns the same UV with the positive branch. The plane normal `sum(R rows)` satisfies `n·s=d` everywhere, giving `|s|≥|d|/|n|`; maximum norm over the source square occurs at a corner. These facts give a valid ideal nonzero source-plane and denominator bound without sampling an interior grid as proof.

The actual positive viewport hull encloses the curved stereographic viewport. Each correctly oriented hull halfspace becomes a linear UV inequality `h·s(u,v)≥0`. Intersecting those inequalities with the source square yields a convex polygon containing the ideal visible source set. Its UV extrema are attained at vertices, so a conservative padded AABB can retain all ideal source texels. Invalid inverse geometry, uncertified wide viewport, degenerate normals, unstable intersections and empty/rounded-empty results must preserve full source. An empty polygon in this candidate is deliberately not an image-demand cull.

The independent execution recalculates original directions from the raw star catalogue and observation instant, then derives the affine plane directly from the three UV/direction anchors. It does not use `inverse(R)` as its expected plane. Direct and recovered affine coefficients differ by at most `7.66053886991358e-15` in these inputs. A separate vertex enumerator intersects every pair of ideal halfspace boundary lines and tests all inequalities; it does not reuse the candidate's Sutherland–Hodgman routine, polygon or heuristic expanded coefficients as an oracle. All 28 ideal domains fit the reported windows.

The recomputed candidate has 11 partial windows: original illustration cost 21,495,808 B becomes 16,506,880 B, saving 4,988,928 B (about 4.76 MiB, 23.2%). Existing galaxy/foreground windows add 9,437,184 B, giving 25,944,064 B. That still exceeds the current 16 MiB frame-end retention policy. These are hypothetical retained texture bytes, not native decoded memory, driver peaks, throughput or acceptance. The original encoded files and full-source decode cost do not shrink.

## Actual float path and footprint risk

The current artwork fragment declares `highp float`, computes the stereographic ray from camera uniforms, calculates three row dot products, sums them, rejects a near-zero/wrong-sign denominator, divides two anchor-weighted numerators and samples `(uv-imageOrigin)*imageScale`. It then performs additive compositing. CPU double affine clipping is not identical to this complete path.

The candidate's 64-ulp UV/world expansion is explicitly an investigation of the current owner's convention. It does not yet bound every uniform conversion, camera/ray operation, varying interpolation, row/anchor product, cancellation, division, clipping coefficient, sampler remapping or target precision variation. A minimum double denominator exceeding a heuristic roundoff term is not such a certificate. A production implementation needs a defensible outward error bound for its admitted device/input domain, or full-source fallback when that bound cannot be established. Conditions on matrix/UV area, norms, sign, inverse residuals and ray-cone validity remain essential; no one successful near-singular case justifies widening them.

The independent diagnostic evaluates a nearest float32, non-FMA sequence of the actual shader formulas at every 390×844 pixel centre, using rounded current camera/row/anchor uniforms. For all 28 images it found zero missing LINEAR neighbours in the candidate windows. The largest UV arithmetic difference against double evaluation using the same perturbed ray was about `1.6391e-6`, for Vul. This is a finite discrepancy guard for this operation order, viewport, DPR1 lattice and uniform set. It does not certify the continuum, FMA/alternate dot-product orders, interpolation error, rolled/offset views, changing time/pose, other source sizes or target shader precision.

Texture footprint is a separate boundary. Full source and cropped source must address the same original texels, including texel-centred LINEAR neighbours; `imageOrigin/imageScale` arithmetic must keep its outward allowance. Existing no-mipmap LINEAR behavior must remain explicit. Copy unavailability must still keep the full source and its matching origin/scale, without a stale window or publication identity. GPU-copy overlap, context loss, failed upload/retry, source retirement and any shared-source/multisampler preparation remain necessary affected-owner paths.

Four independently invoked candidate controls—uncertified 274.9° hull, degenerate UV triangle, zero row inverse and wrong original anchor directions—return the expected full window. This checks those real fallback branches, not all possible numerical failures. Other uncertainty should conservatively retain full source rather than become an assertion, an empty image or a scientific-coverage statement.

## Pixel oracle must detect a harmful change

At the original 139° condition, actual artwork opacity is only `0.0002368`. RGBA8 output can quantize a small contribution away, depending on existing destination/blending/dithering. Therefore a normal A/B screenshot or even complete RGBA equality may have no detection power for a lost illustration. The actual original opacity run is still required for its stated scope, but it cannot alone establish crop correctness.

A bounded software-GPU trial should keep the original view, source bytes, registrations, draw order and objects, and separately expose a clearly labelled visible counterfactual—for example isolated artwork on a controlled background with increased opacity. It must compare complete pixel arrays, bind source/driver/precision/GL-state details and prove that an intentionally harmful crop mutation fails that same pixel oracle. A gross one-texel crop is already caught by the independent geometric neighbour guard in all 26 images with valid fixed-lattice fragments; Boo/Cet have zero valid samples in this view and must not count as positive pixel evidence. This geometric mutation is not a substitute for the requested GPU pixel-oracle mutation.

Nonzero source contribution and sensitive mutation matter more than output count. A combined new crop/retention experiment should preserve separate baseline, crop-only and retention-only results so one mechanism cannot hide another discrepancy. Even a passing bounded visible trial would establish only its software runtime inputs; adoption still requires the numerical fallback and affected consumer/lifecycle obligations.

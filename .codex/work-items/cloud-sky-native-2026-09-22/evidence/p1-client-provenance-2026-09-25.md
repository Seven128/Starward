# P1 隔离预览的客户端代次判别

上一次以动态后端的 Sloan 来源文案推断客户端代次已撤回。本次在 Taro 配置中增加仅 `MINIAPP_ISOLATED_CHECK_BUILD=1` 才接受的短标记常量；普通构建恒为空，错误地给非隔离构建设置标记会直接拒绝。Sky 只在该标记非空时把它放入现有视场状态区，生产页不出现版本文案。该标记是开发反馈辅助证据，不能代替微信内部包哈希或正式视觉验收。

首个隔离构建因 PowerShell 单元素字符串索引失误把完整局域网 API origin 截为首字符，已判无效，未送手机。第二个独立槽 `weapp-check-sky-provenance-b-0925` 以完整旧候选 origin 重建：Mini typecheck、Taro 正式 WEAPP 构建通过，仍是既有三项 CSS/体积建议。257 个文件；编译后的 Sky JS 中 `P1RING25A` 恰出现一次，旧候选无此字串，新候选完整 origin 与旧候选相同且没有 loopback。

项目反馈 owner 对该独立源包建立私有 generation 1，本地指纹 `fde6e394fc5b61800b68bd07b53a2503e5a9ab9b8a9da98199be91b9c230b428`；官方同账号自动预览命令完成。唯一受权无线 Android 通过项目守卫在 1080×2376 手机实际星图看见右上 `验证 P1RING25A`，随后 owner 绑定该代次。Agent 沿现有 UI 从地点页进入 Sky、选择手动查看、列表中的土星及“定位到星空”；此时同屏有标记、土星定位、星场和普通控件，仍是宽视场，没有新环高倍画质结论。私有截图、设备标识、反馈 run 和源包临时目录均不入仓库。

下一项仅在本代同一页面持续显示 `0.05°` 时，抓实际土星环缘、OPAL/环影；整页帧耗、内存、真正调试 AppID 与微信内包字节另需对应证据。旧代标记缺失及当前标记出现只构成客户端代码路径身份，不证明同一源码的无标记正式包画面。

同一源码另以 `MINIAPP_SKY_FEEDBACK_ID` 为空构建 `weapp-check-sky-clean-provenance-0925`：257文件、构建退出0，编译字节中零处 `P1RING25A`；带标记包恰一处。两者都仅是隔离检查槽，未将无标记新包推送手机。验证文案没有进入该普通配置产物。

继续检查发布消费者发现 `releaseBuildEnvironment` 原先从终端继承隔离构建开关。新增旧行为回归先失败（继承 `MINIAPP_ISOLATED_CHECK_BUILD=1`），发布打包现明确清除隔离检查/夹具开关、slot 与 Sky 标记；8项发布打包测试修后通过。这防止正式构建受开发反馈环境污染；当前手机候选源包字节未因此改变。没有执行远端发布。

前一代作废反馈 run 的 watcher 后来自行释放；项目 owner 再次 stop 返回 owned_run_removed，phoneDataChanged=false。当前带标记的反馈 run 仍保留。

用户再次确认手机停在 `0.05°` 后，agent 用当前 feedback run 的嵌套受保护设备会话经 wireless ADB 新抓 1080×2376 真屏：同帧仍有 `验证 P1RING25A`、`土星·定位`、星场及普通控件，却没有角度读数，画面是宽视场。项目 doctor 同时只见一台授权 wireless `device`。因此本次回复与抓屏之间的倍率状态并不一致；此帧不能用于高倍环缘/OPAL/环影判断，也不能归因于单一手势缺陷。源码只在原生手势取消、主动校准、页面重挂载等路径可回默认倍率；中心定位按钮可能截获触摸，但尚未取得事件轨迹。保持同一代候选及设备会话，先核用户当前可见读数，再抓同一状态复测，期间不刷新或重推包。

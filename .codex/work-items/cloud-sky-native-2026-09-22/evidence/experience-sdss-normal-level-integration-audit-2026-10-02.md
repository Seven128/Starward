## Necessary new immutable publication meaning

A new explicit optical publication version must bind actual canonical raw source identities/receipt hashes, actual projected/coherent science and joint-availability master identities, the actual transfer recipe and RGB mother identity, crop/box recipes, exact TAN geometry (including CRPIX), and encoded file bytes/hash/format. All three levels must reference the same science/RGB mother and transfer, rather than separately fitted images. The master supplies finite zero/negative and source absence before display; it does not certify source artifacts, PSF, depth, astrometry, natural color or scientific quality.

New encoded levels supplied to `artworkLevels` must declare the real producer's **joint-area-alpha** meaning: alpha is the area fraction of coherent eligible master samples contributing to that texel, with availability-premultiplied RGB box means. This is distinct from a binary HIPS nearest-sample mask and from the task's alternate `encoded-display-contribution-v1` alpha. The latter alpha is derived from brightness and cannot go into the availability slots. Reuse the existing availability RGBA; do not add a second coverage image just to satisfy an adapter.

The current 2048→512 mother uses box factors 4, 2 and 1. For these factors, an incomplete group cannot round to alpha 255. The shader then requires all four neighboring encoded alpha values to be complete. This finite supported producer/consumer relationship must be recorded/validated; an arbitrary future large box factor could round an almost complete area to 255 and cannot silently inherit the same complete-stencil proof. This is a scope condition, not a failure in the current candidate.

Use the new publisher's actual level `fieldDegrees`/WCS/CRPIX; do not derive new geometry from old JPEG `scaleArcsecPerPixel`. Example: actual candidate MEDIUM field is `0.11377788994540003°`, while v1 JPEG metadata is `0.11377777777777778°`. Both currently use the known centered geometry, but the new exact TAN crop belongs to its own immutable contract. `registerSkySurvey` already accepts explicit pixels and one-based CRPIX; it remains the shared ray-plane registration owner.

The minimum compatibility change is an explicit new-format offer plus lookup by admitted immutable hash while retaining the existing JPEG offers and unversioned legacy discovery. Replacing `SDSS_OPTICAL_PUBLICATIONS["M:51"]` alone loses old hash lookup at the BFF and breaks old client discovery validation. A new default cannot be justified by the prototype review. New-format capability can be developed against a task-bound/test publication before any quality adoption or live publication.

## Actual source-route gap

The existing `imagePublicationHash` route parameter has a specific W3 meaning:

- `sky/sources/index.tsx:18` and `use-celestial-information.ts:6` carry it into the resource identity.
- `services/api-client.ts:932` sends it as `deepSkyPublicationHash`; response validation in `celestial-information-response.ts:28` checks only `imagery:` sources.
- BFF `controller.ts:437` and `celestial-object-information.ts:149` select the W3 publication. `:154` independently calls `optical.source(reference)` without a hash, and the information cache key `:70` contains no optical version/hash.
- `api-client.ts:1026` makes an optical manifest download link only when the source ID matches the single current admitted `SDSS_OPTICAL_PUBLICATIONS` offer.

Consequently that existing parameter must not be repurposed as an optical hash. The smallest necessary route extension is an independently named/validated optional optical publication identity, carried through the completed displayed image → modal/source route → hook/client cache and response validator → HTTP/service information cache → optical source lookup/download link. This retains default behavior and independent W3 source selection. Old and new immutable optical hashes must remain resolvable for old frames and fixed downloads. Missing optical provenance must preserve independent catalog/W3 information as PARTIAL with retry; it must not disclose a newer current source as if it produced older painted pixels.

## Actual contribution and failure semantics

The normal scene/page cannot map `submitted` or `finePrepared` to `paintedSdssOpticalImage`. A group may submit with every fragment discarded, an all-black eligible fine region may intentionally exclude a colored coarse region while changing no background pixels, or only coarse may contribute after fine upload failure. Current `artworkIntersectsView` and RGB `displaySupport` certify conservative eligibility/empty rejection, not exact selected sample coverage or visible contribution. DisplaySupport must never decide scientific availability.

A shared group-consumer result must separately preserve: (1) which inputs uploaded/prepared; (2) which field was eligible under the same four-texel rule and fine-over-coarse selection; (3) whether a selected nonzero encoded RGB contribution actually remains in the current viewport after the foreground draws; and (4) the immutable publication identity of that contribution. The minimal publication credit is the one common optical publication when either coarse/fine really contributes; any per-level presented diagnostics must reflect the actual contributing field/set. The current last-single-image result is insufficient for simultaneous partial coarse/fine. The normal page may keep a single publication-level credit, but it must not label a failed or fully suppressed fine image as the displayed source.

Reuse the shared registration/view and foreground mask owners plus hash-bound encoded selection/contribution evidence. Do not use a prepared Boolean or mere field cap intersection as an approximation for that requirement. Any new bounded CPU metadata/support computation must implement the same availability/selection rule once and must identify conservative uncertainty honestly. Full-frame native GPU readback, an invented renderer framework and per-object exceptions are not implied by this audit.

Required affected behavior:

- Fine loading/missing/error/upload failure keeps the independent valid same-publication coarse field. Error remains separately retryable; it does not erase valid coarse pixels or provenance.
- Fine partial/missing stencil chooses coarse there; outside the fine domain coarse remains eligible. If neither has complete qualification, preserve actual sky background.
- Eligible fine black excludes coarse and produces zero display contribution. It is valid source data and cannot be turned into a missing-source fallback or counted as a visible photograph merely because it was prepared.
- Late responses, reference/publication change, mode switch, canvas generation replacement, hide/show and dispose retain the existing image/file/texture lifecycle guarantees; stale sources cannot enter a new frame's credit. Keep the existing pair pin/release mechanism.
- A normal scene still chooses one selected optical/infrared target spectrum. If the optical group provides no visible contribution, preserve the independent W3 path according to the scene's declared fallback policy; this decision must not accidentally expose W3 through a valid optical-black sample or interpret science absence as permission to mix spectra. The exact grouping/spectrum selection policy needs to be stated before implementing this branch.
- Subsequent foreground/optical HiPS coverage and the completed-frame callback remain real downstream consumers. Credit cannot be decided before the relevant later occlusion, nor inferred from the task harness's deliberately null source credit.

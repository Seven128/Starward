## 原始波段与 DR11 交叉检查

按[官方 DR10](https://www.legacysurvey.org/dr10/description/)及[DR11 cutout 文档](https://www.legacysurvey.org/dr11/description/)的 `fits-cutout` 参数，在相同 M104 中心、256px、2.0″/px、`bands=griz` 分别取得 1,054,080 B 的原始 FITS。DR10 SHA-256 `03e156e15aefbc8fe3cf79d5f997d03193f9b384745a8445274cbc757ffb20e5`；DR11 SHA-256 `3cae9d5c9b04d2838ed5d7c4d2131768d5259a42b6dbb66b219dd40fcc43f2ab`。两者头均是 4×256²、`RA---TAN/DEC--TAN`、CRPIX=(128.5,128.5)、2″/px；这里仅分析同一中央区域，没有重新定义整图覆盖。

在翻转为 JPEG 顶向下行序后，DR10 `r` 波段的 x=18–33、y=136–158 **16×23 连续像素精确为零**，其它 g/i/z 在该区域有信号；这与官网 JPEG 中左侧粉红矩形位置一致，说明它源自缺失波段而非 Starward 的渲染/配准。DR11 同区域 `r` 有信号，但 x=15–39、y=132–163 的 `i` 波段 **800/800 像素为零**。DR11 官方 `ls-dr11` 512px、2.0″/px JPEG 69,824 B、SHA-256 `b9318efbffb06c41321d3c01b11b114a7d32b27082d642a40862afbc4ddf16c3`，目视没有 DR10 的小粉红块，却有绿色大片及水平色阶。一次 `ls-dr11-grz` 同尺度 JPEG 请求为 HTTP 500，既没有可用成品也不推断该参数长期不可用。图像与只在 ignored 试验目录的分析脚本保留用于复算；未进入包、服务、Context 采用状态。

按官方 viewer 的 `&invvar` 实际再取与上述色块中心对应方向、128px、**原生 0.262″/px** 的 DR10/DR11 `griz` FITS：两份各535,680 B，均有4×128²主图与同形 `IMAGETYP=INVVAR` 扩展；SHA-256 分别 `e4b07684f4d59f308ecba8c541837865e3e01429586a48183c85535b12744e94` 和 `6252fa588846ec8d198d5d160aae180f0afd6dcf2a07e218bf79b7dd1eacfc09`。同一原生中央32×32区，DR10 `r` **1024/1024 主图为零且逆方差也为零**，确认该区域没有可用 `r` 观测权重；其它三带的逆方差为正。DR11 同区四带主图与逆方差皆非零，包括 `i` 中位主图约0.0959、逆方差约9231。因此上文 DR11 的 `i` 全零只属于**本次官方 2″/px 重采样 cutout**，不能断言 DR11 原生 coadd 在那里没有 `i` 观测；可能与切图重采样/重叠砖选取有关，机制未证。直接选择官方 JPEG 仍有实际色块，但 DR11 原生波段可能支持不同的自加工路线。

相同接口若以128px、2.0″/px请求 DR11 `griz&invvar`，HTTP200 文件只有267,840 B、一个主图 HDU，没有 `INVVAR` 扩展（SHA-256 `b5c2fd797c3c90459ba53c451b96ef3dd8c84553331e1a06d67795a97acbea9c`）。不能因查询带 `invvar` 就假定粗尺度每像素有质量权重；要做有效像素判断须从原生切图/原始砖另取权重并按同一 WCS 加工。这增加加工与源流量，不是免费提供的成品判据。

因此不宜对缺波段区域只做全图色彩拉伸；独立候选需核逐像素有效权重、切图尺度和拼接一致性，制定可解释的缺片/降级或可追溯改作，且不能把插补伪装为原始观测。DR11 官方数字显示南方加入新数据、共同波段覆盖扩大，但 M104 单例已证明换发行版的现成彩色 cutout 不自动解决目标级质量。[DR11 官方文档](https://www.legacysurvey.org/dr11/description/)还提示北方仍是 DR9 源，两区不能视为同质单图。下一项是限定少量对象/视场的可用像素规则、原生波段加工可行性与真实取图负载测量；满足质量、可见署名与自托管成本之前继续关闭商业光学。

## 原生质量与获取负载的有界复测

官方 [DR11 cutout 说明](https://www.legacysurvey.org/dr11/description/)明确单次最多 512 像素、原生采样约 0.262″/px。针对上文 **DR11 粗尺度 `i` 零块对应的方向** `(RA 190.0555°, Dec -11.6344°)`，仅一次请求 `ls-dr11`、`griz`、`invvar`、512×512、0.262″/px；原始 FITS 存 ignored 试验目录 `ls-dr11-gap-native-512-invvar.fits`，8,398,080 B，SHA-256 `95094a01fbbc3dab4edfbc280026e053f36ea3e2f60e59f1b939a45671058c77`。文件有 4×512² float32 主图及同形 `IMAGETYP=INVVAR` 扩展。中心 128×128 的四波段逆方差均为正，整张四波段同时有正权重 262,070/262,144 像素（99.9718%）。这进一步支持“本方向 DR11 原生数据可用、先前粗尺度 `i` 块是切图产物”，但只有单方向；权重为零与天空扣除后的主图负值不可混为一谈，也不能把此比率外推为目标或整片覆盖。

此真实文件还量化了加工入口：一张原生 512 像素切图只跨 134.144″；0.05° 即 180″ 的**纵向**视场至少需要两张，且 390×762 逻辑视口的横向约 92″ 在切图边界上可能需要两列。因此按本例相同波段+权重、每张同样字节量，单个高倍视场的原始获取量粗界为约 16.8–33.6 MB（2–4 张），未含重叠、重试、邻近 LOD、生成产物或云端流量。它是一次源站取数/加工量级，不是终端传输、存储价格或全产品费用；任意天空浏览也不能逐视场实时依赖这个源站。下一验证仍是代表区域的权重掩码、跨切图拼接/色彩和可复用成品体积，再测发布/缓存/流量，不直接接入生产。

同方向又取一张向西约384原生像素的相邻 DR11 原生512px `griz&invvar` 切图，中心 `(RA 190.0269671088°, Dec -11.6343985967°)`、8,398,080 B、SHA-256 `4f6ba7a5f9e26c51be9848153a207daac534c4eb58941631c1ef5174e6c57e6e`。把首张右128列与相邻张左128列作**未重投影**的名义重叠比较：四带各65,536/65,536像素两侧均有正逆方差；`g/r/i/z` 图值绝对差的95百分位分别约 `0.000369/0.000390/0.001185/0.001305`，相对两侧逆方差合成噪声的95百分位约 `0.059/0.067/0.060/0.064`。复算脚本仅在 ignored `artifacts/miniapp/cloud-sky-native/legacy-surveys-trial/m104-levels/measure_native_overlap.py`。这在**一处同区域、相邻原生请求**没有发现明显权重断层，为可拼接性提供局部证据；名义列比较包含微小 TAN 网格偏差，不能推出彩色成品无可见缝、整个 M104 或 DR11 footprint 一致。C 下一项收敛到同一 WCS 的重投影/加权合成、实际彩色输出及其它代表区域质量，再量生成物和分发成本。

中心质量又给出相反的限制。M104 本体中心 `ls-dr11` 原生512px `griz&invvar` 文件 8,398,080 B、SHA-256 `712651fe1ba1e457ce7174ef547f037e10d53da6040a1a41493713efe605c5a1`；四波段同时有效权重为 261,362/262,144，看似覆盖率很高，但 **782个无效像素聚在目标核心 x=219–285、FITS y=247–263**。单波段无效分别为 g=5、r=690、i=208、z=515。ignored 的 `preview_native_center.py` 只用各带局部百分位做**非光度、非自然彩** PNG 检查，所有缺测像素置黑；实际预览出现黑色核心椭圆，不能作为成品。不能以全图99.7%有效率掩盖目标中心的缺测，亦不能把邻像素填成真实观测。

为避免只靠一个南方目标判断，又按本项目 OpenNGC M51 身份 `(RA 202.469625°, Dec 47.1951666667°)` 从[官方北区 DR9 图层](https://www.legacysurvey.org/dr11/description/)取原生512px `grz&invvar`：6,301,440 B、SHA-256 `033b038480dfc2d4d7c664f53b685cabaf39ca083e54bbbb5e059c106eead595`。DR11 文档说明北区沿用 DR9 且无 `i`，所以没有伪造第四带。三波段同时有效 243,607/262,144；核心64×64仅3,477/4,096同时有效，**619个至少缺一带、304个三带皆无效**。整图 `z` 带18,264个无效，不能从粗 JPEG 的青色/拼缝直接推定唯一原因，但原生中心本身也不能无损给出完整多色目标。这两个方向均不满足“中心真实数据完整”的高质量目标候选，需另源/不同观测或诚实降级；局部接缝数值好不等于可发布。下一项优先建立目标中心与瓦片全域分开的权重/视觉准入及实际输出质量，避免继续把 Legacy Surveys 当作普遍合格光学替代。

再按 OpenNGC M101 `(RA 210.80225°, Dec 54.3489444444°)`取北区 DR9 原生512px `grz&invvar`，6,301,440 B、SHA-256 `88fb8783e43f00a4f9f8ba380c954dcf7dcfde34a6d53b62accc0e0f9b814249`。核心64×64三带权重全部有效，说明上述两处“中心缺测”不能机械推广到每个明亮星系；但全图同时有效仅256,901/262,144，`z` 带另有5,243缺测像素。与 M51 一样的 ignored 非光度 `z/r/g` 各带局部百分位预览可见边缘多块黑色缺测和色彩/块边；M51 预览同时可见中心黑孔与大块缺测。预览只是诊断图，局部拉伸可放大色差，不能据其断言最终自然彩或特定拼缝机制。三目标结果要求将**目标中心、整片有效像素、视觉成品**分开审查；只过任意一个比例或连接检查都不准入。后续若没有适合的真实多带组合/可解释降级，不为交付硬造补色。

另用项目 OpenNGC 的两个短轴目标测试单张原生切图的候选条件：M57 `(283.395875°, +33.028583°)` 主要轴1.27′，M76 `(25.582°, +51.575°)` 主要轴1.12′，理论上都小于单张512px、0.262″/px的2.2357′边长。官方 `fits-cutout` 的北区 `ls-dr9-north`、`grz&invvar` 在 M57 512px 和64px、M76 64px 均返回 HTTP 500；相同接口/图层对已知 M51 64px 同时返回 HTTP 200 `image/fits`，故不是本机整体断网或图层参数普遍无效。不能把500解释成已经证实无巡天覆盖，也不能把单张尺寸理论上容得下目标当成可取/可发布图像；这两目标在本次没有样图，停止继续随机取点。小范围产线同样需要目录级可用性预检及故障降级，不应对在线 cutout 作请求即有图的假设。此次未改生产代码/出版开关。

改以 OpenNGC M97 `(168.699°, +55.019°)` 作另一类代表方向，北区同接口64px预探返回200；原生512px `grz&invvar` 取得6,301,440 B、SHA-256 `0d5c7fb9373dc2dc37d68c42818ca767d70820d53845c26b87c236e608c0c677`，三带同时有效259,780/262,144、中心64²为4,096/4,096有效，但中心128²仅16,073/16,384有效，主要是 `z` 带全图2,338个零权重。官方同中心512px原生尺度 JPEG 44,595 B、SHA-256 `db403be6fe462a0bd8f6782226fff8285e9520aa9d692760f80aab6dac8f9bda`；目视几乎整张为亮青蓝背景，中央 M97 星云结构不可辨，边缘色阶/色斑与星点伪色明显。局部百分位诊断 PNG 同样有强烈彩色渐变及黑色缺测点，但只作掩码检查，不是自然彩。M97 本体主要轴3.58′大于单张2.2357′，这张本来也不能覆盖完整目标。中心64²权重全有效不足以成立产品画质；不能将官方 JPEG 上线，也不能推定原始数据经其它可追溯加工一定无法用。该单次样本继续留 ignored 试验目录，普通商业客户端门禁不变。

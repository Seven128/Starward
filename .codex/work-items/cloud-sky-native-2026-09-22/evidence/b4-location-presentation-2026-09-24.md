# B4：定位标记与当前原生画面

B2 已有日月行星数值、盘面、来源图/恢复 owner 和同帧标签的非手机局部证据，但进阶外观与微信像素仍开放。B3 现有晨昏/散射、2MASS 和 W3 有独立局部证据；Sky 真地景所需数值 DEM 与可证明观测站位/高度未同时具备。已绑定 COG 的约 100 m 邻域试算可造成最高 4.713° 山脊角变化，`SpotSummary` 无站位精度且海拔可空。俯视 RGBA 不能代替天空山脊，保持 P2；B4 对象交互不依赖这个输入，因此继续非手机组合链。

检查当前页面、`sky-object-location`、跟踪、公共 Context 会话、相机/校准及其消费者时，发现定位标记虽要求位置与当前报告的地点、时刻、目录和算法版一致，却未要求报告已在原生 Canvas 上提交。新位置先返回、旧画面仍可见时，WXML 标记会抢先叠在旧星图上。对页面实际 JSX 条件抽取的回归在修前失败；现复用页面既有 `presentedSceneCurrent`，同时要求同一报告对象、精确时刻、模式和健康 Canvas。旧/失败画面撤回标记，完成对应帧后才恢复；旧位置校验仍独立生效。没有新增第二份天文位置、相机或 Canvas 状态。

先运行 B4 五组组合检查，校准集成测试中的两项因测试 VM 未提供页面新增的 `setPresentedSkyFrame` 回调报错，其余 37 项通过；补齐测试夹具后相同 39/39 通过，覆盖时刻/日期迟到响应、换地点/隐藏、校准冻结、总览返回最新姿态、跟踪意图与手势取消。定位标记加目标标签、Context、跟踪、手势的定向检查 28/28 通过。Mini 类型检查退出 0；正式构建使用专属 `dist/weapp-check-sky-b4-0924` 并退出 0，见 [构建日志](b4-isolated-weapp-build-2026-09-24.log)，仍有此前的 CSS 顺序、chunk 体积与 webpack 性能建议共 3 条警告。这些检查说明页面条件和开发层组合；微信 WXML/Canvas 实际合成、系统 Back/focus、姿态/触摸及手机性能仍归 P1/D，不能据此验收。

继续核页面触摸消费者，发现报告替换但原生画面尚未绘完时，`onSkyTouchStart` 可建立新手势，`onSkyTouchEnd` 可从旧 `paintedSkyObjectsRef` 拾取；原选择器只核时刻与目录，不核报告对象/观察者身份。对真实页面条件抽取的回归修前失败；现在手势开始与结束的拾取均需 `presentedSceneCurrent`。途中换报告或画布失败时不把旧画面对象选作当前对象，已有取消/跟踪恢复 owner 不变。画布容器的场景状态、星数、帧时刻及朗读文案同时区分已呈现、待绘与不可绘制，不能从新报告字段提前宣称旧像素已经更新。

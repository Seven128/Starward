## Current causal mismatch and the feasible next dependency

`sky-deep-auxiliary-visibility.ts` currently computes one scalar from FOV, viewport height, catalog major axis and a legacy painted-image Boolean. Scene computes it before drawing each catalog ring. The page independently computes it from final, live source credit after finish. These are different temporal observations: later layers and native retirement may change credit without changing the earlier Canvas decision. The task-only science envelope is deliberately excluded from both legacy Booleans, so unknown science readability currently retains its catalog aid. That staging behavior must remain explicit and does not fulfill the remaining natural fade/recovery obligation.

The next small production repair can freeze the **actual opacity already used by Scene**, publish it through the existing accepted Canvas completion and have DOM names consume it. It needs no new GPU getter, pre-aid MAX reduction, runtime budget, science default opt-in, changed curve or invented readability proxy. It closes duplicate presentation ownership and causal disagreement. Final receipt/source/status/modal behavior remains independently governed by the completed optical union.

Put the immutable records on `SkyPickSnapshot`, rather than `SkyScenePaintedSources`. The record describes a catalog drawing decision made with the snapshot's catalog identity, frame, actual view and logical viewport; it is not survey provenance. The smallest record is `{ reference, opacity }` for each deep-sky object that actually projects into that Scene. `sky-deep-auxiliary-visibility.ts` can own the record type and equality/lookup semantics beside the existing curve. Scene computes once, records before its disc call and uses that scalar. Page saves the captured records only through `paintAttempt -> done -> lifecycle accepted presented -> publish`; DOM retrieves the matching identity's recorded scalar instead of asking final source getters or recomputing the curve.

Page presentation equality must compare actual records as well as source identity. A changed FOV or viewport height can change opacity even when data/publication/native images are unchanged. A changed width can alter projected object membership; width alone is not an input to the current curve. Preserve exact scalar comparison and exact object identity; do not invent tolerances or force width into the curve. The separate accepted view/size continues to position labels, and existing successful landscape alpha continues to govern point occlusion. The Canvas `.01` and DOM `.08` consumer cutoffs can remain different; the decision scalar is shared. Catalog picking/list and the persistent selected-object marker retain their independent identity and interaction semantics.

Absent, failed, duplicate, rejected or old-generation completion cannot publish a new record. Hide, resize, remount and context loss must retire the old presented packet through the existing invalidation boundary. Within a live accepted frame, source retirement must not make a React getter restore only the DOM name while the Canvas ring remains faded. Replacement image/no-image state must drive an actual queued Canvas paint; restoration is published only after that replacement succeeds and is accepted. If replacement fails, retain the existing unavailable/recovery meaning; do not claim an aid repaint happened. A historical copied decision is a record of an actual draw, not permission to suppress indefinitely or a current image lease.

## Science black, partial, failure and late effects

| Later aid, terrain, HiPS or navigation attenuates source | Final provenance may change. It cannot retroactively authorize W3 or rewrite an opacity already submitted before that layer. Catalog point visibility remains subject to the actual successful landscape mask and committed camera. |

## Material uncertainty retained

The repair supplies a common **actual decision**, not a local readability certificate. The catalog already supplies major/minor axes and position angle, and science publication supplies exact TAN geometry, so a local region can be derived without inventing a mask. However, catalog extent is not a per-band segmentation, valid area is not displayed structure and nonzero local RGB can be noise or a companion. Existing references do not resolve a universal contrast, area or recognizability threshold. Any future observation must state its actual region, selected field support, temporal phase and uncertainty; it must not be named readability merely because a MAX sample is positive.

Do not first build a whole-buffer pre-aid getter and let its output implicitly select aid suppression. If a justified local rule later needs a GPU observation, it must flush queued prior stars/bodies/lines once before the first aid, bind the actual draw/signal revision, keep observation separate from final source receipt and measure the added reduction/readback cost.

# Selected W3 content identity: bounded read-only dependency audit

No production change, HTTP/source request, image decode/processing, new publication, runtime or device operation. This is a current owner audit for the existing PLAN, not a second plan. The earlier public-cache audit's selected-W3 gap still exists even though manifest-bound ordinary image consumers now use the shared cache.

## Actual responsibility gap

- `api-client.ts:1041` builds `/celestial-objects/{ref}/image?level=...&imageVersion=source-finite-v3`, with no publication/content hash. `spot-sky-page.tsx:1737` starts that request with only reference/level. Its report catalog is built by `deep-sky-scene-provider.ts` from OpenNGC, contains catalog identity/registration/coordinates, and supplies no imagery publication descriptor.
- `deep-sky-image-request.ts` accepts publication/source/pixel/field headers after response, optional PNG nonfinite count and byte-bound display support. It creates session files and supplies `release()`. It has no expected content SHA/length and cannot independently identify a same-size JPEG substitution. Header identity is not an asset descriptor discovery. Cancellation still uses legacy request/write ownership.
- `DeepSkyImageryService.manifest(hash)` already exposes level `sha256`, `bytes`, `pixels`, `fieldDegrees`, `imageFormat`, `sourceFiniteMask`, optional `displaySupport` and a hash-query download URL. It lacks a current-publication discovery endpoint. `get()` validates local asset bytes against the selected publication and supports approved archives; image bytes are read/hash-checked on each get, while metadata is cached. The old controller returns `public, max-age=86400`; query hash semantics alone do not enter the public runtime's immutable `/v2/sky/...` whitelist or static export.
- `useCelestialInformation`/object information can independently return `imagery:{publicationId}:{hash}`, and the source route links the fixed full manifest using it. These run for modal/source disclosure, not as a prerequisite of the page's imagery request. They cannot be assumed complete/current pre-download discovery. Actual painted W3 supplies its publication hash to modal/source disclosure; this remains separate from SDSS optical credit.
- `api-shapes.ts` says the image and fixed manifest responses are bare, but current generated SDK types wrap `CelestialObjectImageData` and `DeepSkyManifestData` in `ApiEnvelope`. The selected image uses Taro directly and the source page downloads a URL, so neither currently consumes those incorrect envelope types. New discovery/image operation contracts should explicitly use the existing `responseEnvelope:false` generator support and a typed W3 descriptor/manifest, rather than copying this mismatch or `Record<string,unknown>` into the new validated path.

## Minimum complete next responsibility chain

1. Extend the same publication owner with explicit current discovery for `source-finite-v3`, returning the chosen approved publication hash and typed manifest/entry descriptors before any image acquisition. Reuse its current/archived selection and validation; do not extract a content hash from imagery headers or a catalog reference. The current raw full manifest is 175,604 B, so a small current identity plus immutable-manifest retrieval, or a selected-entry discovery response from that owner, can avoid repeating all 153 descriptors. A subset response must retain the original publication identity; its own JSON is not falsely the publication-hash input.
2. Add a canonical immutable file route such as `/v2/sky/deep-sky/{publicationHash}/{file}`. Resolve only an admitted publication's exact level file to reference/level; preserve canonical path, bytes/MIME/size/hash and all W3 field/source/availability/display metadata. Reuse local `get`/asset admission, headers and sealed static enumeration; do not crawl disk or expose FITS/raw inputs. Keep the existing selected endpoint and no-version→legacy-v2 behavior, archived hash downloads and old source offers. Legacy headers/cache policy need not silently change. A new immutable route's header set must be frozen alongside its bytes.
3. Add a typed client W3 manifest/discovery validator and same-origin route consumer, then explicitly extend `acquirePublishedSkyImage`'s whitelist. Acquisition receives already-validated SHA/encoded bytes/format/dimensions and publication selection. It uses the existing singleton core, dedup/lease/readback/quota/clear fencing; no second cache or reference+level permanent key. Selected adapter still owns field/registration/nonfinite/display metadata; preserve page coarse-file fallback, cancellation/new Canvas and source credit. A clear-retired lease must stop pending decode and retire an already-ready selected file's eligible state, as ordinary acquisition does; the present selected decoder only checks page/Canvas generation.
4. Source/modal/route continue binding the actual successful painted file, including a retained coarse predecessor. Equal content may share encoded storage but does not share publication/source/field/scientific meaning by default. Current discovery failure must preserve independently valid catalog/weather and, where still eligible, explicit archived/coarse results; no failed discovery or invalid route should secretly switch to session acquisition.

Important immutable-header edge: `get()` currently permits archived PNGs with the same current content SHA/pixel size to inherit current byte-bound display support. Its archive manifest may omit that refinement. A new static route must bind a stable descriptor/header snapshot (or explicitly version that refinement) and keep this legacy behavior separate; otherwise a later same-byte display-support change can conflict with static history's exact route/header identity. Manifest and served metadata must agree, not merely image bytes.

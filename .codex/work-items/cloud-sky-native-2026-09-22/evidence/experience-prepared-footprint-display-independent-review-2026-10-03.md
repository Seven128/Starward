## Escaped R1 defect and bounded R2 fix

R1 replaced only `contribution=max(rgb)` with `max(rgb)*weight` while retaining `straight=rgb/contribution`. With SRC_ALPHA blending, the weighted denominator cancels gain where the straight channel remains unclamped; normalized output clipping then changes channel ratios. This differs from the CPU sheet's `rgb*weight` common gain. Actual R1 overview/detail were visibly gray/desaturated relative to that sheet.

An independent formula control on actual cached DETAIL texels exposes this distinction. At `(192,256)`, RGB `[212,192,184]`, luma gain `0.8628074`, the R1 normalized-output/alpha model gives `[184,185,187]` over the declared flat comparison background, versus intended `[184,168,163]`; the maximum floating difference is 24.16 byte units. At `(256,192)`, it is 31.63 byte units. These formula controls establish the defect, not an exact GPU ray/sample oracle.

Root repaired only the task transformation: `sourceContribution=max(rgb)` owns straight normalization; `contribution=sourceContribution*weight` owns final alpha. The exact parser bytes prove both declarations and straight denominator changed as intended, with no other module alteration. Four actual DETAIL texels now reproduce the common RGB-gain blend formula within `1e-15` normalized values. Saved R2 versus R1 changes 50,461 overview pixels and 286,498 detail pixels while wrong-family remains exactly unchanged.

# Pre-aid observation and object readability: independent design review

2026-10-02. Read-only review of the current consumer design, actual scene/renderer/receipt/page/lifecycle owners. No production edits, new GPU/HTTP execution, tests, image processing or downloads. This note records a remaining consumer dependency; it does not adopt an API or certify aid delivery.

The material gap is that whole-buffer source participation is not local object readability. Fine data may be available and valid black at the catalog core while a coarse exterior contributes positive RGB elsewhere. Both `HAS_SAMPLES` and a global fine/coarse photo-positive OR can then be true without establishing that the core aid is redundant. A fine positive sample elsewhere can likewise be noise or a companion. The existing `deepSkyAuxiliaryOpacity` Boolean and its angular 24–96 px fade have no local readability certificate. Global provenance, availability, a center brightness proxy or an invented confidence mask must not close this requirement. Keeping aids visible while this dependency is unresolved is staging, not fulfillment of natural fade/restoration.

An eventual `artworkLevelsObservedPhoto(draw)` could expose a current-frame, current-signal-revision observation distinct from completed provenance. It would not be `completed`, would not imply local readability, and RGBA8 zero would remain UNKNOWN. Before the first catalog aid, the renderer must assert availability, flush preceding buffered stars/bodies/lines, observe once, and assert availability again. Scene lines 381–402 are the correct boundary; current renderer lines 1083–1084 delegate getters without flushing. Querying after each aid introduces earlier aids into later decisions. Calling `finish`, navigation clear or texture retirement to obtain this observation would move later effects before the decision and is invalid.

Once the normal consumer has a justified aid policy, the scene must freeze one actual decision/opacity with its object, view, frame and native-generation eligibility. Canvas rings and DOM names consume that same record; their .01/.08 visibility thresholds can remain different. Publish the record only through accepted completion. Page lines 2734–2736 must not rederive earlier aid opacity from final photo/source Boolean or latest metadata. Later aids, terrain and navigation may change final participation without rewriting what was actually decided before the aid. Status/source/modal facts continue to use final, current provenance independently.

A query cache would require an actual signal revision, not only the group token. Capture/replay/clear/invalidation/begin/reset/resize/loss/dispose invalidate the relevant cache; unchanged signal can reuse a copied observation. One pre-aid observation shared by both consumers would normally add one full-buffer MAX reduction and one synchronous one-pixel readback per admitted group beyond capture qualification and finish provenance. No React getter or repeated snapshot should hide that cost. Disabled/foreign/unusable observations must retain no auxiliary work/UNKNOWN behavior; ordinary GL failure must remain ordinary failure.

Retirement/clear between observation and accepted completion needs native-current and accepted-frame fencing. After completion, invalidating a suppression decision must drive a real replacement Canvas paint; a DOM-only restoration while the old Canvas ring remains faded is not a common same-frame repair. A historical copied decision is neither permission to suppress indefinitely nor a current loader identity. Hide/new Canvas, resize, context loss and failed completion cannot revive an old suppression decision. Independent catalog facts and picking remain available.

Immediate ownership entries are `sky-deep-auxiliary-visibility.ts:5`, contribution `currentEntry`/`maximum`, renderer `flush` and the future observation wrapper, scene pre-aid boundary, page accepted painted callback (1412–1439) and DOM labels (2728–2742), and `sky-canvas-lifecycle` accepted-completion gate. Root's next dependency remains normal consumer readability/decision semantics before API expansion or normal science-group adoption. No new proxy is proposed by this review.

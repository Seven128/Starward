# Opt-in static delivery: deployment consumer integration

This is an authored consumer implementation receipt, not independent review or cloud deployment acceptance. The existing release, preview and promotion owners now consume the root-owned sealed-publication/static-store owner. No image pull/build, remote command, container convergence, current-service restart, IDE or device operation was performed for this receipt.

## Responsibility and compatibility

- `STARWARD_SKY_STATIC_DIRECTORY` is optional BASE configuration, an absolute persistent host directory. Unconfigured releases retain the API lane and original v1 receipt/request shapes. Reserved `STARWARD_SKY_*` identity claims are rejected rather than accepted as operator proof. Store roots and overlaps with control secrets, receipts or backups are rejected.
- Configured release prepares the image-bound store after the immutable pull and before migration/convergence. Preview prepares before stopping current writers. The store lease remains held through verification/receipt/pointer and is disposed in `finally`, including contract, compose and verification failures. Configured non-deploy preview operations load the already-bound delivery; absence does not silently select the API lane.
- The static compose overlay comes after the protected-preview overlay. The normal and protected Caddy sites import the generated fragment within their relevant boundary and retain a sibling API fallback. Default compose has one readonly empty fragment; the configured overlay replaces that target and adds the readonly public directory. Logs classify landscape and `sky_delivery` without retaining tokens, URLs or headers.
- Configured success receipts use v2 and record the validated seven-field actual identity plus completed verification result. A production configured release requires v2 staging qualification in both promotion and the direct release entry. It compares the current image's publication hash, permitting different delivery hashes/counts when each host retains a different approved history union. The strict promotion-request v1 fieldset is unchanged. Existing workflow archives already carry these tools/configurations and pass the staging receipt; no new request field/workflow patch is needed.

Independent review is requested separately against the frozen callers and actual outputs. The parent owns sealed-image extraction, approved-history merging/conflict rejection and real local verified-TLS Caddy/controller readback evidence. This receipt does not prove an executed remote release, current cloud/static adoption, server capacity/200 DAU, WeChat native filesystem or total-device memory, GPU quality, historical-image universal rollback, or final full experience acceptance. A pre-static image without its required store binding must still fail before service drain rather than claim supported rollback.

# 执行方案

目标是完整能力与真实运行验证。以下为依赖顺序，可随实际证据调整；不是缩减范围的分期承诺或工期上限。所有阶段都继续维护 INDEX、STATE、REQUIREMENTS 和 evidence。

## 0. 保护、恢复与当前事实核实

- 保存原始用户要求、后续指令、当前 facts/研究/设计/技能入口和初始差异；不改前轮研究/Context。
- 核对已存在的原生相机/星表/星座/影像/姿态/信息功能，沿实际 imports/调用关系确认计算、状态、身份、请求、发布及 GPU owner；历史文档只作为待核线索。
- 读取默认 Context 和相关 current owners；有大文件按章节读，不能把截断输出当成完整阅读。2026-09-23 用户已撤销云观星旧设计稿，不能再把它当视觉依据；其他独立适用的共享资源仍按各自 owner 阅读。编辑相关交互前读该责任的全部当前控制材料。
- 获取当前工具、数据发布、后端与设备事实。只做必要安全范围内的本地验证，不把外部部署当作默认授权。

## 1. 第一条真实链路及关键机制

先验证现有 BSC5P/SAO/独立深空资源的代表性实际链路：

真实版本化数据/天文计算 → 精确观察地点/时刻与恒星几何 → 现有 native WebGL 相机/投影 → 当前绘制快照、标签、点选 → 同一身份资料与来源 → 时间/缩放/前后台恢复。

- 用有已知关系的 Sirius/Vega/Polaris 及地平下负例检查实际发布、BFF 和当前帧，不只看目录总数/hash。追踪 SAO 分片身份、当前 epoch、亮度稳定、实际部署可访问性。
- 运行最相关现有确定性测试，检查测试能否检出缺失效果、错误身份、空数据或保留上一结果。已有失败先修复真实 owner；有逃逸问题才增加有意义回归。
- 使用 wechatide-skill 检查当前官方工具/会话并使用相关 compiler/debugger/automator scene；先读对应规范，复用已拥有会话，不盲目重开工具。真实数据成功链与 fixture 验证分开。
- 按已确认的功能/交互合同与实际 WEAPP 运行帧检查正常/暖红、天体资料、独立来源页、公共时间/Back、左下披露以及实际无遮挡圆盘；不再对照已失效的 Sky 图稿。校准和传感器的组合需要真机。
- 在首个可用设备上测量现有代表性数据规模的加载、帧耗时、内存、包体/流量；记录实际条件和未测范围。这只建立基础，不能宣布对齐完成。

## 2. 提前关闭后续扩展的实质不确定性

- 以已有研究为起点，核实新增深星表、光学巡天/银河、行星纹理、轨道的可用真实数据与合法使用/加工/分发条件。四类权益分开，不复做完整引擎选型/商业询价。
- 研究需要的新机制：全空域层级/坐标/配准、角尺寸与相位、动态轨道时效、适用大气/地景模型。优先成熟算法/标准/可用库，做小型 native trial 关闭格式、API、GPU、bundle、内存不确定性。
- 每个新数据源记录来源/许可原文入口、版本、字段、单位、frame/epoch、空间/时间覆盖、更新/过期、加工/分发、账号/访问和实际费用状态。尚未明确不能认定已采用/可上线。
- 数据或权限缺口单独保持开放，同时推进不依赖它的相机、搜索、计算和渲染工作。若需用户决定/外部授权，在具体方案可审阅后集中提出。

## 3. 扩展统一对象发现、定位和跟踪

- 先检查现有 catalog/detail/alias 状态、当前 frame、modal 和 sources route；重用稳定 HR/SAO/M/太阳系及适用新对象身份，不能另建竞争身份。
- 在自有或合法获权的索引中落实中文/别名检索；定义结果适用地点时刻、缺失/地平下状态和资料来源。不得靠 Stellarium 公共接口冒充自有已授权服务。
- 定位/跟踪通过同一浏览相机和时间 owner；跟随、手动、校准、目标切换/消失、时间变化和旧异步返回必须有明确转换/恢复。静态介绍不因逐帧姿态重新请求。
- 新增交互以用户确认的行为和仍有效的共享组件为基础；Sky 旧视觉已失效，若后续创建新设计资源，另按项目设计资源规则同步 owner。不能用新 UI 掩盖数据未落实。

## 4. 分层天空、太阳系和环境表现

- 在统一绘制/投影/拾取责任上扩展真实深星目录与色彩/光度语义，逐层生产、校验、发布和加载，保留 base fallback、稳定亮度与有界资源。
- 完成星座线/名称/淡图全链，保持精确 geometry、渐显、视口裁剪、身份及独立许可/归因。
- 扩展日月行星相位、角尺寸和适用纹理，计算来自同一天文/地点/时刻 owner，明确模型/数据有效范围、空间遮挡和图层顺序；不能用放大点替代需要的外观。
- 银河/大气/晨昏/地平线/地景共用观察几何，日照随时间变化，区分理论/历史/示意与现场事实；普通天空、夜间/红光、可访问性沿现有 owner。
- 每个新增渲染机制先用有真实输入的一个代表场景在目标 runtime 证明，再扩展对象/页面；保留 GPU/Canvas 代次与错误恢复。

## 5. 合法光学巡天候选与更多深空目标

- 对PS1/SkyMapper仅做有界权利、格式、覆盖和成本核查；只有明确允许当前商用获取/加工/自托管/分发且数据可实际生产，才接生产 optical survey。未核实前不发布其TRIAL、不承诺全天高清；已经发布的12片W3第0阶是用户可选的历史红外宽场，不把红外代替光学。
- 沿现有 publication、请求缓存、影像/纹理生命周期实现全空域分层/瓦片选择、配准、缓存、取消、粗细回退和来源/最大分辨率状态；不启动第二套图像管理。
- 必须用真实数据贯通生产格式与原生绘制、目标选择/资料以及跟踪/缩放/时间交互。下载生产耗时、算力与可部署包大小分别记录，不把 small fixture 当生产完成。
- 暖红模式中的图像亮度/抑制采用经过当前 owner 判断的规则；图像不宣称实时天气或肉眼视效。

## 6. 动态天体的商业版退出与恢复条件

- 商业版目前不接入人工卫星实时位置/轨迹/过境或彗星、小行星动态位置；现有OMM/SGP4是隔离技术试验，不启用生产报告/搜索/渲染/发布路径。
- 只有发现公开条款明确允许本产品实际获取、计算、展示及结果/数据分发，无需逐项申请商业许可的具体来源，再按用户范围决定重评。届时仍须分别落实身份、轨道时效、刷新/过期、观察者时刻、检索/定位/跟踪和目标运行时；当前goal不以这些能力作为完成阻塞。

## 7. 组合验证、审查、修复与收敛

- 依 REQUIREMENTS 的 V01–V08 及当前 owners，按机制选择代表样本。覆盖跨午夜、上下文切换、缩放往返、跟随/手动/校准/跟踪，以及加载/取消/弱网/过期/迟到/前后台/GPU 恢复。
- 实际 iOS/Android 微信执行视觉、点选、手势、姿态及性能；以当前功能/交互要求和适用共享资源检查实际帧，Sky 已失效旧稿不作比较，未测的设备/条件保持开放。
- 记录首屏/渐进加载、帧耗时、内存、包体与流量，明确设备和数据负载。遵守测量证据，不编造统一性能预算或拿名义 FPS 证明体验。
- 高影响共享复用/大交付进行独立审查，给出原始要求/参考/实际结果，修复发现再收集受影响证据。未得到审查不能称已经独立通过。
- 将耐久产品/架构/数据/选择变化放回当前 owner；过程、失败和费用实测留任务内。Context 更新后运行 npm run context:validate。
- 最后逐项对照完整原文和所有当前 owner 的要求，非 edited files 范围也要核对；已知失败/缺失必要证据不能用免责声明转为完成。

## Current implementation

- `workers/miniapp-api/src/astronomy-service.ts` remains the calculation owner. `computeDecision` returns an INTERNAL `AstronomyDecisionReport` (SkyReport without scene, frame/offline fields); map and overview consume this evidence. It never fills missing scene/frame fields with fake UNAVAILABLE/empty values. `compute` still returns the full existing public SkyReport shape and projects the real catalog only when requested. Public map sources no longer include an unused Gaia star-rendering source (1,398-byte reduction in the existing fixture); field/risk/decision truth is retained. Scene failure still affects full SkyReport and never fabricates positions or invalidates independent valid weather/targets.
- Public astronomy calculations are shared by spot geometry/elevation, timezone/night date, exact selected instant (including off-cadence milliseconds), and algorithm. Public decision identity additionally includes current spot payload, access/safety/evidence/route facts, exact night axis/profile/event, complete weather evidence/model/source/validity, rule/event/catalog identities and verification-expired boundary. Acquisition timestamps remain cache/freshness inputs but do not alone change semantic dataRevision. Full SkyReport dataRevision also binds actual scene state/catalog version/hash.
- Every request reads current publication-gated detail BEFORE using cached astronomy. Detail now joins current `spots.payload` instead of trusting an older spot copy in the overview read model; this replaces paired getSpot/getDetail reads. Repository authorization and private origin/location context are not cached as astronomy facts. A cached public calculation uses a synthetic public context; callers receive their own context ID/fingerprint/revision, and full representation-cache keys include caller identity. No private route origins or user identity enter shared public computations. Existing identity/favorite/account tests are retained.
- New `computation-cache.ts` is a small bounded process-local owner for in-flight coalescing, TTL/LRU, rejected-work cleanup and generation-based clearing. Fixed owner capacities/TTLs live in `ASTRONOMY_CACHE_POLICY`: weather128/decision64/calculations128/scene16/full-report16. Weather max60s, partial/alert-unavailable5s, clipped by every finite source/model validTo and active alert expiresAt; unavailable/expired weather is not retained. Pure geometry max30min. Scene failures are not retained. Capacity overflow performs unretained work instead of cancelling another caller. Consumers receive cloned report objects.
- `clearCaches()` invalidates pending astronomy preparation before it can repopulate nested caches, and is called on service reset/destroy. Exact facts/identities also invalidate computation on publication/status/data/catalog changes. `getSky` old 30-minute context-only external cache is gone. `getSpotOverview` hydrates current detail/route from the shared decision. Map representation lookup occurs only AFTER fresh candidate/population/favorite facts and shared weather/decision revision are checked; this deliberately costs additional reads for repeated identical maps but no longer skips publication/alert freshness checks.
- `provider-deadline.ts` owns transport deadlines and independent waiter cancellation. `weather-provider.ts` applies each lane deadline around fetch AND JSON body (including a transport/body that ignores AbortSignal). Existing attributable partial/UNAVAILABLE composition remains; each QWeather primary/alert/Open-Meteo lane can independently time out. Defaults: lane6000ms, shared overall weather6500ms, entire map weather wait budget7500ms across batches (client transport remains10000ms). Expired later-batch budgets return attributable unavailable evidence and stop launching new provider work. Shared work has its own bounded signal: cancelling or timing out one waiter does not abort peers. Timers and parent/caller listeners are cleaned. No real provider requests or quota use in tests.
- R4 viewport queries now call `listSpotsInRadius` directly, without first fetching all full spot payloads or intersecting their IDs. Public MapScene still promises complete population IDs/count/source and outside-viewport count, so the repository adds a narrow `listSpotPopulation` metadata read (spotId/source only). Both PG paths enforce PUBLIC_EXACT + PUBLISHED/TEMPORARILY_CLOSED + complete current-revision assessment + 30-day freshness; production fixture exclusion remains. No-viewport continues `listSpots`, filtering/ranking/search and coordinate conversion are unchanged. InMemory fixture getDetail now reflects its current spot list.

1. **P2 — production control archive metadata prevents same-revision retry.** At review time `.github/workflows/backend-production.yml:88` used plain `tar -czf`; staging `backend-staging.yml:157` already normalized sort/mtime/owner/group. `infrastructure/deployment/run-remote-promotion.sh:32-38` binds `control/<revision>` to the original archive SHA. A fresh checkout with identical file bytes but different mtimes produces a different production archive; once an earlier attempt has unpacked its control package, a subsequent attempt fails `remote_promotion_existing_control_mismatch`. The normalization fix keeps exact-content validation intact and does not authorize replacement of an existing mismatched control tree.

   `H4-R8-review-probes.mjs/json` copied the58 control-package source files (including the newly introduced launcher), changed only the copied package.json mtime, and invoked installed GNU tar. Plain archive hashes differed (`60661412…` → `564ebca6…`), while both normalized archives were `3762a9bd…`. Four archive artifacts and `H4-R8-control-fixture/` preserve the small local fixture. Initial Windows invocation could not find gzip; the successful probe prepended Git's usr/bin only to that child environment. This was a local probe environment fix, not a GitHub/Linux failure.

2. **P2 — the same production candidate path collides with a new attempt timestamp.** Immediately adjacent to the archive preparation, production creates a fresh `released_at` but uses a fixed `$REMOTE_CANDIDATE_ROOT/$REVISION/deploy.env`. `tools/deployment/prepare-release-candidate.mjs:40-48` correctly accepts reuse only when all bytes match, including `STARWARD_RELEASED_AT`. If the first attempt creates the candidate and a later promotion step fails, a rerun at the same revision still fails `release_candidate_output_exists` after fixing the tar issue. Root agreed to use the same run/attempt-qualified candidate path as staging (`$REVISION/$GITHUB_RUN_ID-$GITHUB_RUN_ATTEMPT/deploy.env`), preserving the existing immutable writer.

   `H4-R8-candidate-retry-probe.mjs/json` calls ONLY `prepareReleaseCandidate` with a task-local base containing `STARWARD_ENVIRONMENT=production`, a synthetic image digest and synthetic timestamps. First preparation succeeds; a changed timestamp at the same path fails and leaves original bytes intact; a distinct attempt path succeeds. This is not a full environment-validation or deployment test.

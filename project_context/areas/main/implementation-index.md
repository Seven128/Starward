## Runtime Entry Points

- `tools/miniapp/device-test.mjs` is the owner-assisted physical-phone diagnostic CLI; `device-adb.mjs` owns bounded official ADB commands, `device-session.mjs` owns external private state and local bundle freshness, and `device-runtime.mjs`/`device-remote-worker.mjs` own allowlisted official SDK observation with stage deadlines. `device-qr.mjs` translates only the official public terminal QR matrix to a private scannable PNG and filters progress events. - `tools/miniapp/device-feedback.mjs` is the adjacent `npm run miniapp:device:feedback` development-only entry. `device-feedback-command.mjs` owns its closed CLI grammar, `device-feedback-official.mjs` owns the public DevTools adapter, `device-feedback-snapshot.mjs` owns stable Taro-output copies and canonical configuration identity, `device-feedback-preview.mjs` owns the current-generation ordinary-preview QR, `device-feedback-binding.mjs` owns confirmed-generation revalidation, pre-confirmation session replacement and failed-bind recovery, and `device-feedback-session.mjs` owns external generation/run locks, official-update state, old-session invalidation and run-scoped cleanup; shared physical-path checks live in `device-feedback-paths.mjs`.
  These modules reuse the fixed-candidate fingerprint and ADB session owners without changing their fail-closed rules. The official adapter invokes only public `auto-preview` and `preview` through argument arrays, bounds/suppresses official output, keeps QR bytes inside the private run and stops at an explicit manual official-tool boundary when unavailable. Outputs identify only `development_feedback` and never promote phone observations into candidate acceptance.
- `tools/miniapp/device-feedback-fixture.mjs` and its content-only companion own only the disposable repository-external A/B project used to prove that development update path itself. They project the current public AppID into a marker- and lock-bound minimal no-network project, expose one visible A/B label and bounded button, are absent from every product build, and delete only the validated temporary root.
- `.codex/skills/starward-wechat-device-verification/SKILL.md` and `.codex/skills/starward-miniapp-release/SKILL.md` are separate thin project-local execution routers. They read the owning Context and invoke current project commands; they own no test meaning, deployment semantics, credentials or run receipts. `tools/miniapp/project-skills.test.mjs` checks their standard structure, UI prompt identity, separation and live repository references.

- WeChat Mini Program production starts at `apps/wechat-miniapp/project.config.json`, whose `miniprogramRoot` is the generated `dist/weapp/` candidate. `src/app.config.ts` owns the 14-route main/subpackage topology and exactly two primary destinations, Map and My; `src/pages/map/index.tsx` and `src/pages/my/index.tsx` are the main-package roots.
- `apps/wechat-miniapp/src/app.tsx` owns the Taro/React application root. `src/state/app-store.ts` owns persisted presentation/selection/filter/library state; `src/services/api-client.ts` is the abortable client port and the only Mini Program path to its BFF. `src/hooks/use-resource-query.ts` owns client-side request generation, stale-cache reuse, refetch and unmount/supersession protection without creating a second domain-state truth. - `tools/miniapp/verification-spec.json` is generated from the one Long-Task Source/Contract and indexes every declared observation, capability, Semantic Fact and selected-design Fact. The checked-in Source/spec still retain their frozen Harness `0.8.12` authority and are not rewritten by the `0.11.0` package/compatibility upgrade outside an active Long-Task; a later formal Mini Program run must first perform the protected Source/Authority revision, regenerate the spec and recollect the candidate carrier. - `apps/wechat-miniapp/config/index.ts` disables Taro persistent webpack caching for production `build` candidates so the main/subpackage module graph is recomputed; watch-mode caching remains available for development feedback. A successful compiler exit is insufficient if the resulting native runtime cannot resolve its emitted module graph.
- `tools/miniapp/run-wechat-devtools-session.mjs` cleanly rebuilds weapp with a dynamic BFF port and fingerprints the complete generated bundle. It accepts only a direct physical canonical root or a direct Harness snapshot under a validated external run root, separates Harness and DevTools child temp state, and observes exact watcher/process/IDE/automation/callback-port ownership. A new snapshot first completes a non-product project-registration session: unique reversible private identity, exact watcher binding, same-byte public-config refresh, SDK `3.17.1`, `App.exit`/`Tool.close`, and total teardown. Fresh setup/evidence sessions then prove canonical state, production Settings DAY control, journeys, degradation and runtime quiescence.
  Its explicit `platform-simulation` scope supplements those journeys with session-only fixed `getLocation` and compass mocks, exercises the production location and orientation controls, records the simulated boundary, and is never formal permission, map-tile, provider or physical-sensor evidence. After evidence shutdown, byte-different public-config formatting is restored only when canonical JSON is unchanged; exact public/private bytes are restored before candidate after-fingerprint. Candidate and bundle drift, semantic config mutation, aliases, unexpected runtime/runner errors or incomplete cleanup fail closed.
- `tools/miniapp/invoke-wechat-long-task-proof.ps1` creates and validates one `E:\Dev\.starward-tmp\run-<id>` invocation root, applies the pinned compatibility check, and runs `verify`, `diagnose-revision`, `final-gate` or formal `close` with physical snapshot temp state; `close` is included because the package reruns a fresh Live Final Gate before clearing the active binding. The wrapper detects leaked `ty-context-*` snapshots before cleanup and retries removal only for that exact resolved root. `tools/miniapp/apply-ty-context-harness-compatibility.mjs` is pinned to `project-tiny-context-harness@0.11.0` and changes only transient exact-root cleanup retries in the current workspace-snapshot and counterfactual-sandbox owners; unknown version/source shape fails, and acceptance semantics remain untouched.

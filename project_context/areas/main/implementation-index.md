## Runtime Entry Points

- `tools/run-node.cjs` is the shared development Node entry used by npm scripts. It checks the root engine contract, can recover through npm's verified Node executable, and passes that runtime to child commands without changing global PATH. Production image start/migration commands retain their image-owned runtime.
- `apps/wechat-miniapp/src/services/response-cache.ts` owns the BFF response memory/disk cache, lazy chunk hydration, representation validators and invalidation; it consumes the platform storage port rather than page state. `cache-policy.ts` and `request-lifecycle.ts` select temporary-data clearing without deleting preferences, plans, identity or active mutations.
- `apps/wechat-miniapp/src/features/sky/sky-canvas-lifecycle.ts` owns measured native Canvas lifetime, latest-frame scheduling and callback cleanup. `spot-sky-page.tsx` uses a WEAPP `type="2d"` canvas node, device-pixel-ratio backing store and its node-owned 2D context; this same-layer path is required for the adopted full-screen Sky composition because the legacy native canvas can cover ordinary Taro controls on Android. Canvas creation, drawing and downloaded-image decoding fail independently while the object list, time controls and sensor recovery remain usable. The existing page, exact-time frames and compass owner remain the sources of scene and pose truth.
- `workers/miniapp-api/src/astronomy-service.ts` owns reusable public astronomy/decision computation and current caller-envelope binding; `computation-cache.ts` supplies bounded in-process retention, and `provider-deadline.ts` bounds weather transport and shared waiters. The durable decision and freshness constraints remain in [Runtime And Domain](../../architecture/runtime-and-domain.md).
- `tools/miniapp/device-test.mjs` is the owner-assisted physical-phone diagnostic CLI; `device-adb.mjs` owns bounded official ADB commands, `device-session.mjs` owns external private state and local bundle freshness, and `device-runtime.mjs`/`device-remote-worker.mjs` own allowlisted official SDK observation with stage deadlines. `device-qr.mjs` translates only the official public terminal QR matrix to a private scannable PNG and filters progress events. The tools never rebuild, mock a phone location, read WeChat storage or set product acceptance to passed. Repeatable scope and command guidance live in `verification/wechat-device.md`.
- `tools/miniapp/device-feedback.mjs` is the adjacent `npm run miniapp:device:feedback` development-only entry. `device-feedback-command.mjs` owns its closed CLI grammar, `device-feedback-official.mjs` owns the public DevTools adapter, `device-feedback-snapshot.mjs` owns stable Taro-output copies and canonical configuration identity, `device-feedback-preview.mjs` owns the current-generation ordinary-preview QR, `device-feedback-binding.mjs` owns confirmed-generation revalidation, pre-confirmation session replacement and failed-bind recovery, and `device-feedback-session.mjs` owns external generation/run locks, official-update state, old-session invalidation and run-scoped cleanup; shared physical-path checks live in `device-feedback-paths.mjs`.
  These modules reuse the fixed-candidate fingerprint and ADB session owners without changing their fail-closed rules. The official adapter invokes only public `auto-preview` and `preview` through argument arrays, bounds/suppresses official output, keeps QR bytes inside the private run and stops at an explicit manual official-tool boundary when unavailable. Outputs identify only `development_feedback` and never promote phone observations into candidate acceptance.
- `tools/miniapp/device-feedback-fixture.mjs` and its content-only companion own only the disposable repository-external A/B project used to prove that development update path itself. They project the current public AppID into a marker- and lock-bound minimal no-network project, expose one visible A/B label and bounded button, are absent from every product build, and delete only the validated temporary root.
- `.codex/skills/starward-wechat-device-verification/SKILL.md` and `.codex/skills/starward-miniapp-release/SKILL.md` are separate thin project-local execution routers. They read the owning Context and invoke current project commands; they own no test meaning, deployment semantics, credentials or run receipts. `tools/miniapp/project-skills.test.mjs` checks their standard structure, UI prompt identity and live repository references; it does not certify routing behavior from prose matches.

- WeChat Mini Program production starts at `apps/wechat-miniapp/project.config.json`, whose `miniprogramRoot` is the generated `dist/weapp/` candidate. `src/app.config.ts` owns the current 18-route main/subpackage topology and exactly two primary destinations, Map and My; `src/pages/map/index.tsx` and `src/pages/my/index.tsx` are the main-package roots. The registered content routes are article detail, plan detail/list/edit, event list/detail, contribution records/editor, formal-spot feedback and Settings. Retired profile-link and import implementations are not registered routes.
- `apps/wechat-miniapp/src/components/native-back-boundary.tsx` owns the shared native WEAPP Back bridge for custom modal surfaces whose visible layout remains caller-owned. On the verified Android/WeChat runtime, its native `PageContainer` must be newly mounted while active with `show=true`; keeping an invisible instance mounted at `show=false` and later toggling it does not reliably establish a Back layer. A consumed Back unmounts the native boundary and rearms it on the next task only when the caller remains active. My nickname/avatar, Settings option sheets, Search filters, the shared observation-date calendar and Sky object information/overlap choice are current consumers; their cancel/save/draft semantics remain with those feature owners.
- `apps/wechat-miniapp/src/hooks/use-editor-leave-guard.ts` owns the native dirty-editor protection used by standalone Plan, contribution and formal-feedback editors; `components/custom-nav.tsx` owns programmatic Back dispatch. After a page-owned confirmation authorizes an explicit Back, the native guard is suspended before navigation so the same intent is not confirmed twice. It is restored only when every navigation path fails; Android system Back continues to use the native prompt directly. Feature owners retain dirty/busy decisions and confirmation copy.
- `apps/wechat-miniapp/src/app.tsx` owns the Taro/React application root and existing QueryClientProvider. `src/state/app-store.ts` owns persisted presentation/selection/filter/library state; `src/services/api-client.ts` is the abortable client port and the only Mini Program path to its BFF. `src/hooks/use-resource-query.ts` owns client-side request generation, stale-cache reuse, refetch and unmount/supersession protection without creating a second domain-state truth. Shared UI lives under `src/components/**`; tokens and theme behavior are projected through `src/styles/**`, `src/theme/**` and `app.scss`. `semantic-asset.tsx` remains the only icon/asset adapter. UI-library selection and rejected alternatives are owned by [Architecture](../../architecture.md#component-map), not by this navigation index; adopted resources and production migration remain separately recorded.
- `packages/miniapp-contracts/**` owns stable spot/filter/feature-gate/API/data-state identities. `workers/miniapp-api/src/main.ts` starts the Nest/Fastify modular-monolith BFF; its ports, adapters, repository, deterministic decision engine and explicit fixture/provider states are server-owned and cannot be bypassed by Mini Program pages. `workers/miniapp-api/src/weather-provider.ts` owns the current QWeather grid/official-alert plus Open-Meteo layered-cloud/model-evidence composition and its explicit primary-fallback semantics; `AstronomyService` consumes only that normalized result. Mini Program owner operations use authenticated `/v2/admin/**` APIs through `tools/miniapp/admin-operations.mjs`; the removed demo Web console is not an implementation or design authority.
- Mobile production starts at `apps/mobile/index.js`, which enters `expo-router/entry`. `apps/mobile/app/_layout.tsx` owns the persistent five-tab Expo Router navigator for `(tonight)`, `(map)`, `(trips)`, `(sky)`, and `(me)`; each group owns its nested routes.
- `apps/mobile/src/shell/RuntimeRoot.tsx` owns shared React Native providers and renders the Expo Router `Slot`. `apps/mobile/src/shell/WebApplication.tsx` is only a compatibility export of that root and does not own route or Screen identity.
- `apps/mobile/src/shell/MobileShellScreen.tsx` currently owns the onboarding/preferences screen and is exported by `apps/mobile/app/(me)/onboarding-preferences.tsx`; it does not render or switch the five primary destination roots.
- API production entry starts at apps/api/src/start.ts. The current owner-only composition intentionally enables the Open-Meteo noncommercial POC and selected local adapters, while route, durable domain repositories, identity and several worker/provider boundaries still require production-path wiring or honest unavailable states.
- Owner operations entry starts at apps/admin-web/src/main.tsx. A runnable operations surface exists, but its protected endpoint, authentication, authorization and real mutation/readback boundaries remain implementation obligations.

## Verification Implementation Navigation

- `tools/miniapp/run-wechat-devtools-session.mjs` and the real WEAPP routes own tool-side runtime collection; successful schema-v3 output is `collected` while product conformance remains unverified. `tools/miniapp/conformance-review.mjs` is an optional notes helper for scoped reviews with or without a session. It reports file changes and recorded-source differences separately from the reviewer's conclusions, never product acceptance. Acceptance and current-candidate freshness remain with [candidate acceptance](../../development-workflow/candidate-acceptance.md). Adopted resources are implementation inputs through Screen Contracts; browser previews are references, and historical unadopted prototypes are not authority.
- `tools/miniapp/verify-miniapp-target.exe` and its older generated specs are historical carriers of the removed H5 mechanism. They are not current verification commands. Current Mini Program checks use the standalone WEAPP collector and the current project scripts; old compiler/protected-revision recovery is retired.
- `tools/miniapp/verification-spec.json` retains historical direct observation data used by project regression tests. The I21 spec and `tools/miniapp/verifier-runtime/**` are separate retained diagnostics. Neither historical spec nor candidate preparation proves current acceptance. `artifacts/miniapp/**` is disposable observation output, never durable Context.
- `apps/wechat-miniapp/config/index.ts` disables Taro persistent webpack caching for production `build` candidates so the main/subpackage module graph is recomputed; watch-mode caching remains available for development feedback. A successful compiler exit is insufficient if the resulting native runtime cannot resolve its emitted module graph.
- `tools/miniapp/run-wechat-devtools-session.mjs` cleanly rebuilds weapp with a dynamic BFF port and fingerprints the complete generated bundle. `verifyWechatWorkspaceLocation` admits only the direct physical canonical root; `verifyWechatProcessEnvironment` validates physical child temp outside the candidate and reserved run roots before run setup. Copied Harness roots and their preliminary registration phase are no longer admitted. Fresh setup/evidence sessions retain reversible private identity, exact watcher binding, same-byte public-config refresh, SDK `3.17.1`, canonical state reset, journeys, degradation, runtime quiescence and complete teardown. Runtime semantics remain in [candidate acceptance](../../development-workflow/candidate-acceptance.md).
  Its explicit `platform-simulation` scope supplements those journeys with session-only fixed `getLocation` and compass mocks, exercises the production location and orientation controls, records the simulated boundary, and is never formal permission, map-tile, provider or physical-sensor evidence. After evidence shutdown, byte-different public-config formatting is restored only when canonical JSON is unchanged; exact public/private bytes are restored before candidate after-fingerprint. Candidate and bundle drift, semantic config mutation, aliases, unexpected runtime/runner errors or incomplete cleanup fail closed.
- `tools/miniapp/docker-compose-runtime.mjs` is the shared infrastructure command owner used by `run-infrastructure-check.mjs` and `backup-restore.mjs`. It selects standalone Compose v2 on Windows and the standard Docker Compose subcommand elsewhere, preserving identical service/backup semantics while remaining executable under the minimal environment. Workflow conformance tests pin that selection, and the infrastructure lane must not depend on an interactive shell; project tests retain the minimal-environment regression.
- `tools/miniapp/start-development-session.mjs` owns the warm interactive inner loop exposed by `npm run dev:miniapp`: pinned PostGIS/Redis development services, one development API port, API/Outbox-worker/watch-compiler process trees, readiness checks and optional opening of the canonical project in WeChat DevTools. UI work reads the owning Screen Contract and current DESIGN rules, observes the real WEAPP route in the warm DevTools window and fixes tracked source. Its explicit `--memory` fallback is non-evidence and the warm session cannot supply evidence to the clean native collector.
- `tests/acceptance/start-mobile-web.mjs` and `tests/acceptance/mobile-web-session.mjs` own the bounded React Native Web/API development-session implementation; formal and warm entry points are routed from the verification Context.
- `tools/long-task/verify-native-target.mjs` is the Android Check executor/aggregator; `tools/long-task/native-verification-session.mjs` owns population, shard, checkpoint and fragment-session mechanics.
- The current Expo Router root does not eagerly import every product Screen through `apps/mobile/src/shell/WebApplication.tsx`. Contract evidence inputs must follow the owning Claim, reachable carrier, and real shared dependencies; APK fingerprint inputs follow the complete production bundle/native inputs. Neither a historical app-wide Stage scope nor runtime lazy rendering is by itself authority to broaden or narrow those sets.
- The Android Release artifact fingerprint excludes `*.test.*`, `*.spec.*`, `__tests__`, generated outputs and other evidence-only files while retaining production Metro inputs, Expo config/plugins, dependency locks, patches, shared packages and toolchain identity. The locally ignored `apps/mobile/android/` CNG output is regenerated inside each formal snapshot and is not a stable authority input; native behavior must originate in the tracked CNG/config/plugin/module sources that generate it. Test-only edits and snapshot-specific native generation must not invalidate a content-identical APK cache entry.
- Before Gradle, the native Gate requires the declared API loopback and runs the mobile TypeScript graph against the real root, so missing imported Screen carriers and type failures stop before packaging. The expensive runner emits explicit preflight and Gradle progress on a non-evidence channel.
- Route/action readiness still becomes observable during the native scenario, and interruption of the parent command does not yet guarantee termination of its complete Windows child process tree. Deterministic route/action contract preflight and complete owned-process cancellation remain required before unattended repeated native Gates can be treated as reliable.
- The mobile Web development lane couples its same-origin session descriptor and OS-temporary registry lifecycle to the foreground owner. An abrupt process-tree failure may leave disposable files, but PID, origin and fingerprint validation prevents their reuse as a live session.
- Filtered native diagnostics distinguish execution failure from observed product/design nonconformance: attributable page, Control-state and acceptance-scenario gaps are retained with screenshots and may be resumed for the identical repair candidate, while infrastructure, identity and population failures still stop the run. This diagnostic completion is never a positive Assertion or formal conformance result.
- Native design collection cold-starts once per selected Condition/Mode unit and proves that unit's production-root journey before sharing the live process. A session-identity-gated context switch then resets and retargets each Control/Scenario observation on the already-proved production surface; switching attribution cannot activate outside that launch session and cannot replace an independently reported interaction/result.
- The design-evidence transport exposes exact session-bound context and forced-state readiness markers solely to delimit React Native commits. After the verifier observes the matching marker and production owner Control in one UI tree, the corresponding state or Scenario carrier must already be present in that same owner tree; absence is an attributable product/design conformance failure, not a reason to sweep the page or retry until a generic timeout. A marker alone remains non-proof and cannot satisfy state, interaction, semantic or visual Assertions.
- These statements describe implementation boundaries and remaining drift. They are not evidence that current candidate checks passed or delivery was accepted.

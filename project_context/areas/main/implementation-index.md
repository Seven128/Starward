## Runtime Entry Points

- WeChat Mini Program production starts at `apps/wechat-miniapp/project.config.json`, whose `miniprogramRoot` is the generated `dist/weapp/` candidate. `src/app.config.ts` owns the 19-route main/subpackage topology and exactly two primary destinations, Map and My; `src/pages/map/index.tsx` and `src/pages/my/index.tsx` are the main-package roots.
- `apps/wechat-miniapp/src/app.tsx` owns the Taro/React application root. `src/state/app-store.ts` owns persisted presentation/selection/filter/library state; `src/services/api-client.ts` is the abortable client port and the only Mini Program path to its BFF. `src/hooks/use-resource-query.ts` owns client-side request generation, stale-cache reuse, refetch and unmount/supersession protection without creating a second domain-state truth. Shared surface/state components live under `src/components/**`; exact Mini Program tokens and mode rules are projected in `src/styles/**` from the adopted DESIGN target.
- `packages/miniapp-contracts/**` owns stable spot/filter/feature-gate/API/data-state identities. `workers/miniapp-api/src/main.ts` starts the Nest/Fastify modular-monolith BFF; its ports, adapters, repository, deterministic decision engine and explicit fixture/provider states are server-owned and cannot be bypassed by Mini Program pages.
- Mobile production starts at `apps/mobile/index.js`, which enters `expo-router/entry`. `apps/mobile/app/_layout.tsx` owns the persistent five-tab Expo Router navigator for `(tonight)`, `(map)`, `(trips)`, `(sky)`, and `(me)`; each group owns its nested routes.
- `apps/mobile/src/shell/RuntimeRoot.tsx` owns shared React Native providers and renders the Expo Router `Slot`. `apps/mobile/src/shell/WebApplication.tsx` is only a compatibility export of that root and does not own route or Screen identity.
- `apps/mobile/src/shell/MobileShellScreen.tsx` currently owns the onboarding/preferences screen and is exported by `apps/mobile/app/(me)/onboarding-preferences.tsx`; it does not render or switch the five primary destination roots.
- API production entry starts at apps/api/src/start.ts. The current owner-only composition intentionally enables the Open-Meteo noncommercial POC and selected local adapters, while route, durable domain repositories, identity and several worker/provider boundaries still require production-path wiring or honest unavailable states.
- Owner operations entry starts at apps/admin-web/src/main.tsx. A runnable operations surface exists, but its protected endpoint, authentication, authorization and real mutation/readback boundaries remain implementation obligations.

## Verification Implementation Navigation

- `tests/acceptance/miniapp/playwright.config.mjs`, `design-conformance.spec.mjs` and `ui-proxy.spec.mjs` own the production-derived same-source H5 diagnostic lane at 320/375/430 CSS px, including exact mode roles, selected-resource hierarchy, reduced motion, interaction, accessibility and gated fallback journeys. `tools/miniapp/start-h5-acceptance.mjs` cleanly builds and serves that candidate on dynamic loopback ports through the pinned acceptance-workspace Playwright. This browser lane cannot prove native map, permission, lifecycle, package or sensor behavior.
- `tools/miniapp/verify-miniapp-target.exe` launches the independently frozen `verify-miniapp-target.mjs`. Its collection mode, exposed as `npm run prepare:miniapp:final-candidate`, runs only after the verifier/spec/runner and active Authority are frozen and binds type/unit/contract checks, fresh weapp/H5 builds, browser journeys, authority hashes, static owner/boundary checks, WeChat DevTools cold-start evidence and a complete current-source fingerprint into `apps/wechat-miniapp/src/authority/delivery-carrier.json`; ordinary verification mode never refreshes that counterfactual carrier, emits typed per-Assertion evidence, and fails stale before expensive product execution when the carrier or its bound snapshot changes. A failed degradation assertion omits its unavailable `failure_injection` record instead of emitting a schema-invalid false record. Population inspection derives the exact 26 `spot_id` values only when the current catalog retains the complete static `SEEDS` block, the `toSpot` `spot:${seed.id}` projection and `DEMO_SPOTS = SEEDS.map(toSpot)` binding; missing, duplicate or structurally detached seeds fail closed.
- `tools/miniapp/verification-spec.json` is generated from the one Long-Task Source/Contract and indexes every declared observation, capability, Semantic Fact and selected-design Fact. `artifacts/miniapp/**` contains disposable proof artifacts only and never becomes Context or product authority.
- `apps/wechat-miniapp/config/index.ts` disables Taro persistent webpack caching for production `build` candidates so the main/subpackage module graph is recomputed; watch-mode caching remains available for development feedback. A successful compiler exit is insufficient if the resulting native runtime cannot resolve its emitted module graph.
- `tools/miniapp/run-wechat-devtools-session.mjs` cleanly rebuilds weapp with a dynamic BFF port, fingerprints the complete generated bundle, and opens the exact current-candidate Mini Program project through isolated setup/evidence stages on the installed automator's standard port `9420`. It reversibly overlays the ignored private config with a root-and-candidate-unique project name plus pinned SDK `3.17.1`, requires exact private-config readback, `Tool.getInfo` SDK identity and a sole `wxfilewatcher_x64.exe` bound to the requested project path, then restores the exact prior private bytes or absence after teardown. It preserves the Windows CLI installation-directory bootstrap contract, explicitly awaits log activation, performs canonical resets only on the network-neutral auth route, proves the production Settings DAY control in setup, re-establishes the exact DAY/MY evidence seed in the fresh evidence stage, and opens degradation faults only after that healthy reset. Each observation window must quiesce before listeners detach; process/port teardown and private-config restoration are proven separately. The runner captures declared native journeys and screenshots, rejects unexpected runtime/runner errors, project aliasing, candidate drift or generated-bundle drift, and records final evidence only after teardown succeeds. Unexpected promise rejections are hash-recorded, force failure and still reach teardown. `tools/miniapp/generate-mode-icons.mjs --check` independently regenerates expected mode pixels in memory and fails on binary or manifest drift.
- `tools/miniapp/start-development-session.mjs` owns the warm interactive inner loop exposed by `npm run dev:miniapp`: pinned PostGIS/Redis development services, one development API port, API/Outbox-worker/watch-compiler process trees, readiness checks and optional opening of the canonical project in WeChat DevTools. Its explicit `--memory` fallback is non-evidence. The warm session is intentionally separate from and cannot supply evidence to the clean H5/native acceptance collectors.

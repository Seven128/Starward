# 地点信息页：紧凑且清晰的设计逻辑

适用：微信小程序地点面板、场地资料、天文事实及类似详情页；其他页面复用方法，保持各自职责。目标是小巧、精致、高级感、密而不挤。此处定义内容组织与判断方法；精确字号、间距、颜色、触控和动效值由根 DESIGN.md 的小程序 profile 单独拥有，不复制第二套 tokens。

## 先决定内容，再决定容器

每个模块先回答：用户在此要确认什么、哪个事实影响下一步、哪些事实需要一起比较、哪些是说明或追溯。没有独立用户问题的标题、重复状态和内部解释应删除。有效信息密度是单位注意力内可理解的有效事实，不是字符数或组件数；不能用缩字、隐藏风险或塞满首屏提高密度。

- 小巧：去掉重复标题、过大容器与无效空行；短事实并排，点击区仍满足 DESIGN。
- 精致：同类信息对齐、单位和状态表达统一，标题紧邻内容；长短、缺失、加载等真实状态都有稳定安排。
- 高级感：有限强调、稳定节奏、克制表面与颜色、清晰主次；不是深色、更多阴影、装饰和大量留白的别名。
- 密而不挤：组内紧、组间松，主要事实易扫读，解释可阅读，动作可命中；留白表达关系而不是均匀撒开。

## 信息顺序与注意力

地点身份（名称、区域及必要真实状态）先建立对象；路线、开放、安全、设施帮助理解场地；天文区呈现当前所选时间的客观证据；长攻略、完整场地资料和来源按需深入。严重风险不能藏到详情里。面板不生成出行推荐，星图仅属云观星，具体顺序以 spot-and-sky.md 为准。

身份下的概览/天文是轻量文字吸顶定位入口，同一滚动文档；不做等分填色切换面板。正文与固定动作各自有位置，固定栏不能遮住末行。导航、详情等动作靠近所作用对象，同一动作不重复占几个区域。首要信息可先呈现，不被低优先级请求阻塞；加载占位应接近真实内容几何，避免位置跳动。

## 按信息形态选择表现

| 内容与条件 | 首选表达 | 不适用时怎么变 |
| --- | --- | --- |
| 一条短事实与一个动作，如距离/路线 | 同一行的摘要 + 尾部入口 | 长摘要自然换行；不能挤窄入口或截断关键单位 |
| 两三个关联短指标 | 共享容器内并列指标，标签与值对应 | 依据可用宽度、最长标签/值减少列数，不按数量强塞三列 |
| 同维度可比较的数据，如分层云量 | 共享列/紧凑矩阵，统一标签、单位和对齐 | 多时段使用明确时间表头；不把每个数字做独立卡片 |
| 少量设施及短状态 | 两列轻分组或紧凑状态集合 | 长说明跨列完整展开；不要只因有说明就丢弃其余事实 |
| 短类别/筛选/有意义状态 | 有限 tag，贴近对象；可点与不可点外观有区别 | 长句回归正文；同一事实不重复成 badge 和正文 |
| 独立对象，含图片、名称、摘要或动作，如攻略 | 图文卡片或列表单元 | 无合法图片不留空图；只有一个标量不成立为独立对象卡 |
| 开放限制、道路风险、条件与原因 | 可读正文/简短列表，明确严重性 | 不强压为标签、不以省略号隐藏危险或授权条件 |
| 完整来源、长攻略、详细设施说明 | 摘要 + 单一明确深入入口 | 重要风险、当前值缺失/过期造成的影响仍留在当前层 |

变化来自内容职责；同一类数据保持相同语法，不能为了“丰富”随机交替圆角、底色、图标或字级。通常先用对齐和间距分组，只有确实需要边界才增加轻底色/分隔线，避免每组同时叠加底色、边框、阴影。

## 数据与尺寸适应

- 布局同时考虑内容类型、长度、数量、可用宽度和比较关系；不是“少=卡片、多=列表”的固定开关。单个残项不为填满行被放大，不补假数据。
- 关键缺失值明确写暂无数据，0 是有效值；缺失很多时可以合并说明共同缺失原因，但不能把必须区分的状态混为一谈。可选空模块不造空卡，错误提供对应恢复入口。
- 长地点名、长值、真实说明优先自然换行；可读字号不变，容器增高或减少列数。禁止固定高度截断关键内容、把正文全部当44px点击行，或为非交互数字保留大块空白。
- 主题只改变对应语义角色，不改变信息等级；风险与选中不能只靠色彩。所有样式沿用生产 token 和图标 owner。

## 每次相关UI修改主动检查

不要求新增设计稿或文档。直接对当前WEAPP检查：首屏能否辨认地点、关键状态和下一步；每个模块是否回答不同问题；短值是否浪费整行、同类数据能否横向比较；相邻组是否区分而组内关联明显；主要动作是否突出但不抢内容；长名/长说明/无图/全缺失/0值/旧值/风险是否仍诚实可读；320/375/390/430标准字是否换列/换行合理；吸顶和底栏是否遮挡、点击区是否重叠。源码/构建检查不能替代视觉与真实交互核验。发现同类问题时检查共享组件及相关页，不等用户逐项指出。

## 依据与适用边界

- 用户提供的高德地点/商户截图：直接观察到身份与短属性成组、路线与行动邻近、横向类别导航、不同对象用不同布局。这只是这些截图的观察，不宣称掌握高德/美团/点评全端最新内部规范。营销榜单、折扣、推荐商家不属于本产品需复制的内容。
- [大众点评M站重构，美团技术团队，2026-03-13](https://tech.meituan.com/2026/03/13/Qwik-practice-in-dianping.html)：官方说明地点基础信息最高加载优先级、次要模块渐进加载；支持内容优先级判断，不证明全部App视觉规则。
- [Google Places紧凑地点组件](https://developers.google.cn/maps/documentation/javascript/places-ui-kit/advanced-place-details)：提供横/纵紧凑布局、内容选择及自适应高度思路；是公开组件，不等同Google Maps消费App，也不引入其技术栈/截断策略/尺寸值。
- [NN/g：视觉层级](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)、[共同区域](https://www.nngroup.com/articles/common-region/)、[渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)：支持有限强调、邻近分组与次要信息深入读取。

以上设计选择是结合公开依据、用户参考和Starward职责得到的项目方法，不是竞品官方结论或已经通过用户测试的效果保证。后续仅在持久决策改变时更新本owner，不积累竞品截图库、原型或逐页同步报告。

# WeChat Mini Program Map And Search Invariants

This on-demand subdomain node normatively continues `Cross-Control And State Invariants` for Map, dedicated Search, the spot information panel and shared Observation Context behavior.

The adopted daytime layer composition is reached through the sole [Map resource entry](../../../../../docs/design-resources/wechat-miniapp/map/ADOPTED.md). Read its layer-selector package together with the [shared observation-time owner](shared-state-and-recovery.md#shared-observation-time-resource) and its resource before implementing this control.

- `spot-contribution-entry` and `my-contribution-entry` converge on one contribution owner. The information panel passes only its formal `spot_id` and display label; Map opens new-place intake; My opens the account’s creation and feedback records, including private drafts. Approval means accepted for canonical owner processing, not that the report itself became a published fact; only an audited operations merge followed by a fresh complete publication assessment can change formal output.
- `map-search-entry` is one fixed floating Search field on the Map. It contains no embedded filters, result list, filter summary grid, content Sheet or additional product launcher. A valid tap/keyboard/accessibility activation pushes `spot/search`, preserving the physical Map instance, camera, committed filters, selected time and analysis layer behind the child route. The entry is visible while the information panel is hidden, small or medium; it is absent at large. During large-to-smaller direct manipulation, Search and the other Map controls return in their near-top phase before media retracts; their hit/semantic state follows the same live transition without covering readable media. Search never overlaps readable media or appears as a disabled large-state duplicate. Map and Search states contain no trailing clear/close glyph.
- `spot-search-shell` owns the dedicated child page and a keyboard-safe vertical content owner. `spot-search-field` is the same visual rectangle and rendered text as `map-search-entry`: route activation preserves its size, position, fill, border, radius, query-or-placeholder string, typography and input origin as a stationary transition anchor while the remaining Search content reveals below it. Only the leading slot crossfades from Search to a named Back glyph. That glyph, WeChat/system Back and the platform edge-back gesture all reverse the same child reveal and return to Map; cancellation restores the live Search state, and commit alone pops the route. The field receives entry autofocus and owns query/submit semantics without a trailing `x` action. A valid outside tap may blur the field, dismiss its IME and close `spot-search-query-overlay` without leaving Search or trapping focus; the field can be focused again. The compact overlay anchors directly below the field with body-level rows and quiet dividers; it does not introduce card-sized rows or move the filters. Pointer/keyboard suggestion choice commits before blur cleanup.
- `spot-search-filter-group` exposes the 14 current terminal filters in one compact horizontal scrolling line immediately below the field, with a fixed named filter trigger at its trailing edge. It is one filter family and one committed Map/Search store. Every strip `spot-search-filter-choice` commits immediately; retired driving-range and low-cloud parameters have no editor. Horizontal drag scrolls without selecting on release and does not steal vertical result scroll or platform Back; every terminal value remains keyboard/assistive reachable. Prefix icon and label keep normal flow; selected fill, boundary, small ornament and programmatic checked state communicate selection without changing geometry. The adopted resource owns the daytime composition; no “筛选条件” heading or extra explanatory band is added.
- The filter trigger opens one modal sheet with exactly two classification levels: a category and its terminal choices. The five categories are `观测条件`, `到达方式`, `设施配套`, `场地偏好`, and `资料更新`; the 14 current values and their meaning are owned by the Filter semantics section below; the adopted Search visual structure supplies grouping/layout, not business predicates. Retired recommendation, driving-range and low-cloud controls are absent. Opening copies the committed selection into a sheet-local draft. Choice taps and `清空选择` edit only that draft; `确定` replaces the single committed selection and updates the strip/results. Close, backdrop, Escape or system Back cancels the draft, then restores trigger focus and the preserved query, committed filters, partition and scroll state. Back closes this sheet before attempting the Search route transition. Category switching only changes which terminal choices are visible, retains all draft selections and introduces no third level. The modal traps its own focus/interaction while open; it is separate from Map's bottom-presentation coordinator and cannot become a second persistent filter store.
- `spot-search-result-list` has exactly two first-level partitions: `想去` contains favorited matching formal spots and `其他观星点` contains the remainder. Each compact body-level partition header remains a full 44px operable row, exposes expanded state and count, and uses a stable chevron. Expand/collapse preserves one retained item tree and animates the current measured block geometry plus opacity; it never remounts results, toggles the outgoing tree before measurement, changes card width, resets scroll or flashes a replacement surface. Rapid reversal retargets from the live block. City names are group headings or sticky labels inside the partition, not another disclosure layer. The page restores useful query/filter/partition/scroll state when returning from Map and hides scrollbar chrome without clipping touch/wheel/keyboard reachability. Empty/no-results, stale-summary, partial and dynamic-provider failure states preserve static formal-spot/favorite identity and expose safe recovery.
- `spot-search-result-card` uses the full available result column width. When licensed site media exists it becomes the card background, with no card border or shadow in the adopted daytime composition. Its leading readability treatment follows the adopted resource, preserves legible names/metadata and retains a faint view of the image; it is not an opaque slab, glass or blur and does not imply media rights or freshness. The address icon aligns with the first text line, including wrapped addresses. When no valid image exists the same content geometry uses the normal quiet surface without a placeholder or reserved media gap. The entire card is the one selection action; there is no separate trailing “选择” label/button. Press-in is visible, and only a valid press-out/keyboard/accessibility activation commits the formal spot, pops Search, recenters the existing map on that spot and opens `map-spot-information-panel` at `medium`. This is a selection intent even when the spot ID matches the previously selected spot: it must restore medium from a small, hidden or layer presentation and recenter the same map rather than returning early on ID equality. Drag-away, scroll competition, cancellation, disablement or invalid release does not commit. The adopted browser resource demonstrates press appearance only; real selection, camera and panel behavior require production implementation and verification.
- `map-marker-panel-coordinator` owns one selected typed location; public Search returns formal spots, while the owner’s private markers use the location identity contract below. The accessibility list preserves that distinction. A first valid marker activation selects the spot and opens the same panel at `medium`; a second activation is not required. A valid tap on physical map space that is not a formal marker clears the visible spot selection and transitions the panel from its live position down to `hidden`; its hit and semantic surface remain until the exit completes so the state never vanishes abruptly. A pan/pinch beginning outside the panel remains map-owned; automatic camera movement never fights user pan. The Search result list and semantic map list provide non-gesture point-selection alternatives.
- `map-spot-information-panel` is map-parallel, non-modal and has `visibility = hidden | visible` plus `extent = small | medium | large`; hidden is not another extent. All three extents retain one ordered document tree and one mapping from formal facts to rows. Extent changes only the viewport crop; `medium` and `large` enable the document's one vertical scroll. Per-extent conditional content trees, remounts, reordered facts and duplicated mappings are forbidden. The panel retargets from the live presentation position and queues nothing. At medium/large, only `map-spot-panel-handle`'s full-width compact white identity-header band owns vertical extent manipulation; the centered dash is a visual hint, not the hit-region boundary. The band and name belong to the retained document and scroll out together, never fixed/sticky to the panel viewport. The name may visually overlap the lower part of the band without adding a tall blank spacer; actions never overlap its hit region. Once that actual band has scrolled away, visible top chrome/content cannot initiate extent drag. System/platform Back (and the supported edge-back equivalent) resolves large to medium; scrolling back to the band restores its direct manipulation. At medium/large, other content/media never starts extent dragging. At small, upward document drag expands to medium; downward drag is clamped to small without motion or dismissal. Fixed actions remain independent. Pointer down alone shows feedback but does not change extent, and a release below the drag threshold is a no-op. A left-edge rightward Back gesture resolves to `large → medium`; handle keyboard/assistive increment/decrement is the non-gesture alternative.
- The sole presentation exception is valid licensed media. It occupies no region at small or medium, then pulls out continuously at the document top during medium-to-large progress. The image reaches its full region before `map-search-entry`, `map-location-control` and the layer trigger begin their near-screen-top fade; reverse motion restores those controls before retracting media. Missing, invalid or unavailable media removes the media node entirely. A compact white identity-header band remains below any visible site media; when media is absent it is the document's first region. It follows the document during large-state scrolling and never becomes a persistent overlay. Site media supports one wide image or a horizontally draggable multi-image strip with a next-image cue and truthful count. Direction-lock separates horizontal strip drag from vertical document scroll and panel/edge-back gestures; a drag suppresses image-opening taps, while an intentional tap opens the selected image in the shared viewer; no-media has neither gallery nor placeholder. Ordinary unknown/unprovided values share the visible copy `暂无数据`, while permission, loading, stale, error, not-applicable and safety states remain distinct model states with their real recovery/effect.
- `map-spot-panel-section-nav` follows the sole current [Spot and sky](spot-and-sky.md) contract: one-level horizontal section navigation in the same continuous document. It is absent at the basic-information start, appears when the astronomy boundary reaches the reading top and then stays sticky; returning to the basic-information start hides it. One rounded gradient indicator slides between sections without remounting content or changing document geometry. It reserves no right-side column.
- `map-spot-panel-action-bar` is a separate bottom safe-area action region containing, for a formal spot, exactly three icon-labelled actions in left-to-right order: `想去`, `云观星`, `分享`. Its adopted three-extent composition is three separate compact buttons as specified in DESIGN.md §5A.0 and the sole Map resource entry. It remains operable at all visible extents without being duplicated in the document. Favorite success is expressed by `spot-favorite-action` alone. Share is an explicit user action over the formal spot's allowed public summary and excludes private current coordinates, raw sensor data, unpublished contribution/media metadata and debug state. `spot-cloud-stargazing-action` validates the formal spot or authorized pending proposal and Observation Context, then pushes `sky/detail`; invalid or stale context fails beside that action with recovery.
- The ordinary base map is not a layer choice. Quiet map-edge controls own location and one compact layer trigger; no independent lower-left `观测条件` card remains. The Map's single coordinator is an enum `bottomPresentation = none | spot-panel | layer-sheet | spot-editor`, not parallel visible/active booleans. Activating `map-layer-selector` retargets that owner to one content-sized bottom sheet: the spot panel and marker selection lose active/hit semantics as the layer takes ownership; only the outgoing visual may finish its exit, while the prior spot and extent remain restoration history. A later marker/result intent retargets directly from the live layer sheet to the newly selected spot at medium and never restores an intermediate old panel. Map tap, system Back or the active trigger closes the layer; prior panel extent returns only if no newer intent superseded it. The trigger's open state uses a pale selection treatment without changing geometry. Exactly two equal-width, whole-card single choices remain: `光污染` (`LIGHT`) and `云量` (`TOTAL_CLOUD`). Valid activation commits immediately; selecting the current option is idempotent, never deselects both, never enables two overlays and has no Apply step. Keep the last valid choice on reopen; use `TOTAL_CLOUD` for a first selection without valid prior state. `观测机会` / `OPPORTUNITY` is no longer a Mini Program map choice, summary or legend. A legacy selected opportunity value normalizes to `TOTAL_CLOUD` without changing point, date or camera. Removing this map presentation does not retire underlying SkyReport/astronomy signals used by other responsibilities. There is no off/close `x`.
- `map-time-control` composes the same shared observation-date/time component as panel astronomy inside `map-layer-selector`. It includes the identical centered date/calendar cluster, previous/next available local date and return-to-tonight, plus the same curved ruler geometry and preview/commit/cancel behavior; this consumer only omits lunar icons and their empty slot. Date availability, local observation-night semantics, preservation of clock time, missing samples and request cancellation follow [Lunar Facts And Date Selection](spot-and-sky.md#lunar-facts-and-date-selection). The date arrows change local calendar dates, preserving the local clock when a valid sample exists. The sheet describes the entire Map: show only the selected layer legend and meaningful source/coverage information, never a spot name, single-point value or an invented viewport aggregate. The date/time component is present only for the time-dependent TOTAL_CLOUD choice. Map, panel and orientation preserve one `ObservationContext.selectedAt` through opening/closing and layer switching.
  MapScene supplies a viewport-bounded timeline from the same per-spot SkyReport truth. Dragging previews the selected frame and dependent values, valid release commits, and cancel restores the committed instant. `TOTAL_CLOUD` and dependent point facts may change with the selected sample; cloud polygons remain bounded to supported formal-point cells. `LIGHT` uses published EOG annual nightlight grids; `layerFor` in `workers/miniapp-api/src/miniapp-service.ts` takes its validity from source metadata and queries cells by dataset version and viewport, without an observation-time selector. Hide its date/time component completely, including hit and accessibility surfaces; do not disable it or leave an empty time slot. A compact annual-data explanation makes clear that changing observation time does not change this layer; specific year/period must come from real metadata. Preserve the committed Observation Context in the model and restore the same date/time when returning to TOTAL_CLOUD. Keep the bottom choice cards and navigation anchored while the sheet top smoothly contracts/expands to fit content, retargeting from live geometry on reversal; reduced motion changes state directly. Cancel an in-progress time preview before hiding; a calendar modal closes before its parent and focus must never return into a hidden time region. Whole-night TripDecision is not a selected-time fact.

No personal/external-profile link summary or entry, content-import entry, direct contribution form entry, or pending-count strip remains on My. External-profile management is retired from the Mini Program product topology; removing UI does not authorize deleting stored account data. Existing import infrastructure is not a visible My feature and has no newly approved replacement entry.

Avatar opens album / camera / cancel actions, then preview and explicit save; nickname has edit / save / cancel. Cancellation or failure preserves the current saved identity. Production must persist changes through the current authenticated account owner, not change WeChat profile or use a local sample as account truth. Native media permissions, upload and recovery remain implementation work; prototype success is not backend completion.

观星计划 is the stable entry title for all dates. One plan relates to one formal spot, an explicit observing interval, departure arrangements, optional astronomical events, user-authored reminder checklists and remarks; weather/route facts are read for that saved context without overwriting user choices. selectedAt remains the observing interval start for the existing My-card ordering contract. My shows ongoing plans (start <= now < end) and plans starting within now <= start <= now + 24 hours, ordered ongoing first, then absolute start and stable planId, at most three. Refresh on foreground and as time passes; an ongoing plan remains across midnight until its end. Display ongoing state and its local ending time without enlarging the card into a separate timeline. Render date/time in the spot timezone; skip invalid times rather than inventing a value. No visible 未来24小时 badge. More than three eligible plans exposes one … target; three or fewer do not. The card-header arrow always opens all plans including those outside the window; each row opens its own plan. An empty near-term subset retains the card and all-plans entry. Loading/failure must not pretend to be an empty successful result or delete saved plans. Prototype sample time is not production logic. The plan detail's existing mixed arrival/observation labels must resolve to an explicit planned observing time during migration; automatic departure and composite recommended windows are retired. The adopted objective reference retains darkness/dawn, moonrise/moonset and illumination, cloud cover, wind and temperature. Show the actual computed night and returned forecast-hour coverage; missing days/hours never inherit the first night's values. Read-only plan date/time labels use the saved snapshot timezone even when Context restoration fails.

### 观星点创建与反馈

本页管理本账号的创建记录与反馈编辑记录；不是公共动态或观星点修改历史。一级分组“创建的观星点”“反馈编辑”分别保留状态筛选与滚动位置；按最近保存/提交/审核变化时间倒序展示，返回编辑前的组、筛选、滚动和焦点。

- 创建状态为“草稿、审核中、已上线、审核未通过”；反馈状态为“审核中、已通过、审核未通过”。“全部”只属筛选，不是业务状态。创建的已上线必须有正式发布回执与 formal spot_id；审查通过而尚未发布时，保留处理中语义（主状态审核中、实际详情可说明待发布），不能提前标为已上线。反馈已通过表示本次审核结论，不自行宣布正式内容已经合并上线。
- 记录中的观星点卡片复用搜索页的基础卡片：区域、地点名称、地址与有图/无图构图保持一致，审核状态、时间、修改字段摘要、原因及操作扩展在其下方。点击仍按本记录状态进入编辑或只读内容，由明确动作文案解释目的，不因为外观复用改变权限或路由。设计预览共同实现由 [公共观星点卡片](../../../../../docs/design-resources/wechat-miniapp/shared/spot-card/README.md) 承载，生产组件仍需按现有Taro owner迁移。每条记录展示对应保存/提交/审核时间、文字与图标共同表达的状态；使用可归属的照片时才显示缩略图，不用附近点照片冒充。草稿“继续编辑”，审核中“查看提交内容/本次反馈”只读；已上线打开正式点信息组件，若当前正式点已不可公开查看，应明确说明并保留本次冻结记录入口，不能误报网络失败；反馈已通过查看本次冻结快照和结果。空列表区分本筛选无记录与读取失败，失败可重试，不把失败当空。
- 两类审核未通过都显示服务端公开给提交者的具体原因，并提供“修改后再提交”。打开原表单，回填该次提交内容与必要审核意见；不要求重建地点或重复填所有字段。创建重提复用编辑观星点及手动远端保存；反馈重提复用完整反馈编辑、浅黄差异及文末原值→新值，无存草稿。
- 未通过的旧提交和审核意见保持不可变；打开编辑得到工作副本。创建的手动保存更新同一逻辑记录的工作副本，主状态仍为审核未通过，不能清掉拒绝证据或伪装成新地点；首次未提交的草稿仍为草稿。再次提交生成新审核批次，成功回执后才进入审核中并冻结；传输重试不生成新批次。失败保留输入、媒体及原审核结果，返回/关闭未保存编辑仍走现有放弃修改确认。
- 反馈重提以最新正式版本核对：保留用户已改字段；若正式资料期间改变，展示受影响的原值、当前正式值和用户修改，要求处理冲突后重提，不能全量覆盖别人已通过的修改。新批次同时冻结原始 baseline/用户提议与核对后的正式版本/实际接受的差异；本人只读页及审核摘要按实际接受的差异展示，已放弃的冲突值不得伪装成待审修改。旧批次对比不随之重算，缺少核对后版本的历史快照只能按其原始提交内容兼容显示。同一用户×同一正式点最多一份审核中反馈的约束保持。
- 列表发起的重提成功展示该记录的审核中只读内容，并保留回到本列表的路径；Map/点信息组件发起的首次提交仍按各自原返回合同。涉及未提交草稿的地图展示继续由新增观星点合同拥有，不把列表作为第二草稿源。
- 观星点修改历史由后续管理后台展示；小程序只展示当前记录内容、本次差异、审核原因与结果，不增加版本历史、审核批次时间线或后台操作入口。服务端历史保留与权限边界由 [Contribution revision](../../../../architecture/runtime-and-domain.md#contribution-revision-remote-drafts-and-frozen-field-edits) 拥有。

## Location identity and capability lifecycle

| Input | Identity and authoritative facts | Current account actions |
| --- | --- | --- |
| Formal spot | Published canonical spot_id and current restrictions | Existing browse/favorite/share/plan/navigation/sky actions, each subject to its existing safety and authorization checks |
| Private draft | Account-owned remote working copy and revision | View/edit/explicit save; no favorite/share/plan/sky; no implied formal navigation permission |
| Pending creation | Account-owned frozen submission, proposal_id and current attempt | View and cloud stargazing with authorized submitted coordinates; no favorite/share/plan; no inherited formal publication or action clearance |
| Formal spot with own pending feedback | Formal facts plus separately loaded own frozen feedback | Formal actions remain governed by the formal spot; feedback is not a pending new location |

Publication/merge returns a durable mapping from stable proposal identity to canonical spot_id, including merge into an existing published point.

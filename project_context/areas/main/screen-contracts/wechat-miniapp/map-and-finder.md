# WeChat Mini Program Map And Search Invariants

This on-demand subdomain node normatively continues `Cross-Control And State Invariants` for Map, dedicated Search, the spot information panel and shared Observation Context behavior.

## Cross-Control And State Invariants

- `mini-primary-navigation` owns only Map/My. My has no second tab set: `my-account-header` composes the existing avatar/display-name/account state into one compact aligned account-hub header, `my-settings-action` remains one named 44px Settings gear target, `my-profile-summary` owns login/account state, and `my-grouped-entry-list` contains only a limited number of routine rows. `my-plan-entry` and `my-contribution-entry` may form one restrained utility group before those rows but retain their existing child routes and real status only; no commerce, membership, promotional or fabricated-statistics module is introduced. Back restores the My root's useful scroll position and logical opener focus. Favorite browsing remains in Search `想去`, while the same underlying relation remains operable from the Map spot information panel; Plan, Contribution and Settings do not create another favorite or spot truth.
- `spot-contribution-entry` and `my-contribution-entry` converge on one contribution owner. The information panel passes only its formal `spot_id` and display label; My opens general intake. A draft, upload session and submitted report are identity-scoped server records with explicit revision/idempotency state. Approval means accepted for canonical owner processing, not that the report itself became a published fact; only an audited operations merge followed by a fresh complete publication assessment can change formal output.
- `map-search-entry` is one fixed floating Search field on the Map. It contains no embedded filters, result list, filter summary grid, content Sheet or additional product launcher. A valid tap/keyboard/accessibility activation pushes `spot/search`, preserving the physical Map instance, camera, committed filters, selected time and analysis layer behind the child route. The entry is visible while the information panel is hidden, small or medium; it is absent at large. During large-to-smaller direct manipulation, panel media opacity reaches its closed threshold before Search begins its own fade-in. Search never overlaps readable media or appears as a disabled large-state duplicate. Map and Search states contain no trailing clear/close glyph.
- `spot-search-shell` owns the dedicated child page and a keyboard-safe vertical content owner. `spot-search-field` is the same visual rectangle and rendered text as `map-search-entry`: route activation preserves its size, position, fill, border, radius, query-or-placeholder string, typography and input origin as a stationary transition anchor while the remaining Search content reveals below it. Only the leading slot crossfades from Search to a named Back glyph. That glyph, WeChat/system Back and the platform edge-back gesture all reverse the same child reveal and return to Map; cancellation restores the live Search state, and commit alone pops the route. The field receives entry autofocus and owns query/submit semantics without a trailing `x` action. A valid outside tap may blur the field, dismiss its IME and close `spot-search-query-overlay` without leaving Search or trapping focus; the field can be focused again. The compact overlay anchors directly below the field with body-level rows and quiet dividers; it does not introduce card-sized rows or move the filters. Pointer/keyboard suggestion choice commits before blur cleanup.
- `spot-search-filter-group` exposes all Source-defined terminal filters as one compact adaptive wrap-safe group immediately below the field or active suggestion overlay. It keeps only a micro-gap to that owner and a modest `12–16rpx` visual separation before the first result partition; no blank section band is inserted. It has no visible “筛选条件” title or divider, quick/more classification, hidden advanced editor, opening snapshot, draft, apply/revert footer or checkbox-table variant. Every `spot-search-filter-choice` is an immediately committed multi-select value derived from the same filter store. It keeps normal label flow, places one semantic prefix icon before the label, and layers its selected ornament over the trailing text region without reserving inline width or changing geometry. Icon, text, the palest current active fill, ornament and programmatic checked state jointly communicate selection.
- `spot-search-result-list` has exactly two first-level partitions: `想去` contains favorited matching formal spots and `其他观星点` contains the remainder. Each compact body-level partition header remains a full 44px operable row, exposes expanded state and count, and uses a stable chevron. Expand/collapse preserves one retained item tree and animates the current measured block geometry plus opacity; it never remounts results, toggles the outgoing tree before measurement, changes card width, resets scroll or flashes a replacement surface. Rapid reversal retargets from the live block. City names are group headings or sticky labels inside the partition, not another disclosure layer. The page restores useful query/filter/partition/scroll state when returning from Map and hides scrollbar chrome without clipping touch/wheel/keyboard reachability. Empty/no-results, stale-summary, partial and dynamic-provider failure states preserve static formal-spot/favorite identity and expose safe recovery.
- `spot-search-result-card` uses the full available result column width. When licensed site media exists it becomes the card background; a fixed half-width leading information field preserves readable name and metadata while retaining a faint, low-contrast view of the image beneath its translucent solid-to-transparent treatment. The treatment is not an opaque slab, glass or blur and does not imply media rights or freshness. When no valid image exists the same content geometry uses the normal surface. The entire card is the one selection action; there is no separate trailing “选择” label/button. Press-in is visible, and only a valid press-out/keyboard/accessibility activation commits the formal spot, pops Search, recenters the existing map as needed and opens `map-spot-information-panel` at `medium`. Drag-away, scroll competition, cancellation, disablement or invalid release does not commit.
- `map-marker-panel-coordinator`, Search result state and the map accessibility list expose one selected formal spot. A first valid marker activation selects the spot and opens the same panel at `medium`; a second activation is not required. A valid tap on physical map space that is not a formal marker clears the visible spot selection and transitions the panel from its live position down to `hidden`; its hit and semantic surface remain until the exit completes so the state never vanishes abruptly. A pan/pinch beginning outside the panel remains map-owned; automatic camera movement never fights user pan. The Search result list and semantic map list provide non-gesture point-selection alternatives.
- `map-spot-information-panel` is map-parallel, non-modal and has `visibility = hidden | visible` plus `extent = small | medium | large`; hidden is not another extent. All three extents retain one ordered document tree and one mapping from formal facts to rows. Extent changes only the viewport crop; `large` alone enables the document's one vertical scroll. Per-extent conditional content trees, remounts, reordered facts and duplicated mappings are forbidden. The panel retargets from the live presentation position and queues nothing. Only `map-spot-panel-handle`'s small long rectangular hit region owns vertical extent manipulation; panel body, content, media and other top chrome never start that gesture. Pointer down alone shows feedback but does not change extent, and a release below the drag threshold is a no-op. A left-edge rightward Back gesture resolves to `large → medium`; handle keyboard/assistive increment/decrement is the non-gesture alternative.
- The sole presentation exception is valid licensed media. It occupies no region at small or medium, then pulls out continuously at the document top during medium-to-large progress. The image reaches its full region before `map-search-entry`, `map-location-control` and the layer trigger begin their near-screen-top fade; reverse motion restores those controls before retracting media. Missing, invalid or unavailable media removes the media node entirely. In that case a compact structural handle band remains at every intermediate extent; when media exists the handle overlays it and the separate band collapses. Ordinary unknown/unprovided values share the visible copy `暂无数据`, while permission, loading, stale, error, not-applicable and safety states remain distinct model states with their real recovery/effect.
- `map-spot-panel-section-nav` floats above the panel at the vertical center of the currently visible panel/viewport and has exactly two icon-plus-label actions: `概览` and `天文`. Its outer pill has zero internal top/bottom padding; the first item touches the clipped top curve, the second touches the bottom curve, and only one shared divider separates them. It consumes no document column or global trailing padding, has no inter-item gap, directional shadow or geometry shift. Its active fill uses the palest current sky surface plus a non-color indicator.
- `map-spot-panel-action-bar` is a separate bottom safe-area pill containing exactly three icon-labelled actions: `想去`, `分享` and `云观星`. It remains operable at all visible extents without being duplicated in the document. Favorite success is expressed by `spot-favorite-action` alone. Share is an explicit user action over the formal spot's allowed public summary and excludes private current coordinates, raw sensor data, unpublished contribution/media metadata and debug state. `spot-cloud-stargazing-action` validates the formal spot and Observation Context, then pushes `sky/detail`; invalid or stale context fails beside that action with recovery.
- The ordinary base map is not a layer choice. Quiet map-edge controls own location and one compact layer trigger; no independent lower-left `观测条件` card remains. The Map's single coordinator is an enum `bottomPresentation = none | spot-panel | layer-sheet`, not parallel visible/active booleans. Activating `map-layer-selector` retargets that owner to one fixed-height bottom sheet: the spot presentation and its active semantics are removed after exit, while selected spot and previous extent remain model state. A later marker/result intent retargets directly from the live layer sheet to the newly selected spot at medium and never restores an intermediate old panel. Map tap, system Back or the active trigger closes the layer; prior panel extent returns only if no newer intent superseded it. The trigger's open state uses the palest sky treatment without changing geometry. Exactly three image-backed choices remain and there is no off/close `x`.
- `map-time-control` owns `ObservationContext.selectedAt` inside `map-layer-selector`: exactly one visible current local date/time value, selected analytical layer, its objective value, direct scrub preview, compact metrics and map feedback remain together. Its shared curved ruler is raised closer to the affected data, has no visible arrow controls, and must be horizontally draggable through the existing Taro enhanced `ScrollView`; fixed-center preview and release snap advance only through real timeline slices. Programmatic min/max/current and incremental actions remain available through adjustable semantics, keyboard and assistive technology without arrow chrome.
  MapScene supplies one viewport-bounded compact timeline projected by the BFF from the same per-spot hourly SkyReport truth. Each frame contains per-spot cloud, moon and selected-time SkyOpportunity signals, plus polygons only for the requested dynamic layer; static layer metadata is not duplicated per frame. Dragging updates the displayed time, frame polygons, metrics and dependent point summary without client-side weather/opportunity calculation; valid release commits the sole Observation Context, while cancellation returns to the committed value. `LIGHT` is source-dated/static for its declared period; `TOTAL_CLOUD`, `OPPORTUNITY` and dependent point summaries may change with selected time. A static layer never animates fabricated hourly change, and a whole-night TripDecision is never presented as the selected-time condition.
- Direct map input is pan, pinch and tap. The map does not render permanent pan arrows or zoom steppers where native gestures apply. Every icon-only map action has a programmatic name/state and a keyboard/accessibility-list alternative.

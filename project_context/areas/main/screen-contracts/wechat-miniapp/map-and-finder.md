# WeChat Mini Program Map And Search Invariants

This on-demand subdomain node normatively continues `Cross-Control And State Invariants` for Map, dedicated Search, the spot information panel and shared Observation Context behavior.

The adopted daytime layer composition is reached through the sole [Map resource entry](../../../../../docs/design-resources/wechat-miniapp/map/ADOPTED.md). Read its layer-selector package together with the [shared observation-time owner](shared-state-and-recovery.md#shared-observation-time-resource) and its resource before implementing this control.

## Cross-Control And State Invariants

- `mini-primary-navigation` owns only Map/My. My follows [My account and plans](#my-account-and-plans); there is no second tab set. Back restores useful scroll position and opener focus. Favorite browsing remains in Search 想去; no second favorite or spot truth is introduced.
- `spot-contribution-entry` and `my-contribution-entry` converge on one contribution owner. The information panel passes only its formal `spot_id` and display label; Map opens new-place intake; My opens the account’s creation and feedback records, including private drafts. Editable new-place drafts are explicitly saved to the remote database, support multiple account-scoped records and are owned by the existing contribution owner; upload sessions and submitted reports retain server revision/idempotency state. Approval means accepted for canonical owner processing, not that the report itself became a published fact; only an audited operations merge followed by a fresh complete publication assessment can change formal output.
- `map-search-entry` is one fixed floating Search field on the Map. It contains no embedded filters, result list, filter summary grid, content Sheet or additional product launcher. A valid tap/keyboard/accessibility activation pushes `spot/search`, preserving the physical Map instance, camera, committed filters, selected time and analysis layer behind the child route. The entry is visible while the information panel is hidden, small or medium; it is absent at large. During large-to-smaller direct manipulation, Search and the other Map controls return in their near-top phase before media retracts; their hit/semantic state follows the same live transition without covering readable media. Search never overlaps readable media or appears as a disabled large-state duplicate. Map and Search states contain no trailing clear/close glyph.
- `spot-search-shell` owns the dedicated child page and a keyboard-safe vertical content owner. `spot-search-field` is the same visual rectangle and rendered text as `map-search-entry`: route activation preserves its size, position, fill, border, radius, query-or-placeholder string, typography and input origin as a stationary transition anchor while the remaining Search content reveals below it. Only the leading slot crossfades from Search to a named Back glyph. That glyph, WeChat/system Back and the platform edge-back gesture all reverse the same child reveal and return to Map; cancellation restores the live Search state, and commit alone pops the route. The field receives entry autofocus and owns query/submit semantics without a trailing `x` action. A valid outside tap may blur the field, dismiss its IME and close `spot-search-query-overlay` without leaving Search or trapping focus; the field can be focused again. The compact overlay anchors directly below the field with body-level rows and quiet dividers; it does not introduce card-sized rows or move the filters. Pointer/keyboard suggestion choice commits before blur cleanup.
- `spot-search-filter-group` exposes the 16 current terminal filters in one compact horizontal scrolling line immediately below the field, with a fixed named filter trigger at its trailing edge. It is one filter family and one committed Map/Search store, not quick/advanced subsets or two independent selections. A parameter-free strip `spot-search-filter-choice` commits immediately. The driving-duration item opens the existing filter sheet at 到达方式 for its enabled state and minutes input; it does not silently apply an unseen value. Horizontal drag scrolls without selecting on release and does not steal vertical result scroll or platform Back; every terminal value remains keyboard/assistive reachable. Prefix icon and label keep normal flow; selected fill, boundary, small ornament and programmatic checked state communicate selection without changing geometry. The adopted resource owns the daytime composition; no “筛选条件” heading or extra explanatory band is added.
- The filter trigger opens one modal sheet with exactly two classification levels: a category and its terminal choices. The five categories are `观测条件`, `到达方式`, `设施配套`, `场地偏好`, and `资料更新`; the 16 current values and their meaning are owned by the Filter semantics section below; the adopted Search visual structure supplies grouping/layout, not business predicates. The two retired recommendation values must be removed during migration. Opening copies the committed selection into a sheet-local draft. Choice taps and `清空选择` edit only that draft; `确定` replaces the single committed selection and updates the strip/results. Close, backdrop, Escape or system Back cancels the draft, then restores trigger focus and the preserved query, committed filters, partition and scroll state. Back closes this sheet before attempting the Search route transition. Category switching only changes which terminal choices are visible, retains all draft selections and introduces no third level. The modal traps its own focus/interaction while open; it is separate from Map's bottom-presentation coordinator and cannot become a second persistent filter store.
- `spot-search-result-list` has exactly two first-level partitions: `想去` contains favorited matching formal spots and `其他观星点` contains the remainder. Each compact body-level partition header remains a full 44px operable row, exposes expanded state and count, and uses a stable chevron. Expand/collapse preserves one retained item tree and animates the current measured block geometry plus opacity; it never remounts results, toggles the outgoing tree before measurement, changes card width, resets scroll or flashes a replacement surface. Rapid reversal retargets from the live block. City names are group headings or sticky labels inside the partition, not another disclosure layer. The page restores useful query/filter/partition/scroll state when returning from Map and hides scrollbar chrome without clipping touch/wheel/keyboard reachability. Empty/no-results, stale-summary, partial and dynamic-provider failure states preserve static formal-spot/favorite identity and expose safe recovery.
- `spot-search-result-card` uses the full available result column width. When licensed site media exists it becomes the card background, with no card border or shadow in the adopted daytime composition. Its leading readability treatment follows the adopted resource, preserves legible names/metadata and retains a faint view of the image; it is not an opaque slab, glass or blur and does not imply media rights or freshness. The address icon aligns with the first text line, including wrapped addresses. When no valid image exists the same content geometry uses the normal quiet surface without a placeholder or reserved media gap. The entire card is the one selection action; there is no separate trailing “选择” label/button. Press-in is visible, and only a valid press-out/keyboard/accessibility activation commits the formal spot, pops Search, recenters the existing map on that spot and opens `map-spot-information-panel` at `medium`. This is a selection intent even when the spot ID matches the previously selected spot: it must restore medium from a small, hidden or layer presentation and recenter the same map rather than returning early on ID equality. Drag-away, scroll competition, cancellation, disablement or invalid release does not commit. The adopted browser resource demonstrates press appearance only; real selection, camera and panel behavior require production implementation and verification.
- `map-marker-panel-coordinator` owns one selected typed location; public Search returns formal spots, while the owner’s private markers use the location identity contract below. The accessibility list preserves that distinction. A first valid marker activation selects the spot and opens the same panel at `medium`; a second activation is not required. A valid tap on physical map space that is not a formal marker clears the visible spot selection and transitions the panel from its live position down to `hidden`; its hit and semantic surface remain until the exit completes so the state never vanishes abruptly. A pan/pinch beginning outside the panel remains map-owned; automatic camera movement never fights user pan. The Search result list and semantic map list provide non-gesture point-selection alternatives.
- `map-spot-information-panel` is map-parallel, non-modal and has `visibility = hidden | visible` plus `extent = small | medium | large`; hidden is not another extent. All three extents retain one ordered document tree and one mapping from formal facts to rows. Extent changes only the viewport crop; `medium` and `large` enable the document's one vertical scroll. Per-extent conditional content trees, remounts, reordered facts and duplicated mappings are forbidden. The panel retargets from the live presentation position and queues nothing. At medium/large, only `map-spot-panel-handle`'s full-width compact white identity-header band owns vertical extent manipulation; the centered dash is a visual hint, not the hit-region boundary. The band and name belong to the retained document and scroll out together, never fixed/sticky to the panel viewport. The name may visually overlap the lower part of the band without adding a tall blank spacer; actions never overlap its hit region. Once that actual band has scrolled away, visible top chrome/content cannot initiate extent drag. System/platform Back (and the supported edge-back equivalent) resolves large to medium; scrolling back to the band restores its direct manipulation. At medium/large, other content/media never starts extent dragging. At small, upward document drag expands to medium; downward drag is clamped to small without motion or dismissal. Fixed actions remain independent. Pointer down alone shows feedback but does not change extent, and a release below the drag threshold is a no-op. A left-edge rightward Back gesture resolves to `large → medium`; handle keyboard/assistive increment/decrement is the non-gesture alternative.
- The sole presentation exception is valid licensed media. It occupies no region at small or medium, then pulls out continuously at the document top during medium-to-large progress. The image reaches its full region before `map-search-entry`, `map-location-control` and the layer trigger begin their near-screen-top fade; reverse motion restores those controls before retracting media. Missing, invalid or unavailable media removes the media node entirely. A compact white identity-header band remains below any visible site media; when media is absent it is the document's first region. It follows the document during large-state scrolling and never becomes a persistent overlay. Site media supports one wide image or a horizontally draggable multi-image strip with a next-image cue and truthful count. Direction-lock separates horizontal strip drag from vertical document scroll and panel/edge-back gestures; a drag suppresses image-opening taps, while an intentional tap opens the selected image in the shared viewer; no-media has neither gallery nor placeholder. Ordinary unknown/unprovided values share the visible copy `暂无数据`, while permission, loading, stale, error, not-applicable and safety states remain distinct model states with their real recovery/effect.
- `map-spot-panel-section-nav` follows the sole current [Spot and sky](spot-and-sky.md) contract: one-level horizontal section navigation in the same continuous document. It is absent at the basic-information start, appears when the astronomy boundary reaches the reading top and then stays sticky; returning to the basic-information start hides it. One rounded gradient indicator slides between sections without remounting content or changing document geometry. It reserves no right-side column.
- `map-spot-panel-action-bar` is a separate bottom safe-area action region containing, for a formal spot, exactly three icon-labelled actions in left-to-right order: `想去`, `云观星`, `分享`. Its adopted three-extent composition is three separate compact buttons as specified in DESIGN.md §5A.0 and the sole Map resource entry. It remains operable at all visible extents without being duplicated in the document. Favorite success is expressed by `spot-favorite-action` alone. Share is an explicit user action over the formal spot's allowed public summary and excludes private current coordinates, raw sensor data, unpublished contribution/media metadata and debug state. `spot-cloud-stargazing-action` validates the formal spot or authorized pending proposal and Observation Context, then pushes `sky/detail`; invalid or stale context fails beside that action with recovery.
- The ordinary base map is not a layer choice. Quiet map-edge controls own location and one compact layer trigger; no independent lower-left `观测条件` card remains. The Map's single coordinator is an enum `bottomPresentation = none | spot-panel | layer-sheet | spot-editor`, not parallel visible/active booleans. Activating `map-layer-selector` retargets that owner to one content-sized bottom sheet: the spot panel and marker selection lose active/hit semantics as the layer takes ownership; only the outgoing visual may finish its exit, while the prior spot and extent remain restoration history. A later marker/result intent retargets directly from the live layer sheet to the newly selected spot at medium and never restores an intermediate old panel. Map tap, system Back or the active trigger closes the layer; prior panel extent returns only if no newer intent superseded it. The trigger's open state uses a pale selection treatment without changing geometry. Exactly two equal-width, whole-card single choices remain: `光污染` (`LIGHT`) and `云量` (`TOTAL_CLOUD`). Valid activation commits immediately; selecting the current option is idempotent, never deselects both, never enables two overlays and has no Apply step. Keep the last valid choice on reopen; use `TOTAL_CLOUD` for a first selection without valid prior state. `观测机会` / `OPPORTUNITY` is no longer a Mini Program map choice, summary or legend. A legacy selected opportunity value normalizes to `TOTAL_CLOUD` without changing point, date or camera. Removing this map presentation does not retire underlying SkyReport/astronomy signals used by other responsibilities. There is no off/close `x`.
- `map-time-control` composes the same shared observation-date/time component as panel astronomy inside `map-layer-selector`. It includes the identical centered date/calendar cluster, previous/next available local date and return-to-tonight, plus the same curved ruler geometry and preview/commit/cancel behavior; this consumer only omits lunar icons and their empty slot. Date availability, local observation-night semantics, preservation of clock time, missing samples and request cancellation follow [Lunar Facts And Date Selection](spot-and-sky.md#lunar-facts-and-date-selection). The date arrows change local calendar dates, preserving the local clock when a valid sample exists. The sheet describes the entire Map: show only the selected layer legend and meaningful source/coverage information, never a spot name, single-point value or an invented viewport aggregate. The date/time component is present only for the time-dependent TOTAL_CLOUD choice. Map, panel and orientation preserve one `ObservationContext.selectedAt` through opening/closing and layer switching.
  MapScene supplies a viewport-bounded timeline from the same per-spot SkyReport truth. The shared component receives genuine available dates/samples and presentation callbacks; it does not require the map overlay to produce data before other supported facts can be used. Dragging previews the selected frame and dependent values, valid release commits, and cancel restores the committed instant. `TOTAL_CLOUD` and dependent point facts may change with the selected sample; cloud polygons remain bounded to supported formal-point cells. `LIGHT` uses published EOG annual nightlight grids; `layerFor` in `workers/miniapp-api/src/miniapp-service.ts` takes its validity from source metadata and queries cells by dataset version and viewport, without an observation-time selector. Hide its date/time component completely, including hit and accessibility surfaces; do not disable it or leave an empty time slot. A compact annual-data explanation makes clear that changing observation time does not change this layer; specific year/period must come from real metadata. Preserve the committed Observation Context in the model and restore the same date/time when returning to TOTAL_CLOUD. Keep the bottom choice cards and navigation anchored while the sheet top smoothly contracts/expands to fit content, retargeting from live geometry on reversal; reduced motion changes state directly. Cancel an in-progress time preview before hiding; a calendar modal closes before its parent and focus must never return into a hidden time region. Missing coverage remains explicit and never borrows neighboring/stale values. Switching layers preserves date, clock, selected point and camera, cancels superseded requests, changes only that layer's legend/source/overlay and conditional time presentation and exposes genuine loading or failure locally. Whole-night TripDecision is not a selected-time fact.
- Direct map input is pan, pinch and tap. The map does not render permanent pan arrows or zoom steppers where native gestures apply. Every icon-only map action has a programmatic name/state and a keyboard/accessibility-list alternative.

The visible TOTAL_CLOUD label is `云量`; the domain key and percentage meaning are unchanged. LIGHT carries a bulb outline and CLOUD a cloud outline beside the label; keep a separate checked indicator so icons do not replace selection semantics.

## My account and plans

The sole daytime adopted resource is [My resource entry](../../../../../docs/design-resources/wechat-miniapp/my/ADOPTED.md). Root has no visible 我的 page title; retain native capsule, editable avatar and nickname, one Settings gear, one 观星计划 card and one 观星点创建与反馈 entry. No personal/external-profile link summary or entry, content-import entry, direct contribution form entry, or pending-count strip remains on My. External-profile management is retired from the Mini Program product topology; removing UI does not authorize deleting stored account data. Existing import infrastructure is not a visible My feature and has no newly approved replacement entry.

Avatar opens album / camera / cancel actions, then preview and explicit save; nickname has edit / save / cancel. Cancellation or failure preserves the current saved identity. Production must persist changes through the current authenticated account owner, not change WeChat profile or use a local sample as account truth. Native media permissions, upload and recovery remain implementation work; prototype success is not backend completion.

观星计划 is the stable entry title for all dates. One plan relates to one formal spot, an explicit observing interval, departure arrangements, optional astronomical events, user-authored reminder checklists and remarks; weather/route facts are read for that saved context without overwriting user choices. selectedAt remains the observing interval start for the existing My-card ordering contract. My shows ongoing plans (start <= now < end) and plans starting within now <= start <= now + 24 hours, ordered ongoing first, then absolute start and stable planId, at most three. Refresh on foreground and as time passes; an ongoing plan remains across midnight until its end. Display ongoing state and its local ending time without enlarging the card into a separate timeline. Render date/time in the spot timezone; skip invalid times rather than inventing a value. No visible 未来24小时 badge. More than three eligible plans exposes one … target; three or fewer do not. The card-header arrow always opens all plans including those outside the window; each row opens its own plan. An empty near-term subset retains the card and all-plans entry. Loading/failure must not pretend to be an empty successful result or delete saved plans. Prototype sample time is not production logic. The plan detail's existing mixed arrival/observation labels must resolve to an explicit planned observing time during migration; automatic departure and provider-derived windows are supplementary, not user-entered truth.

“观星点创建与反馈”替代“已提交”，具体状态与重提规则见下节。新地点的空白创建入口仍属 Map，正式点的首次反馈入口仍属该点信息组件；My 只管理已有记录，编辑与只读详情复用原表单职责。当前采用的 My 布局仍有效，入口新名称依本产品合同迁移；设计候选并不表示生产路由与 API 已完成迁移。


### 观星点创建与反馈

本页管理本账号的创建记录与反馈编辑记录；不是公共动态或观星点修改历史。一级分组“创建的观星点”“反馈编辑”分别保留状态筛选与滚动位置；按最近保存/提交/审核变化时间倒序展示，返回编辑前的组、筛选、滚动和焦点。

- 创建状态为“草稿、审核中、已上线、审核未通过”；反馈状态为“审核中、已通过、审核未通过”。“全部”只属筛选，不是业务状态。创建的已上线必须有正式发布回执与 formal spot_id；审查通过而尚未发布时，保留处理中语义（主状态审核中、实际详情可说明待发布），不能提前标为已上线。反馈已通过表示本次审核结论，不自行宣布正式内容已经合并上线。
- 记录中的观星点卡片复用搜索页的基础卡片：区域、地点名称、地址与有图/无图构图保持一致，审核状态、时间、修改字段摘要、原因及操作扩展在其下方。点击仍按本记录状态进入编辑或只读内容，由明确动作文案解释目的，不因为外观复用改变权限或路由。设计预览共同实现由 [公共观星点卡片](../../../../../docs/design-resources/wechat-miniapp/shared/spot-card/README.md) 承载，生产组件仍需按现有Taro owner迁移。每条记录展示对应保存/提交/审核时间、文字与图标共同表达的状态；使用可归属的照片时才显示缩略图，不用附近点照片冒充。草稿“继续编辑”，审核中“查看提交内容/本次反馈”只读；已上线打开正式点信息组件；反馈已通过查看本次冻结快照和结果。空列表区分本筛选无记录与读取失败，失败可重试，不把失败当空。
- 两类审核未通过都显示服务端公开给提交者的具体原因，并提供“修改后再提交”。打开原表单，回填该次提交内容与必要审核意见；不要求重建地点或重复填所有字段。创建重提复用编辑观星点及手动远端保存；反馈重提复用完整反馈编辑、浅黄差异及文末原值→新值，无存草稿。
- 未通过的旧提交和审核意见保持不可变；打开编辑得到工作副本。创建的手动保存更新同一逻辑记录的工作副本，主状态仍为审核未通过，不能清掉拒绝证据或伪装成新地点；首次未提交的草稿仍为草稿。再次提交生成新审核批次，成功回执后才进入审核中并冻结；传输重试不生成新批次。失败保留输入、媒体及原审核结果，返回/关闭未保存编辑仍走现有放弃修改确认。
- 反馈重提以最新正式版本核对：保留用户已改字段；若正式资料期间改变，展示受影响的原值、当前正式值和用户修改，要求处理冲突后重提，不能全量覆盖别人已通过的修改。新批次绑定核对后的 baseline/baseRevision；旧批次对比不随之重算。同一用户×同一正式点最多一份审核中反馈的约束保持。
- 列表发起的重提成功展示该记录的审核中只读内容，并保留回到本列表的路径；Map/点信息组件发起的首次提交仍按各自原返回合同。涉及未提交草稿的地图展示继续由新增观星点合同拥有，不把列表作为第二草稿源。
- 观星点修改历史由后续管理后台展示；小程序只展示当前记录内容、本次差异、审核原因与结果，不增加版本历史、审核批次时间线或后台操作入口。服务端历史保留与权限边界由 [Contribution revision](../../../../architecture/runtime-and-domain.md#contribution-revision-remote-drafts-and-frozen-field-edits) 拥有。

2026-09-08 用户确认采用：[观星点创建与反馈唯一资源入口](../../../../../docs/design-resources/wechat-miniapp/contributions/ADOPTED.md)。覆盖两组状态列表、公共观星点卡片、审核意见扩展、两类未通过编辑及只读结果；返回保留组/筛选/滚动。复用反馈完整表单与搜索基础卡片。设计采用不证明服务端重提、冲突处理或生产页面迁移完成。


## 新增观星点
唯一采用入口为 [Map ADOPTED](../../../../../docs/design-resources/wechat-miniapp/map/ADOPTED.md) 的 add-spot 包。此采用不表示生产实现完成。
- 地图工具栏增加与定位、图层同尺寸的加号。点击后加号、搜索框及其余工具淡出；新增弹层上滑至原加号顶部位置，无拖动横杠、无拖动改变高度，关闭和系统返回下滑退出。
- 地图保持可平移/缩放；选择地址只提交坐标和地址元数据并将候选点居中于弹层上方可见地图。候选灰色简化标记的名称实时来自“地点名称”，不是地址；空名称显示未命名状态，不生成正式点身份。手动地图操作不与自动居中竞争。
- 新增/编辑表单、点信息、图层由同一个 bottomPresentation 协调器互斥，spot-editor 内区分新建与编辑，不新增旁路可见布尔。点击其他点、关闭或返回时，有未保存修改先确认放弃；确认前不提交选点、相机移动、Observation Context 或依赖请求切换。取消保留表单、媒体、候选位置和原呈现；确认后才关闭编辑并切到目标点的 medium 信息组件。关闭、切点和返回不触发隐式保存。常规正式点信息的搜索/工具可见性仍遵守其既有 extent 规则。
- 表单为一个垂直滚动文档，地点/到达/设施/说明 Tab 仅定位章节；不折叠分组。停车、洗手间分别收集说明与对应照片；不要求到访时间，不强制补充说明20字。必要的结构化安全/联系状态仍按 Shared State 的 intake 要求，未知不等于允许进入或安全。
- 一个账号可有多个远端草稿。每次点击加号总是打开新的空表单；仅点击存草稿才请求服务端数据库。首次保存建立独立 draft/proposal 身份，编辑时按同一身份和版本更新，不重复创建。取消每60秒自动保存、关闭保存和本地草稿权威；失败保留当前输入，只有成功回执后才更新保存状态。草稿允许不完整；可地图展示的草稿至少有名称和有效选点，其余字段按提交/发布阶段分别校验。同一草稿/媒体/幂等状态由既有 contribution owner 持有，不建立第二业务 store。
- 保存不弹通知。标题右侧显示 HH:mm 已保存；非当天附日期，跨年附年份。必填字段用浅红星号，选填不加文字。具体必填语义以字段职责为准，不能把演示校验当作完整服务约束。

- 已保存且坐标有效的远端草稿作为灰色草稿点留在地图，只对拥有者可见，名称使用地点名称。点击展示复用的信息组件（草稿状态），无“我要反馈”；从编辑动作打开回填的“编辑观星点”表单。加号不恢复任何草稿。重新进入地图从服务端读取本账号的所有草稿；无有效坐标时不生成标记。草稿不开放想去/分享/计划/云观星，不伪造正式点身份。
- 新增提交得到真实成功回执后，将该草稿原子转为审核中提案、从草稿集合移出（保留提交证据），将地图标记替换为正常星形点针加右上角微型时钟审核角标；其身份仍是 proposal_id，不是 formal spot_id。默认只在提交者账号地图可见，不进入公共点位查询。审查通过与正式发布仍按审核/发布职责区分，不由前端本地修改状态充当通过。
- 提交成功按顺序收起新增弹层、居中对应提交点、弹起 medium 观星点信息组件。审核中复用正式组件的布局、extent与内容映射，标题紧邻“审核中”tag；底部隐藏“想去”和“分享”，保留“云观星”。缺失事实按正常缺失规则处理，不把附近正式点的数值复制为提案事实。
- 审核中云观星使用经授权的提案坐标和同一Observation Context，不伪造正式spot_id；此范围扩大了原本仅正式点的云观星输入身份，仍由既有天空/报告职责接入与校验，不另起事实源。审核失败、待补充或后续发布从服务端状态更新，不能长期把终态仍标为审核中。
- 点选其他正式观星点时恢复完整正式底栏且移除审核标签；提案信息组件不残留到正式点。提交失败不改变草稿点身份、不弹审核面板、不清草稿。

## 观星计划：出行与观测的组织职责

天文事件更新采用自动获取为主、后台核对和补录为辅。已接入且稳定的结构化来源经校验可自动发布；首次接入、解析异常、关键时刻明显变化或来源冲突进入后台核对，上传不直接发布。小程序只读服务端已发布事件库，不依赖用户或生产服务访问海外。当前服务无法访问海外接口：优先验证国内权威资料；海外独有数据在采集能力未具备前使用已核对版本及必要的后台导入，不承诺持续自动更新。来源暂时失败不删除事件或用户关联；超出资料覆盖范围显示未获取，不能显示“没有天象”。事件更新保留来源和版本，不能自动修改用户计划的时间。技术与发布规则由 [事件采集与网络边界](../../../../architecture/runtime-and-domain.md#astronomical-event-ingestion-and-network-boundary) 统一维护。

2026-09-08 requirement: 观星计划 organizes departure, travel, arrival and the chosen observing interval. It does not duplicate the full spot document or promise favorable weather. Display observing reference near the top, then travel arrangements, associated events, personal reminder checklists and remarks. Detail and editor share this information hierarchy. New plans have no mandatory system-authored checklist.

A formal spot information panel exposes 观星计划 when the current account has associated plans, otherwise 去这观星 opens a new editor with that spot prefilled. Multiple associated plans must remain reachable; the adopted interaction uses a spot-filtered plan list, opening directly when there is only one. Back restores the actual opener, including selected spot, panel extent, observation context and useful scroll position; never hardcode My as the destination. Returning from editor/detail/event children follows the same navigation stack. Existing formal-spot scope is retained; extending planning to private drafts or pending proposals needs a separate decision.

Users choose observation start/end and a departure time separately. End must follow start, including crossing midnight; departure precedes observing start. Display the spot timezone and explicit next-day/date labels. Route estimates may suggest arrival/departure but never silently change saved times. Unknown or stale route duration is unavailable, not zero. With a current, attributable estimate matching the chosen origin/destination/travel mode and departure assumptions, compare departure plus travel duration with observing start; if late, show estimated arrival and the delay. The user may still save; neither an estimate nor its failure rewrites the chosen times. Driving, public transit and walking are desired travel choices. Reuse the server route owner, with origin, endpoint/last-mile entrance, mode, distance/duration, transfer/last-mile information when actually returned, provider attribution and freshness. Current Mini Program adapter supports driving; the other modes and usable route geometry require extension, not a claim of existing implementation.

Each plan supports at most 5 user-created reminders relative to departure; each has its own up-to-20-item editable checklist and independent completion state. Reminders and their items can be added, renamed and removed; never inject a fixed preparation list. Store each reminder group’s intent separately from its own platform authorization/send eligibility and actual send/delivery state; a global enabled switch cannot promise all groups will arrive. The product requests WeChat reminders, but template/category eligibility, current account authorization and scheduling remain required capabilities, not an inferred result of saving. Without authorization the checklist still works and states 微信通知未开启. Changing departure, deleting a reminder or deleting a plan must reschedule/cancel pending jobs with server idempotency. Dispatch must recheck plan/reminder versions and authorization; expired/superseded jobs do not send. Missed triggers after recovery are skipped and recorded; confirmed failures may retry within bounded policy before departure, while unknown send outcomes require receipt reconciliation rather than blind resend. Checklist access remains available regardless of notification state. Do not send all 20 custom items as an arbitrary template payload; use an approved concise notification linking back to its checklist. No exact WeChat quota or long-term subscription eligibility is asserted without current official/account evidence.

Astronomical events extend the existing reviewed meteor-event owner rather than create a competing catalog. Event occurrence identity, type, official source/version, occurrence interval/peak and location-projected visibility are distinct. Initial scope: meteor showers, lunar and solar eclipses. An event detail child surface should answer when it occurs locally, whether the selected spot can see it, relevant phases/peak, horizon/direction and moon/darkness constraints, source freshness and genuinely event-specific constraints. Solar observation needs event-specific eye-protection instructions. No matching/local visibility result means unknown/unavailable, not globally visible. Event association is optional and does not silently move a plan date or location. The adopted event list groups concrete occurrences by peak-date month, with a compact date ticket, activity interval and truthful linked/date-overlap state. “认识这场流星雨” and “观测前的小准备” are removed; do not replace them with generic filler advice or fabricated local facts. An unconnected category is unavailable coverage, not an empty universe of events. Source/API support is not yet deployed.

## Filter semantics and coverage

Confirmed 2026-09-09: exactly 16 terminal conditions in the existing five presentation categories. 今晚推荐 and 最佳窗口时长 are retired from Mini Program discovery; this does not delete algorithms serving other accepted consumers. The existing Search resource’s old 18 labels await visual revision and do not override this rule.

| Condition | Matching evidence / parameter |
| --- | --- |
| 驾车范围（时间 / 距离） | One driving route from the explicit valid origin to this point; exactly one active mode. Time defaults to 180 minutes (integer 30–360); distance defaults to 100 km (integer 1–1000). Limits are product input bounds, not provider coverage promises. Compare the selected mode with its own current route duration/distance evidence; never substitute straight-line distance or infer kilometers from minutes |
| 光害 | Published attributable LOW or VERY_LOW annual nightlight product band; no Bortle/SQM inference |
| 少云 | Total cloud <=45% at selectedAt |
| 停车 | Published parking availability is AVAILABLE |
| 厕所 | Published toilet availability is AVAILABLE |
| 可驾车直达 | Explicit DRIVE_TO access evidence; material restrictions still govern actions |
| 有实拍照片 | At least one valid, authorized, displayable site-specific photo belonging to this spot; not a photography-quality judgment |
| 可露营/驻车 | Explicit permission/evidence for camping or overnight vehicle stay; ordinary parking availability does not imply overnight permission |
| 特定天象 | An attributable published occurrence applicable to the selected observing night and spot visibility; directory/time coverage is evaluated separately from whether any occurrence matches |
| 低云阈值 | Low-layer cloud <=30% at selectedAt; total cloud does not establish this field |
| 月亮影响 | LOW under the existing selected-time rule: moon below/on horizon or illumination <25%, with adequate inputs; this is not a whole-trip recommendation |
| 徒步难度 | Explicit NO_HIKE access evidence; it does not promise accessibility or a particular difficulty grade |
| 信号 | Explicit published AVAILABLE signal evidence |
| 充电 | Explicit published AVAILABLE charging evidence |
| 天空开阔方向 | At least one attributable recorded open direction; show its actual direction, never imply the user’s target direction is clear |
| 最近核验时间 | Attributable verification timestamp within the preceding 180 days as of evaluation time; future timestamps do not qualify |

Each condition evaluates MATCH / NO_MATCH / UNKNOWN for each candidate. Static missing evidence and absent permission are not affirmative facts. A known logical alternative can establish a match without inventing its missing counterpart; otherwise required missing inputs mean UNKNOWN. Explicit negative evidence is NO_MATCH. Dynamic evidence binds selectedAt and its real sample/freshness, never an adjacent frame or nightly average. No valid origin means driving UNKNOWN without automatic location collection.

Compute each condition’s AVAILABLE / PARTIAL / UNAVAILABLE coverage over the geographic/query candidate set before applying any business filters. All known results means AVAILABLE even if none match; some known means PARTIAL; none means UNAVAILABLE. An empty candidate population is an empty search scope, not evidence of provider coverage. Keep zero matches, unavailable coverage and partial results distinct; explain the affected condition and offer edit/remove/retry, not a generic successful empty list. Multiple conditions combine with AND: any definite NO_MATCH excludes the point; all MATCH includes it; the remainder are unknown, not silently proven unsuitable. These are future BFF/contracts obligations, not a new client evaluation engine.

The driving parameter is part of the one committed filter state and its sheet-local copy. Editing enabled state, time/distance mode and the two remembered limits, or 清空, changes only that copy; 确定 validates and commits it, while Close/Back/backdrop cancels both. Display the committed limit in the strip when active. Clearing resets disabled/time-mode/180-minutes/100-km in the draft. Switching mode preserves each draft value without converting between units; only the active mode participates in matching and counts as one condition. Invalid active input blocks confirmation with an adjacent unit-specific error. Cancelling restores committed mode, enabled state and limits together. Hidden legacy ranking preferences do not control this parameter; reopening retains the last committed value. Retired recommendation selections are discarded during later migration, preserving query/time and the remaining valid conditions.

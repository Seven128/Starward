# WeChat Mini Program Map And Finder Invariants

This on-demand subdomain node normatively continues `Cross-Control And State Invariants` for Map, Finder, selected-spot and shared Observation Context behavior.

## Cross-Control And State Invariants

- `mini-primary-navigation` owns only Map/My. My has no second tab set: `my-account-header` exposes the title and one named 44px Settings gear action, `my-profile-summary` owns login/account state, and `my-grouped-entry-list` contains only a limited number of routine rows. `my-plan-entry` pushes `plan/detail`, `my-contribution-entry` pushes `contribution/index`, and `my-settings-action` pushes `settings/*`. Back restores the My root's useful scroll position and the logical opener focus. Favorite browsing remains in Finder `想去`, while the same underlying favorite relation remains operable from Spot Detail; Plan, Contribution and Settings do not create another favorite or spot truth.
- `spot-contribution-entry` and `my-contribution-entry` converge on one contribution owner. Detail passes only its formal `spot_id` and display label; My opens general intake. A draft, upload session and submitted report are identity-scoped server records with explicit revision/idempotency state. Approval means accepted for canonical owner processing, not that the report itself became a published fact; only an audited operations merge followed by a fresh complete publication assessment can change formal output.
- `map-spot-finder-trigger` is the logical Map entry owner rather than a standalone visible button. Its user-visible carriers are `map-finder-search-field` query commit and an unselected→selected action in `map-finder-quick-filters`; either can open the same `map-spot-finder-sheet` to `peek` when it is `closed`. The Sheet keeps `extent = closed | peek | expanded` separate from `open_reason = quick_filter | query | manual`, retargets from its live presentation extent and queues nothing. Clearing the last auto-open reason may return an untouched `peek` to `closed`; once the user manually expands or manipulates the Sheet, filter changes update in place and do not unexpectedly dismiss it. Back/Escape and downward drag step `expanded → peek → closed` before route navigation. Closing never clears committed query/quick filters or the selected map spot.
- `map-finder-search-field`, `map-finder-query-overlay`, `map-finder-quick-filters`, `map-finder-sheet-handle` and `map-finder-advanced-filters` derive one result projection. Search owns exactly one conventional Search symbol. Its history/fuzzy-suggestion overlay is geometrically anchored immediately below the field and above the map/Sheet; focus leaving the field-plus-overlay group fades and closes it on the target state-swap timing, while pointer/keyboard suggestion selection commits before blur dismissal. Choosing a suggestion or confirming a query updates query/results, may open `peek`, and never enters Detail. Quick filters commit immediately, remain visible only beneath Search and use an adaptive wrap-safe compact row with hidden scrollbar chrome when a bounded overflow implementation is unavoidable.
  The Sheet has no explanatory header or textual expand button. `map-finder-sheet-handle` is a programmatically named 44px/88rpx control with expanded state; tap toggles the next extent, direct drag follows the grab offset, and reduced motion preserves the same state graph without large travel. `map-finder-advanced-filters` lives inside the Sheet, uses an adaptive compact grid rather than a fixed two-column wall, and retains full hit regions at every width. Opening its editor snapshots the committed set into one draft. Only when the draft differs, compact named revert and commit actions appear; revert restores the opening snapshot and commit atomically replaces the committed set. Closing the whole Sheet discards an uncommitted advanced draft. Query, committed filters, partition-expanded state and useful result scroll position survive dismissal/reopen within the Map route.
- `map-finder-result-list` has exactly two first-level partitions: `想去` contains favorited formal spots and `其他观星点` contains the remaining matching formal spots. Each padded partition header is a full 44px operable row, exposes an accessible expanded state and result count, and ends with an optically centered 18–20px chevron that rotates without shifting the title. City names are group headings or sticky labels inside the partition, not another disclosure layer. The bounded result owner retains touch/wheel/keyboard scroll and restores useful position while hiding scrollbar chrome. Empty/no-results, stale-summary, partial and dynamic-provider failure states preserve static spot/favorite identity and expose a safe recovery.
- Activating a Finder result closes the Sheet, recenters the existing map only as needed, commits the one selected formal spot and opens the same compact callout. It does not enter `spot/detail`; only a later valid callout press-out, keyboard or accessibility activation navigates. The selected marker/callout receives non-color-only feedback and the callout becomes the logical focus target.
- The ordinary base map is not a layer choice. Formal-spot markers are the default point collection. At normal text size the compact header, one Search row, map origin and bottom navigation fit the usable phone viewport, and the map fills the remaining height so the user can compare points without first scrolling past an analysis panel. `map-analysis-time-bar` is the user-facing `观测条件` Bar, floats inside the map and uses a Tier-A condition/instrument symbol rather than a Favorite/star metaphor. It exposes only the current layer, one key metric/state and local time; it is not a second Search/layer tab row. Activating it opens `map-analysis-focus-layer` through `SourceLiftFocusLayer.mapCoupled`. `map-layer-selector` controls at most one colored analytical raster/forecast overlay at a time so incompatible legends are never blended.
- `map-time-control` owns the shared `ObservationContext.selectedAt` inside the analysis focus layer: exactly one visible current local date/time value, direct scrub preview, compact metrics and map feedback remain together. The slider retains its programmatic value without rendering duplicate hero, helper or input copies of the same selected time. The upper observing-condition control surface must compact/reflow rather than acquire an internal vertical scroll; its quiet close action uses one 44px transparent hit region around an optically centered 18–22px `×`, without a visible oversized button box. MapScene supplies one viewport-bounded compact timeline projected by the BFF from the same per-spot hourly SkyReport truth: each frame contains per-spot cloud, moon and selected-time SkyOpportunity signals, plus polygons only for the requested dynamic layer;
  static layer metadata is not duplicated per frame. Dragging updates the displayed time, frame polygons, metrics and dependent point summary immediately without a request or client-side weather/opportunity calculation; valid release commits the sole Observation Context and may prefetch/request the new window, while cancellation returns to the last committed value. Activating the date/time may open one precise picker using the same state. `LIGHT` is source-dated/static for its declared period and is visibly described as such; `TOTAL_CLOUD`, `OPPORTUNITY` and dependent point summaries may change with selected time. A static layer must never animate fabricated hourly change, and a whole-night TripDecision must never be presented as the selected-time condition.
- `map-marker-card-coordinator`, `map-selected-spot-callout`, route context and accessibility list expose one selected formal spot. The first valid marker activation selects and opens the compact callout. The callout contains only the spot name and a small comparison set such as light class, parking availability, distance/drive estimate and tonight observing condition; its press-in boundary changes immediately, and only a valid press-out/keyboard/accessibility activation enters `spot/detail`. Drag-away, map-pan competition, cancellation, disablement or invalid release does not navigate.
- Direct map input is pan, pinch and tap. The Finder result list provides the non-gesture point-selection alternative. The map does not render persistent left/right pan arrows or `+`/`−` zoom controls; automatic camera movement cannot fight a user-initiated pan.

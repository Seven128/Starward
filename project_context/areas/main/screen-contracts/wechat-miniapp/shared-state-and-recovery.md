# WeChat Mini Program Shared State And Recovery

This on-demand subdomain node normatively continues shared manipulation, accessibility, Settings, import, notification and recovery invariants across Mini Program Surfaces.

## 公共按压与来源入口：2026-10-22采用

按[当前局部采用源](../wechat-miniapp.md#stitch-design-authority)，`shared-button-press`是按钮的共同反馈责任，覆盖圆形图标、文字动作、整行/卡片与相应Sky时间按钮等真实消费者；不取得导航、长按连发或业务状态的所有权。立即按下反馈，合法释放执行原动作；滑出/滚动/取消/隐藏复位且不触发，禁用不假按压，加载保几何并防重复。圆面轻内凹/明度变化和图标轻压，文字布局与命中区不缩；卡片/文本使用同族轻反馈，保原选中/想去动效和主题素材，不为公共反馈重绘Map/Sky。精确值在DESIGN及资源，生产共享实现和真实效果尚需完成。

原生 Picker 的既有 View 触发面由同一 owner 的 `PickerTrigger` 复用公共按压，供计划地点/日期/时刻/交通、贡献日期与回顾年份使用。它仍输出原 View，不增按钮、包裹层、定时器或手势状态；Picker 继续持有值、选择/取消、禁用与 onChange，触发面跟随相同禁用条件撤下反馈。文字、图标、命中盒和原布局保留，不能以普通 Button 的源码清单代替这些触发面的目标交互验收。

`data-source-disclosure`沿已有来源/许可责任供层叠、月相/气象/夜光/地形及点位其他来源消费者复用；首层小按钮，深入内容按当前来源身份显示与复制，返回保选择和正文位置。必要署名、缺失/过期/警告/失败状态不得仅藏进来源。地图Terrain Tiles、点位Copernicus GLO-30、QWeather、EOG及Astronomy Engine保持独立来源和事实；不以统一按钮拼出假来源或新增数据。

## Map/My有效前台与返回

Map/My 的有效前台由既有 `navigation/primary-navigation-controller` 与 `primary-page-navigation` 共同持有：普通Map入口保留同一物理Page/Map节点，以独立全屏My表面左入左出；`pages/my/index`保留原生直达包装，两者复用唯一My正文，原生子页和来源仍实际push/back，不新增全站路由历史。`page-presentation`只提供前台资格、逻辑activation及辅助Back登记，业务状态/查询仍归原owner。切换主目的地退休旧意图；原生子页或已知系统选图的hide/show保留同一activation，前台权限与保留身份分别判断。Map的现有hide清理、My时钟/查询、账户操作、导航及通知消费该边界；My完全左出后才恢复Map交互。My编辑/照片/登录向当前唯一`NativeBackBoundary`登记，一次Back先关当前任务；Map-host不另挂第二个PageContainer。此为实现责任，方向、原生地图合成、物理Back及系统返回仍需目标WEAPP验收。

## Shared observation-time resource


The [shared date/calendar/ruler resource](https://stitch.google.com/projects/7144519510537620825) owns the adopted reusable browser composition and demonstrated motion for the consumers linked from current page entries, within those entries' theme/state scope. Date, slicing and commit semantics remain with the relevant Map and Spot/Sky contracts; production uses the existing Taro component and Observation Context owners. Consumer pages follow this shared owner rather than redeclaring the same resource. Its browser implementation is not WEAPP verification.

`ObservationDateControl` 默认维护日历的原生返回层；同页已有统一弹层返回 owner 时，消费者以 `nativeBackBoundary=false` 交回页面管理。云观星以页面唯一 `NativeBackBoundary` 同时处理日期、天体详情／重叠候选及列表、时间、校准、图层披露，不能叠挂多个 PageContainer；日期内容和选择仍由公共组件负责。日间日历保留共享采用稿的暖色选中材质，夜间与红光选中日期沿既有 `choice-selected` 表面、边框和文案角色，不把日间亮色 fallback 用于深色主题；两处 Map 消费者继续共用该呈现责任。

`NativeBackBoundary` 持有自定义呈现的原生返回层、单次 leave 委派、确认期间去重及存活时重新布防。辅助层只在活动时以show=true新挂载；消费后卸载，调用者仍活动时下一task新挂载。Map 复用其既有全屏原生前景容器变体，持续保留事件 Modal 子树并使用beforeleave协议；Map的布防资格只取主导航同一快照的nativeVisible/foregroundRoute，My closing没有前台owner，必须先退休旧代，不能由滞后的Map内容可见状态继续授权。Map每次show都须在当前shown generation收到原生afterenter后才接收业务Back；active、native hide、消费或卸载立即撤销确认，程序化退场及未完成入场的leave不得降档或关闭保留面板。消费后同时等待命令结束与原生afterleave再重新显示，到新的afterenter才释放周期去重，不以定时器先到代替原生退出。两者共享命令存活和代次守卫，hide即时退休旧回调，即使hide/show发生在React提交前也不复活；返回优先级和关闭确认仍由调用者持有，嵌入表单将媒体交接返回也交给 Map。异步委派失败不泄露错误细节，卸载后不重新布防；各设备系统Back及键盘行为仍需真实目标证据。

Map 的云量与正式点日历共用页面持有的打开身份；公共日期组件均交回 Map 唯一原生返回层。日历先于底层图层关闭或点面板降档，日期忙碌时消耗返回而不误退父层；换号、重置、页面隐藏、呈现/地点/Context 替换退休旧打开身份。Map 的原浮动通知宿主仍留在同页，按实际日历 sheet 顶部限制其顶部滚动区域；未取得当前几何时没有浮动命中面积，消息队列与原行内恢复保留。迟到或已退休的几何不供新日历使用，未见通知继续沿共享可见计时责任。

云观星在地点、时刻、时区和活动 Context 的既有完整性校验通过后，才通过共享 `observation-date` owner 派生民用日期及日期选项；待确认或无效路由不提前调用时区格式化，以免在既有 Context 恢复内容呈现前抛出异常。日期选项的 memo 同时跟随完整性状态和时区，保证同区 Context 查询完成后刷新正常选项。没有猜测默认时区或新建另一时钟；代码/日期消费者检查不等于原生恢复界面已验证。

Production MapTimeRuler and Sky OrientationTimeRuler share `components/scroll-settlement.ts` for user-scroll completion. Only a user-started, actually scrolled sequence can submit; after release, native momentum must settle before one commit. A missing native scrollend cannot leave an indefinite preview, and a late end signal cannot replace the newest scroll position. Multi-touch, cancel, hidden/unmounted pages, disabled state and changed input identity discard pending work. `components/ruler-scroll-position.ts` owns explicit enhanced ScrollViewContext positioning for snap/cancel, including return to an unchanged committed tick; regrabbing or leaving invalidates pending native queries. Continuous scroll events update preview without driving native scrollLeft back on every frame. Date/time identity, persistence and failure recovery remain with each existing observation-context owner; this shared mechanism does not merge their data axes.

Map的云量尺与正式点天文尺在同一观测身份等待新Scene时，只保留禁用的时间刻度/月相呈现，不回填旧天气事实或调用旧数据命令。身份包含账户、Context、观测夜、时区、天气策略与算法；新Scene查询无数据的失败、真实空响应及身份变化撤下旧轴；仍有有效缓存的刷新失败沿用原陈旧可用语义。正式点时间呈现可使用同点且未退休的已确认参照，避免请求Context短暂恢复使控件卸载；日期和时刻操作仍由实际活动Context控制。两尺的可用切片、等待/失败/真空含义与重试属于Scene，天文资料成功不代表Scene成功。有限WEAPP轴保留与失败恢复观察不认证正文位置、完整动效或真机连续验收。

账户删除的本机收口由账户 API 调用既有 `app-store.resetAfterAccountDeletion(deletedUserId)`，清理回执中已删除身份的命名恢复快照及明确属于该身份的当前快照；当前投影属于后来账户时保留，未归属/隔离数据不能被推定为已删除身份。草稿、响应缓存和 QueryClient 均按已删除身份清理；缓存等待后复核身份与 pending 登录，不执行全局查询清空。删除确认与缓存终态先读取不改变状态的 native/store 归属，明确后继账户即使凭证过期也不能被 A 的会话读取解绑，或被认作本次成功清空。当前账户成功清空后，API/session owner 保留该动作读取的精确 installation 清理意图；pending 登录存在时不阻塞删除结果，在每次登录 finally 释放自身 pending 后再次核对。后继 native/store 身份或 installation 值改变即退休旧意图，未知槽及读取失败保守保留；旧登录终态不能清理新的 pending。本机清理未全部确认与服务端删除成功分别报告。原生 auth 槽仅明确归属已删除身份时移除，读失败或非空未知槽保留并标记本机清理不完整；已删除身份仍被会话 owner 拒绝，后继未知身份登录按真实返回身份判断，不能无条件取消。服务端成功回执始终保留，本机清理或同步观察者失败不能改报未删除。设置页拥有不可复活的删除 ticket，只接受 API 同步确认的本动作成功清空身份；外部离开账户（含返回原账户）、hide/unmount 退休结果，原生弹窗终态后再次复核才导航。真实处理器的端口回归不证明微信删除/换号、真机持久化或冷启动保全。

设置清理缓存沿用既有 API 临时响应/查询与 app-store 本机状态两个 owner，并发启动且等待各自终态，正常与部分失败反馈保留。Settings 持有本次页面/账户结果 ticket：任意账户离开、hide 或 unmount 永久退休，返回原页面/原账户不复活旧反馈或失败滚动；已启动清理继续完成，mounted 时解除动作锁，卸载不更新 React。现有本机持久化账户围栏保留后继账户状态，这次页面结果修复不扩张缓存删除范围、不清远端或草稿，也不以端口回归认证手机清理。

账户删除的服务端成功回执与本机清理结果分开：已收到成功回执后，“重试本机清理”只继续原清理，不重新认证或再次 DELETE；后继账户和新安装身份仍受原 API/session owner 保护。偏好首次尚未确认与有旧值但刷新失败分别呈现，未确认时不能把默认值冒充已保存的账户选择；后续恢复仍由既有偏好合并规则负责。

- 并发口径暂按**同一用户 × 同一正式观星点**最多一份审核中反馈；其他用户可以提交各自的反馈。服务端必须原子约束，不能仅前端隐藏入口。用户尚未明确全站互斥；此处为当前实现假设，不声称全站锁定已获确认。
- 开始编辑后正式版本若改变，提交应返回版本冲突并保留修改，重新核对后再提交，不能悄悄覆盖。审核期间冻结记录不随正式点新版本重新回填或重算差异。
- 审核未通过后的回填、重提、新旧批次与最新正式版本冲突，统一遵循 [观星点创建与反馈](map-and-finder.md#观星点创建与反馈)，不新增另一套反馈表单。小程序“本次修改”不是观星点版本历史，后者仅由后续管理后台展示。
- 审核、合并与公开发布仍是不同职责。通过后由现有服务合并可归属证据并执行发布校验；其他用户只读取已发布正式版本。驳回/待补充/撤回等后续状态按服务端回执展示，审核中限制随真实终态解除；不在此设计演示里自动通过审核。
- 新增草稿为拥有者可见的多记录远端资料，手动保存和地图入口遵循 [Map](map-and-finder.md#新增观星点)。提交新增时从草稿转提案并冻结；提交反馈时冻结正式 baseline + 修改，不产生新增地点草稿。两者复用现有认证、媒体、幂等及 moderation owner。

正式反馈页沿原编辑 owner 已确认的提交／可重提模式，在 `CustomNav` 标题右槽呈现审核中或审核未通过；普通编辑、账户归属变化或没有完整编辑内容时不发布审核标记。审核意见与正式 baseline／接受差异仍留在原正文，重提动作显示“再次提交”。提交成功和待审记录回填沿当前记录回执同步审核意见，不能将上一轮未通过意见展示为新待审批次意见；历史意见仍由冻结 attempt 保留。标记采用当前标准 metadata 12/18及现行采用源的主题角色；不再由正文绝对定位模拟标题状态。共享 `CustomNav` 由右槽内容自身宽度保留空间，新点独立编辑页不再覆盖槽位列定义；正式反馈标题沿采用资源左对齐。提交、冻结、取消离开与同记录重提仍由原 owner 执行。

远端草稿回填由既有 contribution 表单 owner 用同一可编辑字段、intake 和媒体投影更新本机已保存基线；数据库对象属性顺序及兼容旧字段的投影不会产生未保存修改或虚假的本机恢复副本。真正的后续编辑仍进入原离开确认与本机恢复职责，不改变账户隔离、手动远端保存或提交规则。

创建与正式反馈的未知提交在完整表单顶部保留只读核验入口，原字段、照片及提交底部同时冻结。各自 `submission-result-client` 通过既有 `api-client` transport/session/account scope 调用受认证的 submit-result GET，以原账户、原标识、原 subject 和操作类型读取精确回执，再分读 FRESH 当前记录或当前正式 baseline；旧回执不回滚最新审核状态。普通创建的恢复标识继续由 `contribution-submit-retry` 持久化，正式反馈保留当前页的原 intent，离开不声称取消请求或承诺冷启动恢复。GET 未找到回执仍是未知，只在此后提供明确“重试原提交”，沿用同一个 key/id/revision 或原 formal body，不保存修改、不生成新标识。实际发送、权限续期、缓存失效与账户退休仍归原 service owner；前端需要包含这两个新增 GET 的服务，旧服务不可用时保留未知，不用 POST 回放冒充查询。

创建编辑的自定义返回和地图内关闭沿同一离开确认职责：取消保留当前输入。DAY 正式反馈及新增独立编辑的右侧关闭呈现复用 `CustomNav` 原返回执行、授权交接与失败恢复；其他调用者保留默认返回呈现。启用本机恢复的独立编辑页在明确放弃后，由本机恢复 owner 清除并退休该次输入，后续计时、隐藏或卸载不能重新写回；清除失败不授权离页，同页后续新编辑仍可进入本机恢复。地图内编辑沿原禁用本机持久化规则；两入口均不推进或删除远端保存基线。系统返回提示的真实平台回执和操作仍单独验证。

创建/反馈记录列表不读取、改写或删除编辑表单的本机恢复副本，不被列表中不可见的待恢复输入阻止返回；继续编辑进入原独立表单后仍由表单负责恢复和离开确认。
## 2026-10-15 登录、消息与加载的补充要求

本次新增视觉范围限于云观星内部以外的真实消费者；云观星入口保留，内部仍沿其原采用与实现责任。

用户要求可见的微信快捷登录组件，采用轻量、可关闭的表达，复用已有微信会话链。不增加手机号、头像或定位前置，不伪造微信系统权限窗；未确立账户时不展示假的私人记录。新增视觉已获用户认可，当前资源与消费者由[完整场景入口](https://stitch.google.com/projects/7144519510537620825?node-id=5205988829884632961)（源包内 `shared/real-scenarios/README.md`）及各页ADOPTED管理。生产是否尊重主动登录与访客选择须由既有api-client/账户查询owner落实，不能只新增入口而由背景请求抹掉用户选择。导出、删账户等原同身份再核验边界保持。

普通Map无数据沿既有顶部浮动通知责任，点击或自动退场，不保留又大又无有效信息的常驻卡。真实失败仍在相应入口保留可用恢复控制。各真实加载/处理消费者须复用公共加载图形与状态，完成、取消、隐藏或卸载按owner停止，减少动态效果提供静态表达；不造百分比或把已有独立内容全部遮住。当前资源采用三点作为内容/普通按钮等待、短弧作为小按钮等待，由同一状态视觉owner呈现；既有共享通知可见计时与生命周期规则继续控制生产实现。设计原型的可点击终态与capture固定示例不代替微信回执、真实持久化、实际业务功能或目标运行验收。

公共等待图形由 `components/loading-indicator` 呈现，`StatusPanel` 与 `SoftButton` 消费实际等待状态，业务锁、取消和结果确认仍由原请求 owner 控制；页面隐藏暂停装饰动画，减少动态效果静态显示。普通无动作浮动通知整条可点关闭，仍复用原队列、可见计时与当前页面宿主；附恢复动作的通知保留独立操作。Map 真空只发布短消息，原生地图和观星点请求失败保留各自重试；地点资料的显式取消即时退休该次回执，与可被图层切换打断的普通面板关闭分别处理。云观星内部继续使用原通知和等待表达。My昵称/头像弹层沿上述有效前台及唯一Back责任恢复；旧TabBar cover已退休，照片native chrome与实际编辑/取消保护继续由原owner持有。

快捷登录由 `components/wechat-login` 与页面级 `use-wechat-login` 复用真实微信会话；可关闭及离页取消，权限读取、微信 code、服务回执和原任务继续均受同一意图约束。`api-client` 的访客门禁阻止后台建立身份，显式登录在微信能力未开启时不退回安装身份；既有同身份续期、删除与草稿围栏保留。账户绑定将旧观察编辑的退休与新身份一次性发布，避免半绑定通知。直接私人路由由 `content/account-entry` 在首次入场前阻止编辑器挂载，后续编辑/续期仍归原表单 owner；公开 TOKEN/SPOT 接收不加门禁。My、Map、设置私有动作和正式点消费者复用这一责任，Map/Settings 各保留自己的唯一原生返回层。

一次定位与登录分别执行。Map 取得有效坐标后保留原视口，由用户明确“移动到本次位置”才应用；取消、后来地图意图、隐藏、换号或重置退休旧结果。Settings 的使用偏好仍是 ASK_ONCE / MANUAL_ONLY，不冒充系统授权；其明确定位或权限设置动作通过当前 opener 的一次 EventChannel 进入原定位页，普通路由或 URL 参数不触发 GPS。发起页面与接收页面各保持身份、地图重置代及生命周期围栏，正常导航隐藏允许有效交接，过期发起者不能在新身份下继续。微信设置返回仅回读权限，不把允许当成已获得坐标。

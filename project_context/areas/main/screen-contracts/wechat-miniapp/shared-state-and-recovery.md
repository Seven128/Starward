# WeChat Mini Program Shared State And Recovery

This on-demand subdomain node normatively continues shared manipulation, accessibility, Settings, import, notification and recovery invariants across Mini Program Surfaces.

## Cross-Control And State Invariants

- A continuous manipulation, its current value and the primary visual or numerical feedback it changes remain together in one mobile viewport or one bounded control-owned scroll surface. A journey never requires scrolling away from a control, manipulating it and scrolling back to inspect its primary effect.
- When direct co-location cannot satisfy that invariant, use one self-explanatory functional trigger plus the named `source-lift-focus-layer` family or a native Modal with the same ownership. A dropdown inside an active focus layer is an anchored disclosure owned by that layer, not another Modal: it overlays rather than reflows owner geometry, owns bounded overflow, closes before its parent and remains mutually exclusive with sibling disclosures.
- An icon may stand alone visually only when its platform convention and meaning are unambiguous in context; every icon-only control still owns a programmatic accessible name, role and state. Otherwise the trigger pairs icon with concise label. Secondary explanation, when genuinely necessary, is explicitly operable and never hover-only; the current product adds no generic `?` control for tutorial, implementation or data-pipeline prose.
- Mini Program component/icon implementation follows one Build / Reuse / Buy boundary. The existing `SemanticIcon`/`semantic-asset.tsx` adapter remains the sole production icon extension point; the preferred reusable generic UI source is a pinned, license-recorded and per-component imported `@taroify/core` release behind shared Starward adapters. One ConfigProvider/CSS-variable projection maps the current DESIGN tokens and density while Product Surface controls, `app-store`, route/presentation coordinators, form draft, upload transport/idempotency and validation policy remain the only semantic owners. `@taroify/icons`, library brand defaults, runtime CDN assets, a second UI suite and a parallel library form store are forbidden. Product-specific moon-phase, horizon, galaxy, radiant, celestial mode glyphs and every selected/favorite rounded star remain bounded project assets through the same icon adapter.
- Component mapping is explicit rather than aspirational: `Tabbar` underlies the Map/My shell; `Search`, `Cell.Group`/`Cell` and `Checkbox.Group` underlie the Search field/suggestions/filters; `Popup` underlies the fixed layer sheet; `Sidebar` and `Button.Group`/`Button` underlie the compact rails; `Radio.Group`, `Cell.Group`/`Cell` and ordinary `Switch` underlie Settings/My; and `Form`, `Form.Item`, `Form.Feedback`, `Field`, `Input`, `Textarea`, `Radio.Group`, `Checkbox.Group`, `DatetimePicker` + `Popup`, `Uploader`, `Progress` and `Button` underlie Contribution. `Toast` is allowed only when `notification-feedback` already calls for short transient acknowledgement. The design-resource viewport never displays this implementation mapping.
- The spot panel may reuse Taroify `FloatingPanel` anchors/scroll mechanics with `contentDraggable=false` only after a real WEAPP compatibility spike proves the exact `104×40rpx` header-only drag region, same-document identity, nav-safe max height, three extents, interruption and nested-scroll arbitration. A failed proof falls back inside the same adapter to Taro enhanced `ScrollView` plus the existing panel coordinator; it does not authorize a library fork, a larger drag region or changed semantics. The raised arrowless curved time ruler always reuses Taro/WEAPP enhanced horizontal `ScrollView` scrolling, hidden-chrome and end-event primitives while a bounded project layer owns curve projection and real-slice snap; Picker/Slider or React-Native-only ruler families are not equivalent. The three-state mode track may reuse `Radio.Group` selection semantics but not a binary Switch. Image-backed layer choices use local generated/self-owned assets through the current asset pipeline, never runtime remote imagery.
- `display-mode-switcher` is the sole Settings owner for `day | night | observation`, defaults to day, preserves route and content state, and consumes tap, adjacent horizontal drag, keyboard and direct assistive selection. The former `observation-mode-control` is retired rather than rendered elsewhere. Day-to-night may animate its Sun/Moon and track; night-to-observation binds the closed black/warm-red target tokens atomically before its Moon/Star transition so no disallowed intermediate hue appears. The information panel and orientation route consume active presentation but do not own another entry or mode store.
- Settings presents the unified three-state display mode first, then permission/privacy and reminder ownership before data actions, with secondary spot-selection and accessibility preferences reachable below. Its celestial track remains one single-choice control, not day/night tabs plus a bottom observation CTA. `nearby-location-preference` writes `ASK_ONCE | MANUAL_ONLY`; orientation access and precise contribution coordinates remain per-use controls rather than durable grants. `departure-condition-reminder` and `contribution-status-reminder` are revisioned identity-scoped intent fields; UI acknowledgement says only that intent was saved and never claims WeChat subscription delivery without a receipt. `account-data-export` consumes a server-generated identity-scoped versioned snapshot and exposes a real platform file/share result; it cannot compose authority from local cache. `account-delete` requires explicit destructive confirmation, an idempotent server receipt and session-invalidating readback before local reset.
- `profile-link-open-copy` always retains Copy when Try Open is gated, denied or fails. URL save/open rejects dangerous schemes and invalid destinations without losing the draft. Import controls preserve edited fields across parser failure/retry. `import-spot-association` treats `spot_id` and `spot_proposal_id` as disjoint; proposal submission never creates a formal point before review.
- `miniapp-contribution-intake` retains one form/document identity from either Panel or My entry. Inline validation is inserted only for the affected field and submit focuses the first invalid control without resetting route scroll. Existing-spot reports never mount or request new-place location controls. Upload and submit state changes are local, interruptible and preserve draft, media identity and the same idempotency key across transport failure/retry; only a durable pending receipt may replace the editable submit state. A sticky final action, if used after native keyboard/safe-area proof, owns one lane and an equal scroll inset and cannot coexist with another submit control.
- `notification-feedback` is the sole shared presentation family for user-visible permission, stale, offline, provider/recovery and otherwise invisible acknowledgement feedback. Visible local state is sufficient feedback for selection, filter, panel extent, disclosure, navigation, favorite success, time scrub, layer and mode; those actions do not also enqueue toast, snackbar or modal. Field validation stays beside its field. `inline` participates in the affected owner flow only when permission, missing/partial/stale/offline data or failure concretely changes the current decision, action or recovery; it names the affected fact and consequence instead of displaying a generic “部分数据”/implementation-status badge. It never auto-dismisses the sole recovery path. Complete provenance and freshness stay reachable through their existing disclosure without becoming a permanent explanatory row. `floating` is reserved for one short asynchronous completion, copy/save acknowledgement or undo whose result is otherwise not visible; it overlays inside the safe area, does not alter page/Map/panel/SourceLift/scroll geometry or steal focus, and cannot cover the primary action.
  Both placements share compact icon/title/optional-body/at-most-one-trailing-action/optional-dismiss anatomy, named 44px actions, non-color-only severity, stable-geometry state-swap motion and reduced-motion substitution. A transaction creates at most one floating acknowledgement. A local owner renders at most one full notification, deduplicates by owner/transaction/recovery identity, and uses deterministic `error → warning → info → success` order plus an accessible residual count. Screen readers announce commits, material state changes, failures and recovery only—not pointer, panel drag or ruler intermediate frames.
- `page-state-recovery` is the shared recovery family for INITIAL/LOADING/READY/EMPTY/PARTIAL/STALE/ERROR/PERMISSION_DENIED. It never substitutes realistic fake values for missing data and never hides usable static content because a dynamic layer failed.

## Responsive, Density, Motion And Accessibility Contract

- The production surface consumes the 750rpx target with 320/375/390/430 CSS-pixel checks, safe areas and 100%/200% text conditions. Compact-but-clear density is a hierarchy rule, not uniform scaling: page titles, section headings, body, supporting values and metadata use the smaller exact current Design Authority roles, while Search partitions deliberately remain body-level. Ordinary content first removes non-useful titles, dividers, explanations and surfaces, then uses aligned axes, weight, restrained role-colored semantic-icon tiles and dividers before card containers. Visible icons/surfaces may be compact while every actionable semantic target remains at least 88rpx/44px. At 200% text, information reflows, layer cards and My utilities may reduce columns, progressive content remains reachable and floating overlays avoid covering the focused object.
- Map contains only its floating Search entry, map controls and the single current bottom presentation. Search activation keeps the field's exact visual geometry and rendered text stationary while compact suggestions/filter/results reveal beneath it. The panel retains one objective document tree across small, medium and large, using extent only as a crop; valid media is pulled out first during medium-to-large, then Search/location/layer chrome fades only near the screen top. Without media a compact handle band remains through drag; with media the handle overlays the image. The floating section rail has no vertical inner gaps and the lower action pill uses the smaller current geometry. Ordinary unavailable values display `暂无数据` without collapsing distinct recovery states.
- Every actionable control has a programmatic name/role/state and non-color feedback. `spot-search-filter-choice` uses a compact visible capsule inside the stable 88rpx hit region. Prefix icon and label remain in ordinary flow. The selected star ornament is a larger rounded pale-yellow shape with controlled translucency, absolutely layered over the trailing label area without allocating width, moving text or changing border geometry. The label must remain legible beneath/around it; selected border/fill, icon/label and checked state remain independent signals. Selection and deselection use an explicit interruptible scale/rotation/opacity state change that starts from the live presentation; reduced motion uses only short opacity/color change. Observation retains geometry and maps every role into the closed warm-red palette rather than preserving yellow.
- Every mobile scroll owner hides vertical and horizontal scrollbar chrome without disabling touch, wheel, keyboard, programmatic or screen-reader reachability. Page-level horizontal scrolling is forbidden except an explicitly owned row, matrix or curved time ruler. The ruler is raised, has no visible arrow controls, retains an 88rpx manipulation lane, and must translate its real track under horizontal touch/pointer drag before snapping to a real cadence slice. Programmatic step alternatives remain available without arrow chrome.
- Contribution uses the same density hierarchy: simple fields are 88rpx-target divider-backed label/value rows, complex fields are top-label groups, and 200% text converts rows to stacks. The only persistent spacing is between real groups; helper/error text, upload recovery and location/rights explanations exist only when applicable and never reserve empty height. Media reduces from three to two columns where needed, the keyboard cannot cover the focused field or sole submit, and page-level horizontal scrolling remains forbidden.
- Panel/ruler/map gesture arbitration waits for directional intent, selects exactly one owner and does not transfer mid-gesture. Only the small long information-panel handle rectangle can initiate extent manipulation; pointer down or a sub-threshold tap cannot commit an extent. All direct manipulation is interruptible and retargets from live position. The Map bottom owner is exactly `none | spot-panel | layer-sheet`; it cannot expose two active states, and a marker intent while layer is open retargets directly to the new medium panel. Search/media phases, the three-state mode thumb, ruler drag, layer dismissal, disclosure and My flow use causal motion from live presentation rather than remounting or queued timeouts.
- Day/night/observation retain semantic-role parity. Observation is a closed black/warm-red palette; media is opt-in, skeletons cannot flash white, and system/native boundaries avoid an unowned bright transition.

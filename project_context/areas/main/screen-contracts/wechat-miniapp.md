# WeChat Mini Program Screen Contract: Starward

## Authority And Product Boundary

- This Context owns the durable route, region, Control, state, navigation, interaction and accessibility responsibilities of the independent WeChat Mini Program delivery. Product and technical meaning comes from the immutable V2.0 product/technical plans indexed by `docs/wechat-miniapp-v2-source.md`; exact visual values come only from `DESIGN.md#wechat-mini-program--soft-instruments-v1`.
- The formal handoff `docs/design-resources/miniapp-selected-handoff-2026-08-06/miniapp-complete-product-selected-v1.md` and its complete frozen resource closure are selected `reference + constraint` inputs. They do not prove production conformance and cannot replace this Screen Contract, the V2.0 plans, or runtime checks.
- The Mini Program is an independently completable product carrier under `apps/wechat-miniapp/**`. It does not replace, prove, or inherit the native React Native App. Shared domain/contracts/adapters may be reused only through their declared boundaries.
- Primary navigation is exactly Map and My. Night Sky has no global destination and is reachable only from a formal Spot Detail context carrying a valid `spot_id`. An ordinary POI or current location cannot synthesize that context.

## Route And Package Ownership

- Main package: `pages/map/index`, `pages/my/index`, `pages/auth/index`, permission rationale and error/recovery pages. Only Map and My appear in the persistent primary navigation.
- Spot package: `spot/detail`, `spot/guides`, `spot/field`, `spot/sky`, `spot/photos`, and `spot/data-source`. `spot/detail` owns the fixed header and Overview/Guides/Site content contract; `spot/sky` is its explicit child page rather than a global destination or an in-place replacement panel. Every detail section and the Night child preserve the same formal `spot_id`.
- Sky package: `sky/detail`, `sky/map`, `sky/observe`, and `sky/targets`. Every entry is delegated by `spot/sky` with the same `spot_id`, date/time, timezone and data/algorithm revision; missing or invalid `spot_id` fails closed.
- Content/user package: `article/detail`, `plan/detail`, `profile/links`, `content/import`, gated `submission/*`, and `settings/*`. Routine favorite browsing is the Finder `想去` partition rather than a separate My/Favorites route.
- Deep links activate the owning Map or My root before entering a subpackage route. Back closes route-owned overlays first, then pops the subpackage stack, and never invents a third primary destination.

### `miniapp-spot-detail`

- Primary question: Is this named formal spot suitable, reachable, trustworthy and safe tonight?
- Main surface owns: a fixed identity/header action hierarchy with the spot name, a visually borderless Favorite icon state inside its full accessible hit region, and a distance/route row with one quiet trailing `去这里 →` text action rather than a filled block; Overview/Guides/Site content with an animated segment indicator/content handoff; representative media first with source/license/site status; hard-blocker-aware Tonight conclusion; route/facility/provenance evidence; plan actions; and one explicit child-page entry to `spot/sky`.

### `miniapp-spot-night`

### `miniapp-my-library`

### `miniapp-profile-content`

- Primary question: How can the user manage external profile links and import their own stargazing post while preserving rights, lineage, moderation and point identity?
- Main surface owns: neutral external link records, URL validation and copy-first fallback; `SOURCE → EDIT_DRAFT → ASSOCIATE_SPOT → PREVIEW → SUBMIT`; rights attestation; manual import; parser/license gates; editable draft protection; formal `spot_id` association or independent `spot_proposal_id`; moderation and EXIF/location sanitization.

## Cross-Control And State Invariants

- `mini-primary-navigation` owns only Map/My. My has no second tab set: `my-account-header` exposes the title and one named 44px Settings gear action, `my-profile-summary` owns login/account state, and `my-grouped-entry-list` contains only a limited number of routine rows. `my-plan-entry` pushes `plan/detail`; `my-settings-action` pushes `settings/*`. Back restores the My root's useful scroll position and the logical opener focus. - `map-spot-finder-trigger` is the sole Map entry for browsing, search, filters and favorites. It opens `map-spot-finder-sheet` through `SourceLiftFocusLayer.panelOnly`: the source bar lifts to the fixed safe top and becomes the `查找观星点` expanded/collapsed toggle with an optically centered 18–20px chevron that rotates without geometry change. The header itself is the Finder's explicit toggle/close route; there is no sibling `×` or second Finder title. Scrim, Back and Escape dismissal, keyboard/safe-area handling, contained focus and opener-focus return remain owned by the layer.
- `map-finder-search-field`, `map-finder-query-overlay` and `map-finder-filter-disclosure` derive one result projection. The field owns a conventional Search symbol only when that cue is not already visible in the lifted `查找观星点` source header; the focused Finder composition therefore exposes exactly one visible Search glyph. Its history/fuzzy-suggestion overlay is geometrically anchored immediately below it, above the existing result surface. Focus entering the field may reveal the overlay; focus leaving the field-plus-overlay group fades and closes it on the target state-swap timing, while pointer/keyboard suggestion selection commits before blur dismissal. Choosing a suggestion or confirming a query updates query/results and never enters Detail. Search and Filter disclosure remain separated by the owning spacing rhythm. The filter disclosure opens one mutually exclusive anchored `map-finder-filter-overlay` without creating another dialog or changing the main Finder scroll geometry, with a visible spacing gap between the disclosure row and overlay. The exact 18 terminal choices use an adaptive compact grid of visually uniform items rather than a permanently fixed two-column wall; long labels reflow/span while compact typography is preserved and every item retains its full 44px hit region. The bounded Filter owner may scroll when required, but hides scrollbar chrome without disabling touch, wheel or keyboard reachability. Opening the editor snapshots the committed set into one draft. When and only when the draft differs, the disclosure row exposes programmatically named revert `×` and commit `✓` actions whose vector glyphs are optically centered inside circular 44px targets and carry non-color-only names; revert restores the opening snapshot and commit atomically replaces the committed set. The bounded result owner retains touch/wheel/keyboard scroll and restores useful position while hiding scrollbar chrome. The selected marker/callout receives non-color-only feedback and the callout becomes the logical focus target.

At normal text size the compact header, one Search row, map origin and bottom navigation fit the usable phone viewport, and the map fills the remaining height so the user can compare points without first scrolling past an analysis panel. `map-analysis-time-bar` is the user-facing `观测条件` Bar, floats inside the map and uses a Tier-A condition/instrument symbol rather than a Favorite/star metaphor. ## Responsive, Motion And Accessibility Contract

- The production surface consumes the 750rpx target with 320/375/430 CSS-pixel checks, safe areas and large-text 2×2 fallbacks. At normal text the Map first-viewport budget keeps the header, one Search row, usable map and bottom navigation visible together; enlarged text may reflow summaries to `+N` but cannot eliminate a usable map or hide close/commit/revert actions. The focused observing-condition controls must reflow/compact at every supported width and large-text mode without internal scrolling, clipped controls or a second visible selected-time value. Finder/filter/result and page owners may retain bounded vertical scrolling for reachability, but all user-phone vertical scrollbar chrome is hidden and consumes zero layout width. Page-level horizontal scrolling is forbidden; only an explicitly owned bounded row or data matrix may scroll horizontally. When such a horizontal indicator is necessary it overlays rather than consumes layout height/width and uses a white semi-transparent treatment legible in the active mode.
- Every actionable control owns at least an 88rpx/44px hit region, has a programmatic accessible name/role/state, communicates selection/risk with more than color, and has a keyboard/accessibility-list equivalent where the native map/canvas is not directly operable. Card-like choices in Finder filters and Observing Conditions share one selected decorator: a rounded rainbow-gradient star clipped approximately halfway by the top-right boundary, plus selected border/state semantics. In observation mode the same geometry uses only the closed warm-red palette; the programmatic selected state, border and/or check meaning remain sufficient without color.
- Notification content height is driven by its actual compact content rather than fixed empty space. At 320/375/430 and large text, title/body/action reflow without clipping, oversized controls or horizontal overflow; a floating notification retains invariant owner geometry, and a single inline notification must preserve a useful primary surface rather than replacing Map/content with blank space. Day/night/observation use semantic-role parity, with observation restricted to its closed black/warm-red roles and no white transition frame.
- Press, sheet, state and mode transitions follow the DESIGN target; gestures are interruptible and retarget from live position. Reduced motion replaces spatial travel with immediate or at-most-100ms opacity changes while preserving state feedback.
- Day/night/observation retain semantic role parity. Observation is a closed black/warm-red palette; media is opt-in, skeletons cannot flash white, and system/native boundaries must avoid an unowned bright transition.

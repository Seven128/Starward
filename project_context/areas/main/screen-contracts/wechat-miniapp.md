## Route And Package Ownership

- Main package: `pages/map/index`, `pages/my/index`, `pages/auth/index`, permission rationale and error/recovery pages. Only Map and My appear in the persistent primary navigation.
- Permission settings report permission availability, never a successful position fix. Only an explicit one-shot location action may acquire a position; an unknown setting is not a refusal. Returning to the default trial region restores the default viewport and removes the prior selected place, Finder query, Observation Context, overlay and pending focus restoration through the existing Map state owner, while retaining committed filters, preferences, favorites, plans and search history. Results from location or map-point requests started before that reset must not restore the old place/context or publish a stale success.
- Spot package: `spot/detail`, `spot/guides`, `spot/field`, `spot/sky`, and `spot/data-source`. `spot/detail` owns the fixed header and Overview/Guides/Site content contract, including its media; `spot/sky` is its explicit child page rather than a global destination or an in-place replacement panel. Every detail section and the Night child preserve the same formal `spot_id`.
- Sky package: `sky/detail` and `sky/targets`. `sky/detail` is the sensor-following `方位天空` child entered only from the astronomy owner `spot/sky`; `sky/targets` owns target drilldown. Both inherit the same Observation Context, formal `spot_id`, selected date/time, timezone and data/algorithm revision from `spot/sky`; missing or invalid context fails closed. The retired standalone decorative sky map and page-level observation-mode route are not current product paths.
- Content/user package: `article/detail`, `plan/detail`, `contribution/index`, and `settings`. Routine favorite browsing is the Finder `想去` partition rather than a separate My/Favorites route. Feature-disabled profile-link/import surfaces are absent from the current route tree and cannot remain as a versioned compatibility product.
- Deep links activate the owning Map or My root before entering a subpackage route. Back closes route-owned overlays first, then pops the subpackage stack, and never invents a third primary destination.

# Product Surfaces: WeChat Mini Program

This on-demand contract node continues the independent Mini Program responsibility portion of `product-surface-contract.md`; route, Control and interaction detail remain in the owning Mini Program Screen Contract. Owner direction on 2026-09-03 supersedes the earlier Finder-Sheet plus standalone Spot Detail/Spot Night topology and then further refines Search continuity, compact density, objective-only spot information, the integrated layer/condition owner, persistent primary navigation, motion and My-surface responsibilities below. The product remains organized around five stable Product Surfaces; this Surface count is governance topology, not a claim that a design-resource revision is “five pages”.

## WeChat Mini Program Surfaces

### `miniapp-map-discovery`

- Surface: `pages/map/index`, its child `spot/search`, map overlays, the integrated `map-layer-selector`, and the map-parallel `map-spot-information-panel`.
- Surface Platform: WeChat Mini Program, Taro + React + TypeScript.
- Primary User Question: Which formal stargazing spot should I find, evaluate and act on without losing the map or the current observing context?
- Main Surface Allows: one-time location with manual fallback; one continuous ordinary base map with formal-spot markers; one fixed floating Search field; and compact location/layer actions. Activating Search preserves the field's exact geometry and rendered query-or-placeholder string; only its leading glyph becomes Back. A compact suggestion overlay attaches directly below it, the titleless filters stay close below, and only a modest gap separates them from `想去`/`其他观星点`. The field initially focuses, outside tap can dismiss IME/suggestions, and every Back path reverses the same transition. Result partitions retain identity/live geometry, and image-backed cards retain the established half-width translucent readability field.
  Selecting a marker or Search result opens the same panel at `medium`. Its `small`, `medium` and `large` extents all retain one ordered objective document and differ only by viewport clipping; `large` alone enables its internal vertical scroll. The only content-presentation exception is licensed media, which pulls into the top during medium-to-large. The image is substantially revealed before Search, location and layer controls fade near the screen top; reverse motion restores those controls before retracting media. Without media, a compact handle band remains during drag; with media, the handle overlays it and no separate band remains. Only the small long rectangular handle region starts extent manipulation. The flush `概览/天文` rail has no top/bottom inner gap; the shorter action pill retains `想去/分享/云观星`. Ordinary unavailable values use the visible copy `暂无数据`, without merging their distinct state/recovery semantics.
  The Map has one `none | spot-panel | layer-sheet` bottom-presentation owner. Opening `map-layer-selector` removes the panel's visible/active state while preserving selected spot and previous extent in the model. If a marker is chosen while layer is open, the owner retargets directly from the layer sheet to that marker's medium panel; it never restores an old panel in between or exposes two active triggers. Layer dismissal restores the previous panel only when no newer intent superseded it. The three Source-supported image-backed choices, integrated factual summary and no-close/no-off boundary remain.
- Main Surface Forbids: the retired lower Finder Sheet; changed Search text, oversized suggestion rows/filter gaps, visible “筛选条件”, trailing Search `x`; per-extent panel content trees; whole-panel drag; no compact band without media or a separate band over media; abrupt one-stage media/chrome replacement; a gapped/shadowed section rail; oversized action bar; visible ruler arrows, framed or non-draggable ruler; simultaneous panel/layer active flags; deep-blue active fill; `尚未核实` as generic missing copy; recommendation copy; or the retired callout-to-detail route.
  It also forbids separate peer entries for Search, Filter, point list and Favorites; an independent `观测条件` card; layer close `x`, off/“关闭图层”, unsupported satellite/traffic/radar/wind/temperature choices or a right-side expanding rail; duplicated selected-time values; ordinary POIs masquerading as formal spots; hidden committed filter state; realistic-looking fabricated fallback data; straight-line distance described as a route; product-design rationale, gesture instructions, generic implementation/status explanations, route/debug/reviewer metadata, visible sample/demo/version copy or third-party brand styling inside the phone surface. Freshness, provenance, limitation, uncertainty, permission and failure are visible only when their concrete effect changes a fact or action; full evidence remains explicitly reachable through its owner.
- Drilldown Ownership: `spot/guides`, `spot/field` and `spot/data-source` may remain progressive child routes from the information panel when their content cannot remain locally complete. External navigation is an explicit provider handoff. Full-sky device orientation belongs only to `miniapp-sky-orientation`.

### `miniapp-sky-orientation`

- Surface: delegated sensor-following `sky/detail`, entered only through `云观星` in a valid formal spot information panel.
- Surface Platform: WeChat Mini Program subpackage plus native canvas/sensor adapters.
- Primary User Question: Where are the currently observable objects in the sky as the device orientation and the selected observing time change?
- Main Surface Allows: the full available viewport as the sensor-following sky canvas; one quiet leading Back icon; Source-backed object labels; and one raised, borderless, arrowless curved ruler that moves beneath its fixed center under horizontal drag and snaps only to real slices. Ordinary successful following remains programmatic; only use-changing recovery is visible. The route consumes the current three-state display presentation without owning another mode control.
- Main Surface Forbids: a boxed orientation header, persistent direction/tutorial copy, framed ruler, visible step arrows, a static or click-only fake time track, generic linear range control, duplicated selected time, decorative objects presented as targets, fabricated pose, persisted trajectories, or disallowed color flashes in observation mode.
- Drilldown Ownership: source and algorithm disclosures remain progressive evidence; no standalone astronomy-information parent, professional page or target-list page is part of the current route topology.

### `miniapp-my-library`

- Surface: `pages/my/index` account center plus Plan, Contribution and Settings child routes. Routine favorite browsing remains in `miniapp-map-discovery` Search `想去`; the same favorite relation is operable from the map information panel.
- Surface Platform: WeChat Mini Program main/user subpackages.
- Primary User Question: How can the user understand their account state and reach plans or settings without mixing those tasks into the root page?
- Main Surface Allows: a compact account-hub header aligning avatar, display name/account state and one Settings gear; the existing profile summary; one shared-surface Plan/Contribution utility group; a short routine list; and an independent Settings route whose sole `display-mode-switcher` owns `day | night | observation`. The three-state track accepts taps, adjacent horizontal drags and accessible direct selection, with Sun/Moon/Star motion and observation-safe token sequencing. Plan, Contribution, Profile Link and Import/Settings may use restrained role-colored `SemanticIcon` tiles to improve scanning while labels/dividers retain meaning.
- Main Surface Forbids: peer My/Favorites/Plan/Settings tabs; redundant explanatory headings; a Favorite duplicate; day/night tabs plus a separate observation CTA; a binary Switch for three modes; plain oversized rows, rainbow card walls, commerce/membership/promotion modules, fake statistics, remote/second-family icons, page horizontal scrolling, sample cards, or duplicate spot information.
- Drilldown Ownership: profile links and imported content belong to `miniapp-profile-content`; a selected spot returns to the Map information panel.

### `miniapp-profile-content`

- Surface: `profile/links`, `content/import`, gated `submission/*` and related preview/status routes.
- Surface Platform: WeChat Mini Program user/content subpackage.
- Primary User Question: How can a user preserve external identity/content provenance while retaining copy/manual fallbacks, rights, privacy and moderation?
- Main Surface Allows: neutral external links with copy-first recovery; rights attestation; parser capability gate; manual import; editable draft; formal spot association or independent proposal; lineage, sanitization and review status.
- Main Surface Forbids: platform affiliation claims, dangerous URLs, unlicensed parsing, edited-field overwrite, proposal-to-spot shortcut or unreviewed public UGC.
- Drilldown Ownership: operations moderation remains in authenticated owner operations; the Mini Program shows only user-relevant status and recovery.

### `miniapp-contribution-intake`

- Surface: `content/contribution/index`, entered from My for general intake or from the map information panel with that formal `spot_id` preselected.
- Surface Platform: WeChat Mini Program user/content subpackage.
- Primary User Question: How can I submit a field report, correction or new-place proposal and know what happens before it affects a formal spot?
- Main Surface Allows: a guided structured report presented as one compact, keyboard-safe scroll document; stable formal-spot/new-place context; explicit observed time and affected fact topics; concise evidence narrative; optional location only for a deliberate new-place proposal; bounded media upload with rights confirmation and metadata sanitization; durable draft/upload/submission status; retry without duplicate writes; and contributor-visible pending/approved/rejected feedback. Simple fields use shared label/value rows, complex controls use top labels, validation stays beside its field, and the route exposes exactly one final submit action without changing the underlying field or state model.
- Main Surface Forbids: instant publication, treating a report as confirmed evidence before owner review, hidden precise-location collection, raw EXIF exposure, upload without MIME/size limits, loss of a draft after transport failure, a new-place proposal receiving a formal `spot_id` before the canonical completeness gate, per-field card walls, duplicate submit bars, or generic instructions/empty helper regions that dilute the report fields.
- Drilldown Ownership: owner review, sensitive evidence inspection, canonical fact merge and publication remain in authenticated `admin-data-operations`; the consumer surface sees only its own redacted submission state.
- Long Task State Requirement: the submission and every media upload have durable identities, explicit expiry/progress, idempotent retry, restart readback and cleanup of abandoned objects.

Across all Mini Program user scenes, compact information density is created through smaller but legible type roles, tighter vertical rhythm, aligned text/value axes, dividers, semantic prefix icons and removal of non-decision copy—not by shrinking touch targets, removing hierarchy, applying indiscriminate card containers or depending on color alone. The owning Design Authority defines exact values, including the pure-white day foundation. At 200% text the hierarchy must reflow and remain operable rather than preserve compact geometry by clipping or horizontal page scroll.

Across all Mini Program user scenes, scrolling remains available where content requires it but mobile scrollbar chrome is always hidden and consumes no layout width or height. Horizontal scrolling is exceptional and belongs only to an explicitly bounded row, data matrix or curved time ruler; it also exposes no scrollbar chrome and retains equivalent keyboard/assistive controls. Hiding chrome never disables scrolling or clips reachable content.

Across all Mini Program user scenes, a visible local state change is the primary feedback for selection, filter, disclosure, navigation, favorite success, time scrub, layer and mode actions; those actions do not also raise a toast/snackbar/modal. Every material surface/state change uses a short, causal, interruptible transition and retargets from the live presentation; reduced motion substitutes a direct state change rather than leaving ambiguity. Persistent/actionable permission, stale, offline and failure feedback uses one shared inline Notification family beside the affected object only when the state changes the current decision/action. Generic “部分数据” or implementation explanations never occupy ordinary chrome. Floating feedback is reserved for short asynchronous completion or copy/save/undo results that are otherwise not visible. One owner exposes at most one full notification at a time, deduplicates repeated events, preserves concurrent material states through deterministic severity order and an accessible residual count/queue, and never replaces the sole recovery path with an auto-dismissing toast or a stack of full-height cards.

The stable Mini Program Control inventory, route/package bindings, cross-control invariants and responsive/motion/accessibility responsibilities are owned by `screen-contracts/wechat-miniapp.md`.

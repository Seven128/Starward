### 云量与光害并发与容量

仅核这两项迁移及其对既有业务的影响。预期4核16GB/12Mbps/2000GB主机继续作为初期验证配置，4GB测试环境不证明生产容量。API与受限加工任务可先同机隔离；全国总量、200 DAU或单张热图吞吐都不直接决定升配。需要扩容的证据是批次无法及时完成、冷派生需求持续超出处理能力，或加工挤占普通API/数据库及整机资源余量。

Standard source manifests share API/export headers and preserve admitted history. `tools/deployment/sky-object-store-package.mjs` derives local OSS keys, exact standard/custom metadata and ESA header configuration inputs from the same sealed static export; the key is the public route without its leading slash, while any physical `.tile` suffix stays with `skyStaticFilePath`. Package readback revalidates the explicitly selected source, edition and resource origin. This remains local integrity preparation, not source adoption, a trusted OCI, account entitlement or cloud publication. `sky-object-store-verification.mjs` shares bounded byte transport with the existing static release and checks exact public GET/header plus grouped HEAD/Range semantics without credentials or API fallback. A controlled provider model does not certify ESA compilation, cache hits, real origin ownership, managed-store/live recovery or capacity; [verification scope](../../.codex/work-items/cloud-sky-native-2026-09-22/evidence/object-store-package-2026-10-10.md) keeps these separate.

Map has its own sealed publication, object plan and uploader under `tools/deployment/map-static-bundle.mjs` and `map-object-store-*.mjs`; it reuses immutable object transport without borrowing Sky's release identity. The Mini Program's shared `map-raster-files.ts` accepts canonical independent HTTPS URLs for the declared cloud and final EOG contrast routes; legacy relative terrain/night-light paths retain their API origin. The same byte/hash/file/native-pin owner and limits cover all three consumers. That source is explicitly `DEVELOPMENT_ONLY`, part of its sealed identity; it has no qualified/adoption override. Cloud records do not enter the business-host Caddy fragment. The object-store package may describe them locally, but upload re-admits the selected bundle and rejects cloud before creating a journal or client. This boundary deliberately remains closed until actual source-group, complete display and formal-delivery qualification exist; a local package, numeric-ready file or editable display flag cannot supply that authority. Terrain/night-light exports and old URLs retain their original scope.

The same offline Map owner accepts explicitly pinned EOG sharded prepared roots through `eog-map-publication-input.mjs`. Existing schema2 export still requires its original PUBLISHED authority. A prepared root or local package cannot activate public schema3 publishing, URLs or ready. Full admission and object packaging still traverse the complete set offline. Partitioning removes the flat runtime-directory dependency; it does not qualify or activate a nationwide export. Sharded EOG scientific discovery stays with its coordinate owner, and actual delivery/routing remains independently required.


The adapter declares project headers as OSS user metadata and origin-to-ESA restoration inputs so cached bytes can retain their exact public headers; standard content type, cache policy and source attachments stay unchanged. It does not configure a live site. The immutable-write path requires a dedicated bucket whose versioning has never been enabled: OSS ignores forbid-overwrite when versioning is enabled or suspended. An existing versioned bucket requires reassessment rather than disabling its history or claiming the flag protects it. ESA response-field/function compilation, available account quota and byte-preserving cache configuration remain live prerequisites. See [OSS semantics](https://help.aliyun.com/en/oss/developer-reference/putobject) and [ESA response-field phase](https://help.aliyun.com/en/edge-security-acceleration/esa/user-guide/phase-list).

`tools/deployment/sky-object-store-upload.mjs` is the explicit upload/recovery operator entry, using the isolated pinned official `ali-oss` SDK through `sky-oss-client.mjs`. It requires the original held release preparation and revalidates the retained union/package; no JSON receipt can authorize an arbitrary bundle. It checks the real versioning response, existing bytes and stored metadata, uses one forbid-overwrite/MD5 PUT per missing key, then reads the actual result after success, conflict or a lost response. Unknown/missing results stop without blind retries; subsequent attempts re-read every remote object. Serial writes, an owned whole-request deadline and abort/disposal bound active I/O. Append-only synced journals preserve independent verified results without advancing current or deleting history. Current tests simulate Docker ingress and OSS on loopback; they do not establish real OCI provenance, cloud write permission, provider durability or CDN acceptance. SDK installation and the separate writing command are documented with the [operation owner](../../infrastructure/deployment/README.md#cloud-sky-oss-upload-and-recovery); [scoped evidence](../../.codex/work-items/cloud-sky-native-2026-09-22/evidence/object-store-upload-2026-10-10.md) retains live gaps. Before live use, credentials must be limited to the selected bucket/prefix and bucket administration must exclude concurrent version-policy changes: separate version-state queries and PUT cannot atomically prevent an outside administrator from changing that policy. The operator never enables/disables versioning or repairs conflicts by overwriting.

请在 Starward 仓库实施 `docs/design-plans/Starward_设计资源Skill_开发方案.md`，并按 `docs/design-plans/Starward_地图与我的_UI重构_测试方案.md` 测试。

目标：开发并实际验证 `$starward-design-resource`。用户只描述产品、页面和普通审美偏好，Skill 自主补齐专业设计判断，交付可编辑 Figma 原生设计资源，并基于实际截图检查和改进。首次场景是微信小程序地图页与我的页的 UI 重构候选。

先阅读 AGENTS、当前默认 Context、DESIGN 的小程序段及相关 Screen Contract，核实当前 HEAD 与研究提交的差异，保留无关和未提交改动。不要使用早期附件恢复三主导航、独立旧详情页或我的收藏夹。

先确认当前模型、Skill 发现路径、Figma权限与运行工具，做真实写入—中文—截图—修改探针。原帖报告模型为 GPT-6 Astra；未公开 effort 与完整图1提示词。实际模型无法确认就记录unknown，不自报替代运行证据，不将别的模型计作同模型复现。

优先复用已可用的 Scripter+浏览器自动化；缺少稳定闭环再验证方案中的本地 Desktop Bridge。通过探针后只选一种主路径，不并行开发三个适配器，不购买订阅、不启用云relay、不自建大型MCP平台。缺少本机登录或插件运行时，完成可实施部分并具体报告外部前提，不伪造设计截图。

开发轻量 Skill 和必要脚本，复用当前图标、组件、业务与验证所有者，不恢复退役 DRA / Long-Task 治理。随后按相同输入生成三方向×地图/我的，保留全部round-0和最终图；完成同模型、同工具的A/B试验。每组最多两轮正式视觉修订；初步有用后按方案冻结版本复验，报告全部候选而非只挑最好的一张。

推荐一个方向并自主补齐其必要主题、状态、尺寸及交接修改测试，明确推荐不等于用户选择。需要调整旧字号或间距的内容作为任务局部的拟议设计差异交付，不被旧的小尺寸锁死，也不擅自覆盖当前规范。

本轮交付 Skill、真实可编辑设计资源、实际测试报告和实施映射；默认不改生产页面、不发布、不把资源生成当UI上线。完成后让我直接比较候选和看到未验证项。人工审美、手机或Figma前提未完成时照实标记，不自评全部通过。

源文件、生成脚本和结果留在仓库可追溯目录；凭证与字体文件不得提交。按开发方案的分层完成标准报告结果。

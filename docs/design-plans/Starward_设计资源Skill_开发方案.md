## 1. 先明确这次要实现什么

**开发一个能把普通设计描述，转成经过实际视觉检查、可编辑、可继续修改的设计资源包的 Skill。**

首次应用范围是《今晚去观星》微信小程序的地图页和“我的”页。Skill 要减少用户补充专业排版、字重、留白、材质、信息层级等指令的负担。它的作用不是宣称模型拥有稳定审美，而是让专业设计判断、工具执行、视觉回看和资源交付成为可复用能力。

本次交付分为两件事：

1. 可被 Codex 实际发现和调用的 Skill，以及必要的轻量脚本、引用和测试。
2. 用该 Skill 产生并测试的地图／我的设计候选、原生 Figma 图层、截图、交互说明及实施映射。

**本轮默认不改生产页面，不发布小程序，不购买订阅，不把推荐候选冒充用户选定方案。** Agent 可以自主推荐一个方向并补全其状态与验证，不必为了等选稿而停在两张初稿；正式采用和生产代码重构在用户明确选择后进行。

## 2. 原帖复核结果与证据边界

### 2.1 作者公开说明支持的结论

原帖地址：<https://x.com/LinearUncle/status/2096513510939529670>。

作者明确写的是 **GPT-6 Astra，在 Codex 中执行**。其流程为：

```text
需求及 /goal
→ Codex / GPT-6 Astra 编写代码
→ Figma Scripter 插件执行 Figma Plugin API
→ 生成原生可编辑画板、图层和原型跳转
→ imagegen 生成晨光背景后导入
→ 浏览器打开插件、执行脚本并点击原型验证
```

这里的 Scripter 是执行器，Figma 是设计编辑环境；不能据此认定使用了 Figma 内置 AI 生成模型。作者后续还区分了插件、浏览器脚本、computer use 和 MCP，并表示当时只试过前三种。[S1][S2][S3]

### 2.2 不能从帖子证明的内容

本次取得了原帖索引文字及作者后续引用的完整帖文，但没有成功取得图 1 中完整提示词，也没有得到完整操作录像、会话日志、精确模型快照、推理档位、失败次数或挑选过程。因此：

- 不能把模型名进一步认定为 Astra Pro。
- 不能认定是零参考、简单一句话、一次生成即成功。
- 不能把图像素材质量全部归因于生成布局的模型。
- 不能以作者演示证明所有普通提示词下都具有高审美下限。
- `/goal` 是任务持续执行方式，不是设计审美保证，也不是模型选择指令。

OpenAI 官方说明 Astra 已进入 Codex，并强调其视觉判断和多步任务能力；这是模型提供方的能力说明，不是针对本项目的独立效果测试。[S4][S5]

### 2.3 本次模型使用规则

P0 记录实际 Codex 版本、模型界面名称／可取得的模型 ID、推理档位和工具能力。优先使用原帖作者报告的 GPT-6 Astra。确切档位未公布，采用本机可用的一个固定档位并明确记录。

不要在 Skill 中伪造“已切换模型”。模型需要由当前宿主实际配置；拿不到模型 ID 时记录 `unknown`，不能通过自报补齐。若 Astra 不可用，可以继续完成工具和 Skill 的工程开发，但其他模型的图不能计作 Astra 复现实验。

## 3. 对 Starward 当前状态的理解

### 3.1 以当前仓库为准，不倒退到早期附件

研究时 `project_context/global.md` 和小程序 Screen Contract 已明确：**主入口只有地图和我的**，天空页属于选定正式观星点的下级页面。早期附件里的“夜空—地图—我的”、独立观星点详情和我的收藏夹不能直接用作本次重构要求。[R1][R2]

执行时先记录实际 HEAD 和工作区改动。若比研究提交更新，重新核实受影响的所有者文件；不要为了匹配本文退回旧提交或覆盖用户未提交内容。

### 3.2 地图不可丢失的产品约束

- 保持一个物理地图、选中观星点、查询／筛选及 Observation Context 的现有所有者。
- 地图搜索框进入独立搜索页；本次不得把搜索筛选重建成第三个主入口。
- 点选正式 marker 后直接打开中档信息面板。
- 面板有独立可见状态和 `small | medium | large` 三档；三档裁切同一份有序内容，大档才启用该文档的纵向滚动。
- 仅把手热区承担档位拖拽；点击把手不应直接切档。图片有／无及展开顺序遵守当前合同。
- 面板章节为“概览／天文”；操作栏为“想去／分享／云观星”。不能为了画面漂亮减少这些职责。
- 信息面板与图层面板经 `none | spot-panel | layer-sheet` 单一协调器互斥。
- 时间预览、提交、取消和真实数据切片语义不变；静态光害不能制造假小时变化。
- 天空页仍由“云观星”携带正式 `spot_id` 与有效上下文进入。

这是一份设计资源范围，不要求本轮重新实现地图底图、天气引擎、路线服务或传感器。[R2][R3]

### 3.3 我的不可丢失的产品约束

保留账户／身份摘要、现有计划、贡献反馈、设置、主页链接、内容导入及真实状态；按当前合同组织为紧凑账户头部、一个明确设置操作和少量分组入口。不要新造会员、商城、勋章、营销位、统计成绩或第二层页签。

收藏浏览继续属于搜索页“想去”分区，不把旧版收藏夹移回“我的”。代码中可能存在尚未符合合同的旧组合，须在资源说明中写清“当前实现／应有职责”的差异，不通过复制当前截图固化偏差。[R3][R4]

### 3.4 现有设计是起点，不是阻止此次重构的理由

用户已经提出手机上的文字过小，希望“精致、小巧、简约，同时有效信息密度高”。候选应解决这个问题，不能以旧字号是规范为由只换颜色。

业务和交互职责固定；视觉候选可以提出字体、间距、容器、图标比例与层级调整。把这些变化保存在任务局部的 `proposed-design-delta`，说明对应旧值／规则、拟改内容和理由。**未选定之前不修改根 DESIGN、不宣称这些值已成为新规范。**

沿用现有品牌语义和资产优先；如果需要改变其已确认的方向，要明确标成候选中的品牌变化，而不是悄悄全站替换。

## 4. 工具选型：先跑通一种，不建设三套系统

### 4.1 原帖复现与长期自动化要分开

**原帖复现路径：Astra / Codex + 浏览器操作 + Scripter + Figma Starter。**

Scripter 本身只执行脚本。要形成低人工介入闭环，Agent 还必须能打开目标文件和插件、运行脚本、读取结果、取得真实截图、继续修改。单纯保存一份 JS 或让用户每轮复制粘贴，不算自动化闭环。Scripter 脚本通常保存在本机浏览器或桌面应用的 IndexedDB，不能当作项目唯一源文件。[S3]

### 4.2 建议自动化候选

为了让本地 Codex 获取结构化结果，可评估开源 **`southleft/figma-console-mcp` 的 Local / Desktop Bridge 路线**。研究时包版本为 `1.40.0`、MIT 许可；作者文档支持本地 Plugin API 执行、设计读写及截图等功能。[S6]

这是本方案的工程建议，**不是原帖作者用法，也不意味着审美已经验证等价**。使用原则：

- 优先使用本机已可用的 Scripter 自动化；若无稳定的运行／读回方式，再验证 Local Bridge。
- Local Bridge 使用本地 MCP 服务加 Figma Desktop 中运行的插件；不要误接只读的 Remote SSE。
- 本地 Codex、服务和 Figma Desktop 必须处于实际互通的环境。云端 Codex 任务不能凭空访问本机桌面；Windows、WSL、容器之间也不能假定 localhost 等价。
- 固定经过验证的版本，记录桌面插件版本；不在每次运行时使用 `@latest` 自动升级。
- 凭证只放本机环境或忽略的私有配置，按实际调用申请必要权限；不照抄无关的评论写权限、不提交 token。
- 按实际发现的工具 schema 调用，不把本文的能力名称当成存在的函数名。
- 不启用云写入 relay，不开放公共端口，不绕过 Figma 席位或文件权限。

**P0 结束时选择一个通过探针的主路径。首版只实现这个路径的使用说明与必要封装。**另一路线保留短说明即可，不要求双栈完整适配，更不自建一套长期维护的 MCP／浏览器自动化平台。

### 4.3 官方 MCP 的准确边界

当前 `use_figma` 自由操作画布要求 Full 席位及目标文件编辑权限，而且有图片导入、自定义字体和单次输出响应大小等限制。这些限制属于该远程工具，不能外推到普通 Plugin API 或 Scripter。[S7]

另有官方 **code-to-canvas**：可以把浏览器 UI 捕获为草稿里的可编辑图层，官方说明任何席位可以用于 drafts。因此“Starter 不能通过任何官方 MCP 写入”过于笼统。**但这条路线不是原帖路径，也不应为了它把现有 WEAPP 重新造一套 H5 产品**，本次不作为主链。[S8]

已有 Full 且官方 MCP 已经可用时可以优先复用，但必须验证图片、中文字体和导出要求能否满足；不要求为本方案购买 Full。

### 4.4 Starter 的设计交付方式

Starter 支持基础 Auto Layout、组件和原型；跨文件团队库、多模式变量及高级变量原型功能存在套餐边界。[S9]

首轮用一个草稿文件，本地组件和独立日／夜／观测画板即可。不要把多模式变量、发布共享库、Code Connect 或复杂条件原型列为免费路径的必需验收项。复制不同模式的画板不是复制业务实现；它们仍应来自同一套模式数据与组件生成函数。

当前 Codex 官方文档使用 `.agents/skills` 发现项目 Skill；本仓库已有 Skill 在 `.codex/skills`。新建一份源文件并实际验证发现方式，不借此迁移老 Skill，不在两个目录维护相同正文。[S10][R5]

### 5.1 SKILL.md 的内容要求

正文只承担路由与关键行为：触发场景、范围保护、读取入口、执行步骤、产物与停止条件。专业细节按需进入 references。不要将完整产品文档、几十万字历史包或通用设计教材复制进来。

触发：设计风格探索、页面视觉重构、原型设计、生成／修改可编辑设计资源。

不触发：普通代码修复、发布、后端任务，或用户只要一段解释而没有要求执行设计。

建议默认显式调用；若宿主支持 `allow_implicit_invocation`，按实际 schema 设置，避免所有前端小改都启动多候选设计。Skill 不管理项目任务生命周期，不恢复已退役的 DRA／Long-Task 验收机制。[R6][S10]

### 5.2 各脚本只解决具体问题

- `preflight.mjs`：检查本地路径、输入文件、版本记录、输出目录及凭证泄漏风险。工具实际可写／可截图只能由真实探针确认，脚本存在不算能力验证。
- `figma-helpers.js`：少量标准 Plugin API helper，处理字体、Auto Layout、组件／图标及范围受控修改；不要发明页面描述语言、通用渲染器或另一个组件平台。
- `check-resources.mjs`：检查导出图片、节点映射、必需控件、来源、过期证据和覆盖情况；输出确定性问题，不自动判定“高级感”。
- `build-review.mjs`：由真实导出的图片生成比较页与匿名评审编号。它不是产品 H5，不参与 WEAPP 运行验收。

使用项目已有 Node、测试框架和合适依赖；新增依赖必须有具体用途。不要为几个文件上独立数据库、服务端框架和后台。

## 6. 核心执行流程

### 第一步：理解需求并建立最小输入包

输入至少包含目标页面、当前所有者、用户偏好、设备尺度、素材与变更边界。已知信息直接从仓库读取，不重复问用户。

`brief.md` 记录四类内容：必须保留的业务与交互；本次希望改善的视觉问题；允许探索的范围；无法自行确定的外部前提。当前真实页面截图应尽量从现有小程序验证入口取得；拿不到时记录缺失，代码和旧截图不能冒充当前渲染结果。

### 第二步：把普通描述转成专业设计选择

用户只需说“精致、小巧、简约、信息密度高”。Skill 应自主补齐：

- 页面首先让用户注意什么、其次是什么；每个动作处于哪个优先级。
- 通过信息分组、对齐、文本精简和渐进展示提高密度，而不是先缩小字体。
- 字号、行高、图标、可见控件与真实命中区域如何协调。
- 何处需要容器、边界、留白，何处不需要独立卡片。
- 地图和真实场地内容如何成为主体，品牌装饰不抢占任务空间。
- 两页如何体现同一个产品，同时各自符合地图工具与账户中心的任务特点。

三个候选必须在至少两个实质维度不同，如信息组织、容器策略、密度节奏、视觉重心或图像占比；不能只是三套颜色。由 Agent 命名和解释方向，不把某一种“蓝色大卡片模板”硬编码为通用高审美。

专业判断应当可修正。不要通过固定大量圆角、颜色和字体值掩盖模型的判断能力，也不要把附加长提示词推回给用户。

### 第三步：先生成六张核心画板

先做三个方向，每个方向各一张地图主要状态和一张我的主要状态。主评审尺寸建议 `390×844` 逻辑像素；固定内容、状态、地图视口、图片与账号数据，便于比较。

本阶段先检验审美和业务组织，不为每个方向穷举所有主题和异常态。保留第一次生成的全部图，标记 `round-0`；后续修订另存，不能用最终图覆盖初稿后声称默认结果就很好。

### 第四步：在 Figma 内生成原生结构

- 文字保持 Text，控件保持可编辑容器／组件，复用项优先为组件实例。
- 相关内容用 Auto Layout，地图叠层、特殊轨道等才使用有理由的绝对定位。
- 仅现有地图或场地图片可为栅格图层，不允许整页截图贴底充当设计稿。
- 中文必须实际加载可用字体并检查替代字体。记录解析到的字体，不用拉丁字体渲染正常推断中文正常。
- 导入现有 `SemanticIcon`／资产管线可用的实际矢量或图片，不引入第二套风格。Figma 组件与代码 owner 通过普通映射关联，不依赖收费 Code Connect。
- 图片需有来源和使用权。生成图片只能作明确的装饰或模拟素材，不能伪装真实观星点实景、地图或当前天气。
- 所有辅助层、解释、候选名和模拟数据标识位于画板外或评审说明，不把 debug/demo/reviewer 文字塞进产品 UI。

普通 Plugin API 与官方远程工具具有不同执行环境。不要把 `use_figma` 特有的便利方法、返回约定或原子失败保证复制到 Scripter。优先依据实际 runtime 与官方类型定义实现并测试。导出使用真实节点渲染，如 standard `exportAsync`，不是在本地另画一张相似截图。[S7][S11]

### 第五步：真实回看与有限修订

每个方向最多进行两轮正式视觉修订。每轮取得 Figma 实际截图；先看完整移动画面，再看文本、图标、命中区域与长内容局部。独立评审与生成步骤分开，尽量使用未看到作者自评的会话。

评审必须指出具体位置、具体问题和预期改善，禁止仅输出“已达到高级感”。发现明显退步应回退。达到预算或连续修订无改善时，交付当前结果和失败原因，不通过无限循环或调低验收标准制造成功。

可以另行记录技术修复次数，但不能把大幅视觉重做伪装成“技术修复”绕开轮数。

### 第六步：推荐一个方向，补齐关键状态

Agent 综合业务正确性、视觉评审和修改成本推荐一个方向，状态明确为 `recommended-unapproved`。补齐地图三档／图层／图片缺失等关键状态，我的加载与异常状态，以及日间、夜间、观测模式和小屏长文本。

细节按测试方案的覆盖矩阵执行，不做三方向×所有状态×所有主题的无差别展开。

### 第七步：交付资源和实施入口

结果至少包含：可编辑 Figma 链接及节点定位、所有候选初稿与最终截图、推荐方案完整状态、可重复运行脚本、使用素材、派生 token、控件与代码映射、拟议设计差异、实际检查与未验证项。

完成标准是“资源能够被接手并修改”，不是“有一个 Figma 链接”。进入下一次会话后，Agent 能从资源包定位控件、修改一条文案、重导出受影响画板，不必重新生成全部设计。

## 7. 资源契约：少量结构化信息，足够追溯即可

### 7.1 run.json

建议记录：研究／执行 HEAD、工作区差异摘要、源文件哈希、实际模型及 effort、Codex／Figma／插件版本、工具路径、目标文件、起止时间、提示词输入、轮次、模型／工具使用量、失败与人工操作次数。

不可取得的用量填 `null` 并说明原因；不得推算成 0。只存可分享的配置与摘要，不记录 token、cookies 或完整私人账号资料。

### 7.2 resources.json

每张画板至少有：候选 ID、页面、状态、模式、逻辑尺寸、Figma 节点 ID、截图路径及哈希、导出轮次、节点结构快照、所覆盖 Control key、资产引用、关联代码 owner。

机器检查不能只检查作者手写的 `passed: true`。控件存在、字体、尺寸、链接目标等应从工具读回的实际节点树或导出结果计算。截图和结构必须来自同一轮画布修改后，过期截图不算本轮证据。

### 7.3 原型表达边界

基础点击跳转应能实际演示。连续面板拖拽、原生地图竞争、速度与中断物理可用状态画板加交互规格说明；不能把静态跳转说成已经实现与验证真实手感。Starter 不支持的高级条件原型不作为前置要求。

如能导出 `.fig`，作为附加备份；**JS、PNG、JSON 不能改扩展名冒充 `.fig`**。未导出原生文件时必须说清。设计文件权限默认最小，不自动公开分享。

## 8. 安全、重跑与故障处理

所有写入限定为用户指定文件中的本次候选区域。先读取并核对文件、目标节点和当前结构；不要删除整页、全局组件或名字相似的其他内容。

记录受控节点 ID，避免仅按名称批量删除。重复运行应更新／替换所属候选而不是不断叠加。已有手工编辑与缓存不一致时先读回比较，不覆盖未知修改。

普通插件脚本可能已经部分修改后才报错。通过小步修改、暂存子树和读回结果管理失败；只有明确属于本次写入的暂存节点才允许清理。不承诺所有运行器都有事务回滚。

断开插件、权限不足、导出失败、字体缺失或错误文件时，停止相应写入并报告具体问题。不得把 `403` 当作不存在、把失败当空结果、自动切换账号或付费绕过限制。

## 9. 尺度、主题与资源复用

### 9.1 不再用电脑缩放后的感觉决定手机字号

画板标注逻辑像素；导出可同时提供 1× 与 2×，二者是相同设计尺寸的不同采样，不是不同字号。评审页提供正确视口尺寸，手机打开验证，不用海报式多机样机代替。

微信换算关系为 `逻辑 px = rpx × 当前视口宽度 / 750`。因此 `88rpx` 只在 375 宽时等于 44 逻辑 px，在 320 宽时约 37.5。实现阶段还须检查 Taro `designWidth` 和 px 转换配置，不能再额外乘设备像素比。

若当前 DESIGN 的精确尺寸和某控件 44px 命中要求发生冲突，记录冲突及候选修正，不用“规范已写了 88rpx”证明所有设备满足。候选保证文字能读、目标可点且扩展命中区不互相覆盖。

### 9.2 三模式是同一业务状态的不同表达

日间、夜间、观测模式保持相同控件与数据含义。观测模式按当前黑／暖红规则单独设计；不能给彩色图加红滤镜就宣布合规。

原生地图、系统弹窗、键盘等不完全受自有主题控制的表面应单列为外部边界。只对拥有控制权的 UI 声明通过；如果相关合同要求保护措施，则沿用或提出明确实现方案，不能靠截图裁切隐藏问题。

### 9.3 设计系统采用流程

当前根 DESIGN 中小程序段是现行精确值来源，Open Design 是现有可编辑上游；本轮 Figma 先作为新候选与交付媒介。选定后，在原所有者处说明是否迁移上游、哪些两页／组件值改变、对其他页面有何影响。[R2][R6]

不要让 Figma、根 DESIGN、手写 JSON 和样式文件各自维护一套互不一致的规范。派生 token 标注来源和生成方向；原历史包保持不可变。涉及全局 token 的改变须列出受影响页面，不能以“两页重构”名义暗改全应用。

## 10. 实施步骤与各步可见结果

| 步骤 | 开发内容 | 可验收结果 |
|---|---|---|
| P0 | 核实当前源、Skill 发现、模型、运行器与目标文件；真实写入／中文／导出探针 | 一份实际能力记录；一个可编辑片段和真实截图；选定一种主路径 |
| P1 | 编写 Skill、专业设计引用、轻量 helper、资源检查和比较页生成 | 新会话能明确调用；工程测试通过；无独立新治理系统 |
| P2 | 地图／我的三方向，保留初稿；有限视觉回看 | 六张核心候选、实际原生结构、修改记录与推荐 |
| P3 | 完成 A/B 测试、推荐方向的状态／主题／尺寸检查及交接重跑 | 测试报告区分工程、设计正确性、审美和用户偏好 |
| P4（选择后） | 将选定方案更新至现有视觉 owner，再改实际 WEAPP 所有者 | 当前候选的原生运行和手机证据；不把资源验收当生产验收 |

P0 外部环境不足时，仍可开发并测试不依赖登录的部分，交付明确缺项；但不得称 Figma 写入或视觉实验已完成。不要为了一个工具异常自动改走截图贴图、生成 H5 代验收或购买服务。

## 11. 成本控制

免费 Starter 和 Scripter 不要求新增 Figma 订阅；Local Bridge 为开源工具，仍存在配置、依赖维护和模型使用成本。[S3][S6][S9]

已有 Codex 订阅可使用实际可用额度；“不新增订阅”不等于模型执行零消耗。默认不采购模板、字体、图片，不启用另外付费的 Figma AI 或云 relay。原帖 imagegen 是可选素材路径，不是两页质量测试的必要条件；A/B 使用相同现有素材。

默认预算以三候选、两轮视觉修订和分阶段扩展控制。报告实际工具调用、输入／输出 token（可取得时）、人工干预和执行耗时，不预先承诺每页美元成本。API 用户如需成本估算，使用执行当日对应模型的输入／缓存输入／输出价格计算，不能把 ChatGPT 订阅额度当 API 抵扣。

仓库 CNY 200/月的外部业务服务预算不构成设计工具采购授权。[R1]

## 12. 完成与失败如何报告

至少分别报告四个结果：

1. **Skill 工程能力**：能发现、调用、真实写入、导出、修改及重跑。
2. **设计职责正确性**：当前地图／我的流程与信息未被破坏。
3. **视觉实验结果**：初稿和迭代后分别是否达到预先规定标准；A/B 的样本量与局限。
4. **采用与实现状态**：是否用户选择；是否改了生产代码；是否运行过 WEAPP／真机检查。

不得只说“全部通过”。视觉评审缺失、模型不可确认、原型未运行或手机未检查都应单列。用户未选稿时状态是“候选已交付、待选择”，不是“UI 重构已上线”。

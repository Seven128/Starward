## 0A.2 最终产品拓扑与页面职责

1. 一级导航固定为“地图 / 我的”二分，地图为默认页；不存在全局“夜空”一级页。
2. 正式观星点在普通底图上默认展示，不设置“正式观星点”或“普通地图”同级 Tab。光害、总云量、今晚观测条件是互斥的可选分析叠加，底图与正式点 Marker 始终保留。
3. 地图页只负责用简化基本信息筛选、比较、定位正式观星点并进入详情；路线、设施、安全、媒体、来源和完整决策证据归 `spot/detail`。
4. Finder 是地图唯一查找入口：搜索、18 项筛选、收藏身份和点位列表共享一个结果投影；结果只分“想去”和“其他观星点”，城市是分区内标题。激活结果先定位同一地图并打开轻量气泡，只有气泡的有效 release/键盘/读屏激活才进入详情。
5. 夜空只属于正式观星点详情的下一级 `spot/sky`，必须继承 `spot_id`、日期、选中时间、时区和数据修订。普通地点和暗夜候选地点不得合成正式 Spot Night 或完整出行/安全结论。
6. Spot Detail 使用“概览 / 攻略 / 场地”内容切换，并以上方唯一入口进入 Spot Night；Favorite 位于名称旁安静 icon，`去这里 →` 位于距离/路线行，设施卡不重复页面动作。
7. “我的”是常规账户中心：标题、右上设置齿轮、简洁身份区和少量普通列表项；计划与设置为独立子页。收藏浏览不在“我的”重复出现，继续由 Finder“想去”与 Detail Favorite 承载；设置是观测红模式唯一显式入口。

## 0A.3 地图、Finder 与观测条件

- 正常字号下，紧凑页头、一行高密度搜索 Bar、地图主体和 Map/My 底栏共同进入首个手机 viewport；地图占剩余高度。
- Search Bar 显示 query/城市、最多两项高优先级已提交筛选、`+N` 与结果摘要。打开使用 `SourceLiftFocusLayer.panelOnly`；上浮后的“查找观星点”标题行自身负责展开/收起和旋转 chevron，不设置独立关闭 X。
- 搜索建议紧贴输入框下方，Filter editor 与 suggestion 互斥且不改变结果 scroll geometry。18 项筛选保持 10 个首层 + 8 个高级项，一个 draft/commit/revert owner；dirty 时才显示光学居中的 44px `×`/`✓` action。
- 地图内常驻紧凑“观测条件” Bar，仅显示当前分析、关键指标与一个当前本地时间。打开使用 `SourceLiftFocusLayer.mapCoupled`：Bar 快速轻微放大淡出，信息面板淡入，同一物理地图只移动/缩放、不复制、不淡出；原位置保留等高占位。
- 时间 scrubber 拖动是 preview、释放是 commit；总云量和今晚条件随 `selectedAt` 更新，LIGHT 只按数据源周期保持静态，禁止伪造逐小时光害变化。
- 地图直接支持 pan/pinch/tap，不显示永久平移箭头和 `+/-` chrome；搜索和可访问结果列表是非手势替代。

## 0A.4 固定复用交互与组件合同

- `SourceLiftFocusLayer` 固定为 `panelOnly` / `mapCoupled` 两变体：一个 live node、一个几何占位、fixed safe destination、scrim、Back/Escape/显式 toggle/close、焦点返回、可中断反转和 reduced-motion 等价。退场连续返回 exact origin，禁止闪烁、挤压地图、瞬移、空白或白色结束帧。
- `NotificationComponent` 固定为 `inline` 与 `floating` 两布局，tone 为 info/warning/error/success。一个 owner 同时只展示一条完整通知，其余按 error→warning→info→success 仲裁并保留可访问计数；每条至多一个 trailing recovery action，44px 命中区，浮层不得改变页面/地图/滚动几何。
- Finder 筛选卡和观测条件图层卡的选中装饰共用右上半裁切圆角渐变星，同时保留 border、ARIA/check 与文本语义；不得只靠颜色。
- 用户页面不显示产品设计思路、调试路由、审阅 metadata、`SAMPLE_DATA` 标签或普通手势教程；来源、时效、限制、不确定性和恢复信息仍在对应产品位置可见。
- 全部用户场景保留必要滚动能力，但隐藏纵向 scrollbar chrome 且不占宽度；横向只允许明确 owner 的行/矩阵，可见指示器 overlay、零布局占位、白色半透明。
- 概览/攻略/场地 Tab 使用稳定指示器与约 160ms 内容淡入淡出；快速切换可重定向，旧 panel 立即失去交互/无障碍可达性，reduced motion 立即或 ≤100ms。
- 生产先复用项目批准的小程序组件/icon；也允许成熟轻量、许可证和平台兼容、可按 DESIGN 主题化且无障碍完整的外部库，或边界清晰的少量自实现。禁止无理由引入重型第二 UI 系统或第二套 token/icon truth。

# 0. 文档结论

V2.0 不重新定义产品，而是在 V1.0 正确主线之上完成两类必要变更：

1. **纠正当前实现对原始产品方案的漂移**：恢复“夜空—地图—我的”三级全局导航，恢复普通地点与当前位置查看夜空，恢复详情页“概览—场地—夜空—攻略”顺序，重新把真实天气、路线、设施、光害和现场安全放回核心优先级。
2. **吸收逐星的高价值能力**：增加天象事件、活动曲线、全球峰值与本地有效观测夜的区分、统一时间轴、多层云量、多模型差异、光害图层、暗夜候选地点和“本地最佳有效观测窗口”。

产品最终形成两条互补入口：

```text
地图入口：地点优先
我在哪里 → 附近有什么正式观星点 → 哪个地点今晚适合 → 怎么去 → 到场怎么看

夜空入口：天象/时间优先
今晚有什么值得看 → 我所在地点何时看得到 → 天气与月亮是否允许 → 去哪里条件更好
```

两条路径最终汇合到同一个“地点 + 观测夜 + 时间 + 天象/目标”的上下文。

完整产品价值可概括为：

> 把“天象值得看、当地看得到、天气允许、地点足够暗、现场能够安全到达”合并为一个可解释、可执行的观星出行决定。

# 2. 产品定义

## 2.1 产品定位

《今晚去观星》是一款以观星出行决定为核心、以地图和夜空双入口组织信息的微信小程序。

它不是单纯的天气工具、天文百科、星图、光害地图或地点攻略，而是把这些能力组合为一条完整行动路径：

```text
发现今晚值得看的内容
→ 判断本地什么时候真正看得到
→ 比较天气、月亮、光害和地点条件
→ 选择正式观星点或合适区域
→ 核验道路、停车、设施和安全
→ 发起外部导航
→ 到达现场后继续查看方向、目标和时间
```

## 2.2 核心价值

### 对普通用户

用简洁结论回答：

- 今晚值不值得看；
- 几点最好；
- 去哪里；
- 最大问题是什么；
- 是否能停车、有厕所、道路是否可走；
- 到达后朝哪里看。

### 对专业用户

提供可继续展开的数据：

- 天象活动曲线；
- 辐射点或目标高度方位；
- 总云和分层云；
- 多天气模型差异；
- 晨昏、月亮、银河和主要目标；
- 光害数据集、年份、估算方法与现场实测；
- 场地遮挡、道路、设施和来源证据。

## 2.3 产品差异化

通用天气或天文产品通常回答“天空会怎样”；地图和攻略产品通常回答“地点在哪里”。本产品要回答的是：

> **这个天象在我的地点和时间是否有实际观测机会；若值得看，哪个正式地点最适合安全执行。**

## 2.4 不做什么

- 不做通用天气预报产品；
- 不做完整天文百科；
- 不在小程序内实现逐向驾车导航；
- 不把暗夜候选地点直接包装为安全、开放、可停车的正式观星点；
- 不以一个无法解释的总分替代所有事实；
- 不展示未经说明的“预计可见流星数量”；
- 不把生成式 AI 作为天气、天文、道路或安全事实源；
- 不优先建设公开社交信息流、主页外链和跨平台内容搬运；
- 不默认持续定位或保存完整夜间轨迹。

# 3. 产品目标与成功边界

## 3.1 核心产品目标

1. 用户能在 3 分钟内完成一次有依据的观星决定；
2. 用户能清楚区分“天象强”“当地能看”“天气允许”“地点可去”四件不同的事；
3. 用户能从任意地点查看夜空，但只有正式观星点才能获得完整的出行与安全结论；
4. 用户能看到最佳连续观测窗口，而不是只看到整夜平均或全球峰值；
5. 所有重要结论可追溯到数据来源、时间、模型、计算和核验状态；
6. 动态数据失败时，静态地点资料仍可用，且不会用逼真的假数据填补缺失；
7. 到达现场后，用户无需重新选择地点和时间即可进入黑红观测模式。

## 3.2 产品完成的判断

仅有页面、固定样例数据或静态星图不代表完成。一个核心场景必须同时具备：

- 真实输入；
- 实际状态变化；
- 可解释输出；
- 失败和降级；
- 返回和恢复；
- 数据时间与来源；
- 对应的用户下一步行动。

# 4. 目标用户与核心任务

## 4.1 事件驱动的新手用户

典型触发：听说今晚有流星雨、月食、行星或银河可看。

核心任务：

- 了解事件是否真的适合本地区；
- 找到本地最佳夜晚和时段；
- 找到天气更好、天空更暗的地点；
- 避免把全球峰值误解为本地最佳时间。

## 4.2 日常新手观星用户

核心任务：

- 今晚临时找一个能到达的观星地点；
- 直接知道是否值得去；
- 确认停车、厕所、道路和安全；
- 到场后知道朝哪里看。

## 4.3 有固定观星习惯的爱好者

核心任务：

- 比较多个正式点位；
- 查看分层云、多模型差异、晨昏和月亮；
- 查看当晚目标和最佳连续窗口；
- 收藏地点和建立计划。

## 4.4 星空摄影用户

核心任务：

- 判断银河、星轨、月亮或行星摄影窗口；
- 了解银河方向、月亮影响、前景和遮挡；
- 确认器材搬运、停车、徒步和末段道路；
- 阅读真实拍摄经验。

## 4.5 进阶用户

核心任务：

- 选择或比较天气模型；
- 查看总云、低云、中云、高云；
- 理解事件活动曲线、天文几何和模型分歧；
- 查看来源、版本、分辨率和置信度。

# 5. 核心产品概念

## 5.1 统一观测上下文

产品内所有夜空相关页面必须共享同一套上下文：

```text
观测上下文
├─ 地点：当前位置 / 普通地点 / 暗夜候选地 / 正式观星点
├─ 当地日期
├─ 观测夜范围
├─ 当前选择时间
├─ 天象事件或观测目标
├─ 天气预报口径
├─ 当前地图/云层图层
└─ 数据与算法版本
```

用户从夜空进入地图、从地图进入详情、从详情进入星图、从星图进入观测模式时，上下文不丢失。

## 5.2 地点的三级产品模型

### A. 普通地点

来源：当前位置、城市、景区、普通 POI、地址或地图任意点。

可以：

- 查看此处夜空；
- 查看天气、月亮、天象和光害估算；
- 移动地图；
- 查找附近正式观星点和暗夜候选地。

不能：

- 自动获得 `spot_id`；
- 显示未经核验的停车、厕所、开放或安全结论；
- 直接被包装为“推荐前往”。

### B. 暗夜候选地点

定义：由光害、天气、地形或人工名单发现的潜在观测区域，但尚未完成现场和通行核验。

可以：

- 显示光害估算；
- 显示所选观测夜的天气与天象机会；
- 参与“哪里可能更暗、更少云”的比较；
- 被收藏为候选地点；
- 关联附近正式观星点；
- 商用阶段发起新增观星点提案。

必须明确显示：

> 暗夜候选 · 未核验道路、开放、停车、设施和安全，不构成前往建议。

### C. 正式观星点

定义：拥有平台自有 `spot_id`，经过人工整理和最低资料核验，能够承担完整出行判断的地点。

必须包含：

- 可追溯位置；
- 道路和末段通行；
- 停车；
- 核心设施；
- 开放与限制；
- 夜间安全；
- 遮挡和光源方向；
- 实景证据；
- 最近核验时间；
- 数据来源。

正式观星点才可以输出：

- 推荐 / 可考虑 / 不建议 / 数据不足；
- “去这里”；
- 完整路线和设施判断；
- 正式观测计划。

## 5.3 天象事件

`SkyEvent` 是新增核心实体，用于表达有明确活动期或发生时间的天象。

至少包含：

- 事件名称与类型；
- 活动期；
- 全球或权威参考峰窗；
- 当地时间转换；
- 历史拟合、年度参考、模型预测或实时观测类型；
- 事件活动曲线或时间窗口；
- 辐射点/目标天体；
- 适用地区；
- 来源、年份和版本；
- 局限说明。

Demo 首先完整支持流星雨事件族。后续扩展月食、日食、行星冲日、彗星、伴月和空间站过境。

## 5.4 观测机会

“观测机会”与“天象活动强度”不是同一概念。

```text
当地观测机会
= 天象活动
× 当地天体可见性
× 黑夜和月亮条件
× 天气透过条件
× 光害与遮挡
```

对正式观星点，还需要叠加：

```text
出行可执行性
= 开放与合法进入
+ 道路和停车
+ 设施
+ 夜间安全
```

严重天气、地点关闭、道路封闭、非法进入或明确危险先执行硬阻断，不能被其他有利条件抵消。

## 5.5 最佳有效观测窗口

最终主要结果不是“全球峰值”或“整夜平均”，而是：

> 用户当前地点、当前观测夜中，天象、黑夜、月亮、天气和地点条件共同满足要求的最佳连续时段。

每个结果支持：

- 主窗口；
- 备选窗口；
- 窗口长度；
- 最大有利因素；
- 最大不利因素；
- 窗口结束原因；
- 数据置信度。

# 8. “夜空”一级模块

## 8.1 模块职责

夜空页首先回答：

1. 今晚有什么值得看；
2. 在当前地点什么时候真正看得到；
3. 天气、月亮和光害是否允许；
4. 是否需要换一个地点；
5. 到场后朝哪里看。

它不是专业数据首页。普通用户先看到结论，专业数据按需展开。

## 8.2 顶部观测上下文栏

固定展示：

- 当前地点；
- 地点类型；
- 当地日期；
- 当前时间；
- 当前天象或“日常观星”；
- 切换地点、日期、事件入口。

切换任一条件后，下面所有模块同步更新，不允许局部仍使用旧时间。

## 8.3 今晚观测机会卡

首屏主卡展示：

- 推荐等级；
- 最佳有效窗口；
- 备选窗口；
- 最主要有利因素；
- 最大不利因素或阻断；
- 适合目视、手机、银河、星轨或望远镜；
- 置信度；
- 数据更新时间；
- “去地图找更好的地点”。

普通地点和候选地点只输出“天空观测机会”，不输出完整“建议前往”。

## 8.4 当前重点天象卡

展示：

- 中文名、英文名/代号；
- 活动期；
- 权威参考峰值；
- 当前地点本地时间；
- 全球峰值发生时当地是否处于黑夜；
- 本地优先观测夜；
- 当前活动阶段；
- 活动曲线；
- 曲线类型和来源；
- “不是当地实际可见数量”的说明。

无重点事件时，自动切换为“日常观星条件”，继续展示银河、月亮、行星和普通目标。

## 8.5 统一时间轴

时间轴是夜空模块的核心交互，同一游标驱动：

- 天象活动强度；
- 辐射点或目标高度；
- 太阳高度和晨昏；
- 月亮高度、照明和方向；
- 总云、低云、中云、高云；
- 降水、风和能见度；
- 最佳窗口；
- 星空地图；
- 观测模式。

默认展示从当地傍晚到次日清晨的“观测夜”，允许跨午夜，不以自然日 00:00 强行截断。

## 8.6 天气展示

### 普通层

默认显示：

- 推荐预报；
- 总云；
- 降水；
- 风；
- 能见度；
- 最佳窗口内的变化。

### 专业层

展开后显示：

- 总云、低云、中云、高云；
- 温度、湿度、露点和结露风险；
- 风速、阵风和风向；
- 模型名称、更新时间、适用时间和空间精度；
- 多模型差异和一致性。

当模型分歧明显时，产品降低置信度并说明差异，不选择最乐观结果作为唯一结论。

## 8.7 月亮、黑夜、银河和目标

展示：

- 日落与天文黑夜；
- 月相、照明、月升月落、月亮高度与方向；
- 无月窗口；
- 银河核心出现时间、方向和高度；
- 主要行星和目标；
- 目标的可见窗口、方向、高度和原因；
- 适合的观测或拍摄方式。

## 8.8 详细专业数据

提供对齐的逐小时矩阵和图表，不把多个来源混成无说明数字。

字段支持：

- 天象活动；
- 辐射点/目标高度和方位；
- 晨昏和太阳高度；
- 月亮；
- 分层云；
- 降水、风、温湿度、露点、能见度；
- 光害和遮挡；
- 数据来源和模型。

## 8.9 简版星空地图

Demo 必须做到：

- 当前地点、日期、时间驱动；
- 方向环和地平线；
- 亮星、主要星座、月亮、主要行星、银河中心和推荐目标；
- 时间游标变化后重新投影；
- 与目标列表使用同一上下文；
- 传感器不可用时提供手动方向；
- 绘图失败时保留等价文字列表。

不要求首版完成 AR 和完整深空星表。

## 8.10 观测模式

只允许从已有夜空上下文进入。

要求：

- 黑色与低亮度暖红；
- 无白色闪屏、白色骨架和自动图片；
- 大触控目标；
- 时间、事件、最佳窗口剩余时间；
- 辐射点/目标方向和高度；
- 月亮、天气变化与风险；
- 离线与最后更新时间；
- 保持屏幕常亮选项；
- 回程地图；
- 退出后恢复原模式和页面。

# 9. 地图模块

## 9.1 默认状态

- 打开小程序默认进入地图；
- 不强制定位，先显示试点区域；
- 用户主动点击附近或定位时请求一次位置；
- 拒绝后继续支持搜索和手动地区；
- 恢复上次视口、缩放、时间、筛选、图层和选中对象。

## 9.2 搜索

搜索框建议：

> 搜索观星点、城市或想看的地方

结果分组：

- 正式观星点；
- 暗夜候选地点；
- 普通地点；
- 历史搜索。

结果行为：

- 正式观星点：进入统一详情；
- 暗夜候选：进入候选详情；
- 普通地点：移动地图，并提供“查看此处夜空”；
- 普通地点不能合成正式 `spot_id`。

## 9.3 地图时间条

地图底部或顶部提供紧凑时间条，显示当前观测夜和时间。

改变时间后同步更新：

- 云图；
- 天象机会；
- 点位天气摘要；
- 候选地点排序；
- 选中卡片。

静态路线、设施和实景不重复加载。

## 9.4 地图图层

### Demo 必须支持

- 普通地图；
- 正式观星点；
- 光害估算；
- 总云；
- 今晚观测机会。

### 专业增强

- 低云；
- 中云；
- 高云；
- 天象事件机会；
- 暗夜候选地点；
- 收藏点。

图层必须同屏显示：

- 图例；
- 数据来源；
- 数据年份或模型批次；
- 当前适用时间；
- 精度；
- 估算或预测说明；
- 加载/失败状态。

## 9.5 Marker 语义

为了避免颜色过载：

- 形状区分正式观星点和暗夜候选；
- 选中状态使用尺寸、描边和文字，不只靠颜色；
- 关闭、危险、数据不足使用独立图标；
- 光害和天气不同时使用同一色阶；
- 地图和无障碍列表共享同一选中地点。

## 9.6 地图卡片

正式观星点卡片展示：

- 名称和地区；
- 推荐等级；
- 最佳窗口；
- 光害；
- 距离或驾车时间；
- 停车、厕所、平台等核心设施；
- 代表实景；
- 数据更新时间；
- 查看详情。

候选地点卡片展示：

- 候选标签；
- 光害估算；
- 当前天气和观测机会；
- 数据来源；
- 未核验警示；
- 附近正式观星点。

## 9.7 筛选

首层筛选：

- 今晚推荐；
- 最佳窗口时长；
- 距离/驾车时间；
- 光害；
- 少云；
- 停车；
- 厕所；
- 可驾车直达；
- 摄影前景；
- 可露营/驻车。

高级筛选：

- 特定天象；
- 低云阈值；
- 月亮影响；
- 徒步难度；
- 信号；
- 充电；
- 天空开阔方向；
- 最近核验时间。

筛选遵循草稿—应用—取消—重置语义。

## 9.8 路线与导航

小程序内部展示：

- 直线距离和路线距离明确区分；
- 驾车时间；
- 徒步段；
- 末段道路；
- 停车点；
- 路线数据时间；
- 外部地图选择。

仅在用户明确请求时计算昂贵路线。完整逐向导航交给外部地图。

# 10. 正式观星点详情

## 10.1 页面结构

```text
固定头部
→ 概览
→ 场地
→ 夜空
→ 攻略
→ 固定底部操作
```

## 10.2 固定头部

包含：

- 返回；
- 名称；
- 收藏；
- 地址/区域；
- 正式点位标识；
- 光害估算；
- 距离和路线摘要；
- 最近场地核验；
- 数据来源入口。

## 10.3 概览

按行动优先级展示：

1. 今晚结论与最佳窗口；
2. 主要有利、不利和阻断因素；
3. 路线摘要；
4. 核心设施；
5. 代表性现场实景；
6. 当前活跃天象；
7. 重点攻略；
8. 来源与更新时间。

非本点位图片必须明确标记，不能证明现场事实。

## 10.4 场地

按真实到达顺序组织：

### 到达

- 道路；
- 末段路；
- 徒步；
- 夜间通行；
- 外部导航。

### 停车与驻留

- 停车位置、空间和限制；
- 驻车；
- 露营；
- 开放时间。

### 基础设施

- 厕所；
- 平台；
- 充电；
- 信号；
- 补给；
- 遮雨/休息。

### 观测环境

- 天空开阔度；
- 各方向遮挡；
- 光源方向；
- 前景；
- 适合的天区和拍摄方向；
- 实景照片与拍摄方向。

### 安全

- 临水、悬崖、落石、野生动物、弱信号；
- 结伴建议；
- 天气限制；
- 临时关闭；
- 非法进入；
- 撤离和返程。

每个关键事实显示来源、核验时间和状态。

## 10.5 夜空

与全局夜空共享数据与时间上下文，增加正式点位特有内容：

- 地平线遮挡；
- 光源方向；
- 现场前景；
- 当前天象在此点的本地窗口；
- 与其他收藏点的比较；
- 建立计划；
- 进入观测模式。

## 10.6 攻略

顺序为：

- 官方重点攻略；
- 路线和停车；
- 场地与安全；
- 观测；
- 摄影；
- 用户实测。

文章显示作者、类型、发布时间、最近更新、现场性和核验状态。

## 10.7 底部操作

- 收藏；
- 查看夜空；
- 去这里。

“去这里”为主操作，但存在阻断时必须先展示风险和确认，不允许无条件突出导航。

- 可分享专题页。

## 12.2 活动曲线类型

界面必须明确区分：

- 年度权威参考；
- 历史拟合；
- 物理/尘埃带模型；
- 实时观测汇总；
- 产品计算。

不同类型不能无说明地拼接成一条曲线。

## 12.3 全球峰值与本地有效夜

页面同时展示：

- 全球/权威峰窗；
- 转换后的本地时间；
- 当地是否处于黑夜；
- 本地最佳观测夜；
- 与峰值的相对活动；
- 月亮、天气和辐射点影响。

## 12.4 流星雨显示边界

- ZHR 只表示标准化活动参考；
- 不直接称为“你每小时能看到多少颗”；
- 首版使用“活动较弱/中等/较强/接近峰值”和“本地观测机会”；
- 未来如提供预计可见区间，必须显示假设、区间和置信度。

## 12.5 事件专题页

用于外部分享和自然增长，包含：

- 事件介绍；
- 本地观测夜；
- 当前地点机会；
- 活动曲线；
- 全国/区域地图；
- 推荐正式观星点；
- 数据依据与局限；
- 打开小程序继续决策。

- 伴月；
- 彗星；

- 重要深空目标季节窗口；
- 实时观测数据。

# 13. 决策逻辑

## 13.1 两类结论

### 天空观测机会

适用于所有地点类型：

- 很好；
- 较好；
- 一般；
- 较差；
- 数据不足。

只判断天空，不代表地点可安全前往。

### 出行建议

仅适用于正式观星点：

- 推荐；
- 可考虑；
- 不建议；
- 数据不足。

## 13.2 判断顺序

```text
第一步：数据完整性和新鲜度
第二步：严重天气、关闭、道路、非法进入和明确危险硬阻断
第三步：识别观测夜中的连续可用窗口
第四步：计算天象、当地可见性、天气、黑暗、场地和目标匹配
第五步：结合用户偏好排序和解释
第六步：给出置信度、主窗口、备选窗口和原因
```

## 13.3 主要维度

### 天象活动

- 活动阶段；
- 距峰值关系；
- 事件模型或观测状态。

### 本地天文可见性

- 辐射点/目标高度；
- 方位；
- 日落与晨昏；
- 月亮；
- 银河或目标窗口。

### 天气

- 总云和分层云；
- 降水和雷暴；
- 风和阵风；
- 能见度；
- 湿度、露点和雾；
- 多模型一致性。

### 黑暗与环境

- 光害；
- 月光；
- 天文黑夜；
- 遮挡；
- 光源方向。

### 场地与通行

- 开放；
- 道路；
- 停车；
- 徒步；
- 设施；
- 安全；
- 最近核验。

## 13.4 最佳窗口优先于整夜平均

地图列表可以把整夜平均作为辅助字段，但主结论必须寻找连续窗口。

示例：

```text
主窗口：23:40—02:10
原因：活动接近峰值、辐射点持续升高、月亮影响低、总云低于 25%
结束原因：02:10 后中高云明显增加
备选：21:50—22:40
```

## 13.5 多模型差异

- 默认使用“推荐预报”；
- 专业用户可查看不同模型；
- 模型差异进入置信度；
- 不允许后台无说明地挑选最乐观模型；
- 页面显示模型更新时间和适用时间。

## 13.6 个性化边界

用户偏好可影响：

- 点位排序；
- 路程接受程度；
- 必需设施；
- 徒步；
- 设备与拍摄目标；
- 解释重点。

用户偏好不能改写：

- 天气事实；
- 天文事实；
- 光害数据；
- 官方关闭；
- 安全硬阻断。

# 14. 数据展示与信任机制

## 14.1 统一来源标签

| 标签 | 含义 |
|---|---|
| 年度参考 | 权威年度日历或预测窗口 |
| 历史拟合 | 历史观测形成的活动曲线 |
| 实时观测 | 当前观测者汇总，不等于未来预测 |
| 第三方预报 | 天气或外部动态数据 |
| 产品计算 | 天文几何、窗口和规则计算 |
| 遥感估算 | 光害或其他空间模型 |
| 官方核验 | 运营或管理方确认 |
| 用户实测 | 有时间和地点的现场反馈 |
| 示例数据 | 仅演示，不得用于现实判断 |

## 14.2 时间字段

至少区分：

- 数据发布/模型起报时间；
- 数据适用时间；
- 产品获取时间；
- 产品计算时间；
- 场地核验时间；
- 用户观测或拍摄时间。

## 14.3 天气显示

显示：

- 模型；
- 起报批次；
- 适用时间；
- 空间分辨率；
- 时间分辨率；
- 是否插值；
- 缺失字段；
- 多模型差异。

## 14.4 光害显示

显示：

- 数据集；
- 数据年份；
- 估算方法；
- 空间精度；
- Bortle 区间或产品等级；
- 不确定度；
- 是否有现场 SQM；
- “不是现场实测”的提示。

不同年份、不同方法的图层不能直接做严谨排行。

## 14.5 缺失和过期

状态统一为：

- 实时/新鲜；
- 过期可用；
- 部分缺失；
- 已过期；
- 不可用；
- 估算；
- 示例。

规则：

- 缺失不显示为 0；
- 过期不显示为实时；
- 可用静态内容不因动态失败而消失；
- 关键数据不可用时不输出肯定推荐；
- 页面提供重试、换时间、换地点或查看静态资料。

## 14.6 冲突处理

- 严重天气与官方关闭优先；
- 近期官方核验优先于旧资料；
- 多条近期现场反馈可触发待复核；
- 天气模型分歧降低置信度；
- 用户反馈不能修改客观天文计算；
- 任何冲突都需保留来源，不静默覆盖。

# 19. 产品验收要求

## 19.1 导航与上下文

- 底栏始终为夜空—地图—我的；
- 默认地图；
- 夜空可无正式 `spot_id` 进入；
- 地点、日期、时间和事件跨页保持；
- 返回地图恢复视口、筛选、时间和选中对象；
- 观测模式退出恢复原上下文。

## 19.2 地点边界

- 普通地点不会合成正式点；
- 候选地点始终显示未核验；
- 正式点具备最低资料完整度；
- 只有正式点输出完整出行建议和导航主操作；
- 敏感地点按可见策略处理。

## 19.3 天象与时间

- 活动曲线显示类型和来源；
- 全球峰值与本地有效夜同时展示；
- ZHR 不显示成实际可见数量；
- 统一时间轴驱动天气、天文、星图和地图；
- 跨午夜观测夜正确。

## 19.4 天气与光害

- 支持总云、低云、中云、高云；
- 显示模型、更新时间和适用时间；
- 模型分歧降低置信度；
- 光害显示年份、精度、估算和非实测说明；
- 缺失不显示为 0。

## 19.5 决策

- 严重天气和地点风险先硬阻断；
- 主结果为最佳连续窗口；
- 显示主要有利和不利因素；
- 显示置信度；
- 普通地点只输出天空机会；
- 关键数据过期不输出肯定推荐。

## 19.6 正式点详情

- 分段顺序正确；
- 路线、停车、设施、遮挡和安全可追溯；
- 非本点实景明确；
- 动态失败不隐藏静态资料；
- 收藏、夜空、导航闭环可用。

## 19.7 观测模式

- 纯黑/暖红闭环；
- 无白色闪烁；
- 图片默认关闭；
- 离线与更新时间可见；
- 方向、目标和窗口共享同一上下文；
- 有等价文字信息。

# 21. 风险与产品约束

## 21.1 虚假精度

风险：ZHR、Bortle、云量和综合分看起来过于精确。

约束：显示类型、区间、年份、模型和置信度；避免精确可见数量承诺。

## 21.2 候选地点被误解为推荐地点

约束：视觉、文案、操作和详情结构均与正式点区分；候选不提供正式出行结论。

## 21.3 专业信息压倒普通用户

约束：首层结论、第二层证据、第三层完整数据；模型选择默认隐藏在专业入口。

## 21.4 地图信息过载

约束：一次只突出一个动态图层；Marker 不同时编码过多维度；保留等价列表。

## 21.5 数据源许可和年份混用

约束：许可、署名、数据年份和再分发边界进入产品与运营台账；不同数据集不无说明比较。

## 21.6 产品再次被实现反向改写

约束：核心需求使用稳定编号；后续代码、Screen Contract 和测试必须映射需求编号；改变导航、地点类型、夜空入口或结论边界必须先更新产品方案。

# 23. 最终产品概括

《今晚去观星》V2.0 的完整主线是：

> 用户可以从地图寻找正式观星点，也可以从某个流星雨、银河或其他天象出发；系统先区分天象活动与本地实际可见机会，再把当地黑夜、月亮、天气、分层云和光害对齐到同一时间轴，找出最佳连续窗口；用户随后比较正式观星点的道路、停车、设施、遮挡、实景和安全，完成收藏、计划和外部导航；到达现场后继续使用同一地点和时间上下文进入黑红观测模式。

这套产品结构保留了 V1.0“观星点出行决策”的核心，同时补齐了逐星擅长的“天象事件与当地观测机会”，形成从发现天象到安全执行的完整闭环。

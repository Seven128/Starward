## 三个方向的假设

1. **场地记录**：先建立对象，再以较短且连续的资料节奏理解下一步。地图名称用细竖线收束，区域退到辅助行，场地状态用无容器短句。我的先辨认账户，计划和反馈在同一轻表面内，计划对象为 15px；常规内容用较窄的行节奏。强调账户/地点身份，不把每个入口当标题。
2. **今晚对象**：地图先给区域，再突出正式地点；开放未知集中为紧凑的暖色证据条。我的把今晚计划作为唯一明显的对象区域，日期贴近对象、出发准备直接连到计划入口；反馈为紧邻的日常状态行，主页与导入再往下读。比方向一更强调“现在要处理的那一个地点”，代价是计划多占约 33px。
3. **内容工作台**：地图先定地点，再把开放与设施作为同层短字段共享横轴。我的压低计划对象的份量，把草稿与待审核两个真实状态明确并排，让进入内容处理的意图更容易发现。方向内仍只有同一计划与贡献职责，不新增统计。该方向先看状态分布，方向二先看计划对象，方向一先看账户和连续记录。

## 结构与边界

- 原生 Text、Auto Layout、Component、Instance；组件原件置于自己 root 的 x=width+80 裁切外侧，产品导出不显示说明。按钮实例与文案组件可以原生编辑。条目正文使用 HEIGHT 自动高度，外层初稿已按 fixture 确定尺寸；长文案与320/375/430仍待后续导出验证。
- 所有图使用共同未调色390×480 OSM参考，放在 y=88；正式点相对参考中心固定195/209。保留可读归属，节点保存版权URL和ODbL说明；native-map外观仍未验证。
- 地图 medium 保留一棵连续文档，先身份→左对齐概览/天文定位→位置/导航→开放与设施→资料/攻略/来源→天文→时间→客观事实。天文与时间在 medium 裁切下方，不造独立天气卡来“塞满”首屏。
- fixture 只提供一个21:00已选离散时刻，没有真实相邻切片。本稿在裁切下方仅放这个真实切片及中心标记，不编造20/22点等新切片。时间尺完整连续交互需由主任务提供真实时间序列后再补，不能将静态图称为拖动验证。
- 我的仅保留账户、单一设置、计划、现场反馈与纠错、主页链接、内容导入；没有收藏、会员或额外统计。每个数字来自共同 fixture。
- 已标控制 owners；handle 为80×44独占区域，tap无动作；概览/天文为同一文档定位；分享只在用户显式激活时发生；图层与面板的单一互斥 owner 保持原合同。
- 两页均保留44px系统区、44px微信区、56px主导航和34px底部安全区。截图内留白不填入假功能或营销内容。

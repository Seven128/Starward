# A 组初稿：三种紧凑组织方式

本稿只依据冻结 brief / fixture、当前 AGENTS、global 与指定微信 Context、根 DESIGN 和强制项目交互 Skill，以及共同机械 helper / 图标。没有读取新 Skill 的正文或 references，没有读取任何其他组、旧试验或评审。交付为六个原生 Figma 页面的参数化脚本，生产源与 Skill 未改动。

## A1 细线手册

地点以 19/26 的身份标题建立唯一重心，路线、设施用细线和共同基线归组，事实不逐项装卡。我的页以一个很浅的计划区为起点，反馈和常规内容成为连续短行。主次来自名称、内容、说明三级字级与靠近关系，避免标题与行内容同样大。

## A2 坐标索引

地图地点名称和区域同一身份行；开放与设施共享左侧字段轴，横向比较节省高度。我的计划把日期放在窄侧栏，地点和出发准备保持一条内容轴；计划与反馈共享一块中性表面。适合偏好明确字段、较少块状视觉的人。

## A3 轻量工具集

地图的开放与设施合成紧凑的局部事实带，其余仍是连续文档。我的页将计划和反馈放在同一个双列工具区，随后是主页链接与导入短行。两列按真实职责分组，草稿和待审数量保持文字，不放大为仪表盘统计。

## 可编辑结构与覆盖

全局接口为 `async function buildDesign({root,page,direction,width,height,mode,state,fonts,icons,mapImageHash,fixture})`。每方向均生成 map / my。Text 为真正 Text；内容、事实、列表、动作与导航使用 Auto Layout；图标和动作有原生 Component / Instance。masters 位于自己的 root 内 x=width+80，由 root 裁切，不污染导出画面。每个 hit 节点通过 StarwardFigma.control 绑定真实页面 owner。

地图 reference 固定 390×480，y=88，图片未调色、未重绘；marker 中心严格为图内 195/209。保留可读归属，外壳应链接 [OpenStreetMap copyright](https://www.openstreetmap.org/copyright)，并说明 ODbL。它不是腾讯 native 地图或 WEAPP 验证。

顶部保留 44px 系统区、44px 微信标题/胶囊区，底部保留 34px 安全区。导航只有地图 / 我的。我的所有 fixture 职责完整保留，设置仅一个 gear；没有会员、收藏副本或假计数。

地图是 medium：一份连续文档包含身份、开放与设施、场地/反馈/来源、天文标题、真实离散时间尺、给定天气/月光/时效和缺失信息，medium 只裁切。handle 是独立 60×44px 命中；tap 为 no-op。概览/天文是左对齐文字定位入口，选中短下划线，非内容 tab。底栏保留想去/分享/云观星。时间与部分天文内容处于 medium 下方裁切区域，不能宣称首屏可操作覆盖；layer sheet 互斥状态本轮未展示。large 才滚动的运行时交互、触觉、还原导航和真实地图仍待生产验证。

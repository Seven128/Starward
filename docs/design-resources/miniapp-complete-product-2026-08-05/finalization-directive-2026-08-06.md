# DRA 最终收口授权（2026-08-06）

## 用户授权

用户明确要求：完成当前累计需求变更后，不再停在逐页候选审计点，直接继续运行 design-resource-authoring（DRA）直至结束，包括：

1. 生成并校验完整需求范围的全量设计资源；
2. 对符合全部权威输入、累计已接受 delta 与设计系统的候选执行委托式最终选择；
3. 生成 Web/App 正式 selected implementation handoff；
4. 将累计已接受的需求变更一次、幂等地应用到两份原始方案；
5. 返回两份新版方案、全量选定设计资源与正式 handoff，随后结束 DRA。

本授权取代此前“每一轮先停下等待用户审计”的暂停点，但不扩大产品范围，也不授权修改 `project_context/**`、`DESIGN.md`、生产代码、测试或 Long-Task Contract。

## 委托式最终选择标准

仅当当前候选同时满足以下条件时才可选定；否则必须先修复并重新验证：

- 完整覆盖两份原始方案中本项目范围内的页面、流程、组件/控件、状态、交互、响应式、可访问性与资源信息；
- 完整纳入所有累计 `accepted-for-next-candidate` 需求 delta；
- 与 `DESIGN.md` 及 Open Design `designSystemId=user:soft-instruments` 一致；
- 通过本轮声明的 320 / 375 / 430 多视口、交互、可读性、资源依赖、控制台和内容一致性检查；
- 不把候选资源、示例数据或推测升级为产品/业务/算法事实；
- 不虚构第三方平台 API、品牌资产授权、精确点位实拍或生产能力。

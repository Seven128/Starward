本文件是搜索页唯一有效的资源采用入口。

2026-09-08 用户确认搜索页完成，采用[日间搜索页资源](adopted/search-page/README.md)：最终单行筛选、二级分类弹层、分组开合、同框拉出和地址对齐修正版。

现行筛选语义以 [Map/Search Screen Contract](../../../../project_context/areas/main/screen-contracts/wechat-miniapp/map-and-finder.md) 的14项终端值为准；采用包内18项是当时的构图样本，不恢复已退役选项。

采用覆盖自有日间UI、可展示的浏览器交互与本包说明的状态。实际整卡选点→原地图重定位→同一点medium信息组件仍由Screen Contract约束；用户允许该链路不在静态地图资源中演示。生产已迁移本页主要布局与交互；已验证范围和缺口以当前WEAPP用例证据为准，资源本身不证明完整WEAPP或真机通过。

2026-09-25 搜索输入竞态补查：当前官方WEAPP中从“深圳”改输“香港”后约55毫秒，旧深圳正式点建议仍可点，虽新输入已显示香港；这是生产请求节流期间的旧结果泄漏。当前生产在输入与已发查询未同步时隐藏旧建议及正式结果，保留搜索节流，并展示“正在查找地点／搜索结果更新中”。同一默认8787重建包、确切项目清编译缓存后，约53–58毫秒抽样已不见旧行，387×836原图 `search-debounce-after.png` 可读等待态；稍后香港结果为空，原地图所选正式点及输入原值已恢复。此处记录生产修复，不改变当前视觉采用范围，也不替代其它搜索状态、真机或独立审阅。

2026-09-25 同查询缓存续查：重开同一个“深圳”查询时，旧正式点建议和卡片曾在受控已下架响应仍未返回时重新可点；地址搜索返回空后，地图结果的60秒缓存又继续留下旧卡片。当前生产对有输入的搜索结果重新校验两份资源，等待期不显示可操作旧点；两接口均确认受控成功空后走公共空态。若两接口同时失败，既有旧结果按陈旧态保留，一次“重新获取”会重试全部失败资源。修后官方WEAPP与本机可撤销响应代理的387×836原图见任务证据：`search-cache-revalidation-before.png`为等待、`search-cache-revalidation-after.png`为空态，另有`search-cache-failure-stale.png`/`search-cache-failure-recovered.png`；代理已停止、默认8787整包已重建并在确切开发器项目重新编译。修前截图被探针同名覆盖，不引用为留存证据。此为局部实现证据，不扩展采用范围，也不证明实际下架发布、正式服务或真机。

2026-09-25 结果分区开合续审：当前官方WEAPP原实现直接卸载卡片，约40毫秒从158高跳到48高，未实现采用资源的保留内容树与连续开合。Search现让“想去”和“其他观星点”共用保留节点的分区组件，按实际内容高度逐帧折叠并允许运动中反向，减少动态偏好直接落终态。仅切换CSS过渡类的初稿在官方模拟器中仍跳变，常驻过渡类初稿甚至保持原布局高度，均未作为最终实现。最终默认8787包在同一正式结果中读到收起150→75→48、展开48→约125→150的中间几何值，卡片节点在收起/展开/反向后保留；另一空分区占位保留且不影响相邻结果。原始387×836展开/收起图`search-partition-final-frame-{open,closed}.png`已查看。抽样不能证明每个160毫秒中间帧、系统辅助焦点或真机触摸节奏；采用范围不变，详见任务A03台账。

2026-09-25 真实无匹配结果续审：官方WEAPP搜索“香港”且全部地点与正式点均空时，旧页面把公共章节级“暂无数据”卡置于顶部，后面重复两个0分区，没有可执行换词入口。当前生产在整页真空时使用已采用共享空态的页面层级与本页身份“没有匹配的观星点”，提供“换个名称”清空并聚焦搜索；原筛选条、平台选点与返回地图仍可用。原始387×836修前/修后图及点击后重新得到深圳正式结果的目标运行时证据见任务A03/A13台账；失败、陈旧和局部缺测仍用各自状态，未把共享画板扩展为Search整套视觉采用。

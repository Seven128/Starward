# 共享 Info 提醒与“暂无数据” · 当前采用设计资源

2026-09-24 预报范围公共消费者续查：`ForecastCoverageNote` 原把无范围标题直接写成字段级“暂无数据”，现按章节级共享 `StatusPanel` 显示“暂无可用预报时段”，并按地图云量、地点天气/计划、空气质量分别说明实际覆盖；更新失败且只留旧范围时标明“上次获取”，旧范围为空时不叠加真空态。四处消费者传入各自请求状态，失败与恢复仍归页面/查询 owner。官方 WEAPP 390×844 逻辑视口在本机只读响应变体中看到地图云量实际零小时章节空态，恢复默认8787构建、精确清该地图响应缓存后原日期重新显示真实范围；其他三处的无范围和失败组合尚缺目标运行时复测。这项实现沿用本资源现有采用范围，不新增采用决定。

2026-09-23 用户审阅确认本设计；采用范围是小程序跨场景的悬浮 Info 与三层“暂无数据”视觉表达。各页原采用资源在其他构图和状态上继续有效；2026-09-24 已将共享表达迁入生产 `notification.tsx`、`status-panel.tsx` 及其受影响消费者；日间 390×844 模拟器已观察列表空态、浮动消息和独立请求失败恢复的部分场景，夜间、红光、其他宽度及真机触摸/安全区仍待验证。当前可编辑 Stitch 项目中的画板为 [08｜共享 Info 提醒与暂无数据](https://stitch.withgoogle.com/projects/7144519510537620825)；本地保存了[可独立打开的 HTML/CSS 源](preview/index.html)和[完整画面](preview/board.png)。`stitch-input/current-stitch-srcdoc.html` 是从刷新后的当前画板读取的原样源，`preview/index.html` 仅移除了 Stitch 编辑器注入的脚本、样式与游标，保留了产品设计内容。Stitch 修订覆盖了同一画板，未生成第二套页面。

2026-09-24 追加核查发现生产计划/成就空页仍显示通用“暂无数据”，已改为各自页面身份、适度留白和有效入口；共享 `StatusPanel` 现区分字段、章节和整页层级。对旧数据刷新失败时的列表/成就/来源/事件空结果加以排除，避免失败与真空态叠加。394×853 物理截图对应390×844 WEAPP 模拟器，已看到计划、成就真空页；其他空错切换与真机安全区/触摸仍须按最终候选补证，不能把静态画板当生产通过。

2026-09-24 后续官方模拟器复核发现创建/反馈记录列表仍使用私有空态，且缓存刷新失败时与“暂无记录”并列。现已改用共享 `StatusPanel` 的整页 EMPTY，只在确认为当前空结果时展示；用本地内存测试接口依次复核真实空结果、停服后的 STALE 与“重新获取”、恢复后的真实空结果，三态不再叠加。截图约387×836物理像素；这项不扩展为其他网络或真机状态的验收。

同日搜索页在官方 WEAPP 真空结果后停服复核，曾同时显示 STALE 与公共 EMPTY，并在两个分区重复断言“没有”。搜索页现以 Query 的刷新失败/旧值优先判定状态，未确认时隐藏分区空句；公共 `StatusPanel` 仍负责共享表达。当前390×844逻辑视口、本地内存测试服务的空结果→停服→恢复重试三态已分别观察，未把静态画板或其他未测搜索条件算作通过。

同轮地点公开分享页及共享 Canvas 海报已改用公共字段缺值文案“暂无数据”；当前本地正式点样本字段齐全，因此其缺值样式尚未用真实 WEAPP 空字段逐项复核。

2026-09-24 官方 WEAPP 复查发现 Map 的共享悬浮 Info 与搜索主入口完全重叠。Map 消费者现按实际安全区搜索框的位置把通知放在搜索下方，并收窄至右侧地图工具左边；公共宿主仍负责可见计时、触摸暂停与去重。390×844 逻辑视口的正式点空气质量异常样本已量测：搜索框 `y96.9–148.9`，通知 `x16–310、y156.9–229.9`，右侧定位按钮从 `x326` 开始；按住通知超过4秒仍可见，松手后按剩余时间消失。320/375/430、不同模式和真机仍待目标运行时验证，不能由这一 Map 样本推定其他消费者没有遮挡。

空气质量字段补查发现服务端明确返回 `REQUEST_FAILED` 时，原页面仍给对应字段一个公共 EMPTY“暂无数据”，同时在同区提供失败重试。现按两个独立片段分别判定：失败片段用公共错误状态与本节重试，可用片段保留原值；只有缺测或到期片段继续使用字段空态。该组合的现有组件回归先在修前失败，再在修后通过；WEAPP 实际字段组合与第三方服务仍单独验证。

2026-09-24 继续检查消费者时发现观星点攻略与场地资料路由在缺少地点/Context身份时，把无效入口显示为共享 EMPTY“暂无数据”。当前生产改为明确“观星点无法确认”的 ERROR，并保留“返回地图”；官方 WEAPP 模拟器两个无参数路由的按钮都实际返回 Map，正常 Map→正式点→攻略→文章仍可达。场地资料旧路由的有效数据入口、本机以外的失败组合及真机仍未由此证明；共享 `StatusPanel` 的采用外观与职责没有改变。

同日正式点地形章节的夜光读取失败曾沿用无覆盖文案，即使有效地形图像和重试按钮仍在，也把请求错误说成“暂无数据”。章节消费者现按失败标记显示“暂时无法读取，请重试”，真正无覆盖继续显示来源给出的覆盖范围；公共共享状态职责未改。本机只读代理注入夜光失败的官方 WEAPP 390×844 模拟器已看到有效地形、失败文案与重试按钮，之后恢复默认接口构建及正常覆盖响应；真机和实际供应商故障仍待验证。

继续核查旧无覆盖结果刷新失败时，地形章节会同时显示公共 ERROR 与“地形：当前地区暂无数据”，地图图层选择器仍把旧空结果当当前状态禁用。两处现共用地形图层状态判定，请求或供应商失败优先于旧空结果，恢复后才按当前覆盖结果显示。该转换已有修前失败、修后通过的组件回归；官方模拟器只观察了当前正常数据的地图图层和正式点章节，旧空结果随后刷新失败的连续目标运行时过程尚未验证。

地图光污染选择器原用字段缺值的“暂无数据”卡表示整个图层无覆盖，旧空结果刷新失败还可能继续显示真空。当前地图消费者已按共享状态层级改成紧凑章节空态，并在本地只读故障代理下以官方 WEAPP 连续观察真空→刷新失败→重试恢复：失败期间抽屉只保留一张有有效“重新获取”的 STALE 卡，地图背景不再叠第二张同故障恢复卡；恢复后回到已确认的章节空态。该证据限定本机接口与390×844模拟器，不证明真实夜光正向覆盖或真机。

同一原图发现章节空态的已采用 Info 图标在地图主包缺失；公共 `StatusPanel` 的默认章节图标同时被主包、content、spot及sky来源页使用。现由打包清单给主包与sky分包补齐同一采用图标，把无运行时读取方的第三方依赖许可证清单从主包移到content分包以维持主包预算；许可证仍随小程序交付。最终默认接口包的地图光污染真空原图可见该图标，四包文件存在检查与生产包预算通过。sky内部交互没有在本Goal复测。

公共 Info 的多条与跨页复查：当前宿主可同时显示前三条，第四条排队待显示；官方模拟器中第四条在前一批消失后出现。修前从地图切到“我的”时，地图消息会继续覆盖“我的”计划卡；共享队列与宿主现按消息发出时的页面路由筛选，模拟器从地图切到“我的”可见消息数归零，返回地图仍有该页未过期消息。该抽样使用已撤销的本机诊断注入入口。最终默认构建也读到地图真实空气质量失败通知及“我的”页零通知，但其短暂计时不足以单独证明跨页筛选；其它页面组合及真机安全区仍待验证。

## 两个共享职责

| 单元 | 消费者与范围 | 当前采用表达 |
| --- | --- | --- |
| `notification-feedback` 的 floating info | Map、Search、点位天气/地形、Sky、My/Settings、事件弹窗等异步结果。各消费者只填自己的对象、结果和必要下一步。 | 顶部安全区内的白色轻抬升条；小语义图标、完整短句、安静关闭。文案一句为主，最多两句；较长时可换行，不截断关键结果。相同几何可承载轻警告或完成回执。 |
| `page-state-recovery` 的 EMPTY 表达 | 点位字段值、点位章节、计划/记录等列表或整页。 | 字段沿用 label/value 轴的次要文字；章节在原阅读轴上使用小图形、短标题和必要范围；真正空列表保留页面身份与可执行入口，使用适度留白。请求失败使用不同文案和真实重试，不能与真空态同时出现。 |

悬浮层的宿主、安全区、最多三条、可见计时、触摸暂停、去重与单宿主归属，以及错误的持续恢复路径，继续由 [Shared State owner](../../../../../project_context/areas/main/screen-contracts/wechat-miniapp/shared-state-and-recovery.md)规定。具体数据/缺测/错误不由这张画板判定。行内通知与权限恢复保留原合同，本资源只控制所示 floating info 和三层 EMPTY 视觉样例。

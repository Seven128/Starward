# 产品逻辑与真实接口核对

## 点位存在、资料覆盖和请求状态是不同维度

- 没有正式可见记录：不创建该点位面板。地图空白位置、投稿候选、撤下/不可见记录不能伪装正式点。
- 有正式记录且资料可用：展示实际身份、位置、进入/安全事实及其他可用内容。
- 有正式记录但部分字段缺失：保留已知事实，缺失项局部表达；可选空模块不造空卡。已知“没有厕所”是设施不存在，不能写“暂无数据”；未知厕所情况才是缺失。
- 有记录但请求加载、网络失败、旧数据或天气不可用：不等于记录不存在。已知身份和仍有效内容保留，失败范围有恢复；收到确实不可用/撤下的记录结果再清理关联展示。

本轮使用虚构“星湾观星点”及明确标记的fixture展示内容较完整、部分缺失和无记录；不是生产数据，不代表当前发布策略已经允许所有这些字段组合，也不代表实时天空事实。

## 投稿与公开的实际差异

依据：`apps/wechat-miniapp/src/content/contribution/contribution-model.ts`、`contribution-form-derived.ts`、`workers/miniapp-api/src/contribution-validation.ts`、`spot-completeness-policy.ts`、`packages/miniapp-contracts/src/types.ts`。

现有新点输入是名称、地区、坐标、日期/时间、主题、说明及权利/位置确认；服务端提交还要求至少一个主题、至少20字说明，含图时必须上传成功并确认权利。开放/合法进入/夜间安全目前只是主题与合并后的场地字段，不是投稿的三个独立结构化值。门禁/负责人联系电话没有正式类型字段。前端对新点要求日期时间，后端只强制现场反馈的observedAt，存在采集规则不一致。

现行正式发布比最小投稿严格很多：身份/坐标/来源、30天内核心证据、道路和停车说明、八种设施各一项状态（不能全未知）、开放/合法/夜间安全/显式危险、地平线、卫星夜光、媒体有无声明等。不能仅修改表单就声称“最小信息可公开”。

建议的最小采集结构：名称、地图选点（保存权威坐标，地区等可推导）、开放状态、合法进入、夜间安全、门禁/负责人联系方式。状态需允许明确“不了解”以诚实接收线索；是否可公开由独立核验规则决定。电话是核心采集项，不代表必须有号码：可填写可公开号码，或明确无门禁/无公开号码/未知，不允许编造号码以通过必填；投稿者自己的手机号不自动转为公开联系人。

新点已完成结构化核心采集时，不再需要凑20字的无意义说明或重复选主题；长限制、现场时间、来源证据、照片及更多设施按适用条件补充，保留真正必要的权利和定位确认。已有点纠错可以只改受影响字段，不能要求重填完整新点资料。审核、合并和公开仍是不同结果。

用户随后要求同步修改产品逻辑；已将核心身份/进入/安全核验后公开、其余资料逐步补齐写入产品Context。电话允许无/未知，禁止把风险未知视为安全。后端策略、生产表单和存储尚未迁移；没有修改任何实际发布状态。

## 天文：实际输出、表达和缺口

| 实际类型/字段 | 设计表达 | 边界 |
| --- | --- | --- |
| `HourlySkyRow.at` 与 `ObservationContext.selectedAtUtc` | 一个浅弧离散时间尺；标明当前日期/时间 | 所有数值和targetFrames跟随同一片，不能用日均值顶替 |
| total/low/mid/high cloud | 总云＋低中高共享一组对齐列 | 云层比例不机械相加，0有效，缺失不归零 |
| temperatureC/relativeHumidityPercent/dewPointC | 温度/湿度/露点三关联短值 | 不用每个标量占一整行 |
| windKph/windGustKph/windDirectionDeg | 风速、风向和阵风相邻 | 单位一致 |
| precipitationMm/probability/visibilityKm | 降水量、概率、能见度共享列 | 能见度不是大气透明度 |
| moonAltitudeDeg/moonIllumination/darkness | 月亮高度、照明比例、天文夜状态 | illumination按比例转百分数；负高度不显示成地平线上可见 |
| `SkyTargetFrame.targets` | 当前目标名称、方向、高度的紧凑对象行 | 属于当前时间片；不沿用生产旧“适合目标”推荐摘要 |
| `LightPollutionEstimate.productBand/radiance` | 卫星夜光估算等级，辐亮度和方法可追溯 | `calibratedSkyClass:false`，不能写精确Bortle/SQM |
| `modelConsistencyLabel/modelSpreadPercent`、weatherEvidence.modelRuns | 共享摘要，专业详情追溯模型、版本/有效期/差异 | 不挑最好模型拼成单一预报 |
| `weatherEvidence.alerts/warningState` | 活动重大预警当前层突出；失败有其影响说明 | 读取失败不是“无预警”；成功且无预警不造空卡 |
| `SkyReport.sources`与SourceSummary | 可读来源句＋明确详情入口 | 更新/有效时间、缺失/过期按实际范围说明 |

目前公开`HourlySkyRow`/`SkyReport`没有独立透明度、视宁度测量字段，也没有结构化日/月升落事件数组；`moonSummary`是文字摘要，不能当结构化事件端点。设计对未覆盖能力明确缺项，不用能见度推导透明度、不编造角秒或升落时刻；后续若保留对应产品职责，需要在BFF补正式来源与类型输出。

当前Map面板的`panelAstronomyFacts`实际只映射总云、低/中/高云和月光影响；面板还渲染`decision.skyOpportunity.suitableFor`，与当前Context禁止推荐型“适合目标”的要求有差距。新资源按客观时间片/目标事实设计，生产迁移时需使用已有SkyReport owner并补齐投影，不能只换CSS。

## 设施照片的数据关联缺口

当前`FacilityEvidence`没有照片字段；`RepresentativeMedia`属于spot.media，`ContributionMediaUpload`只有上传信息，均无确定的停车/洗手间归属。不能用“场地首张图片”填两个设施。

需为媒体建立明确的点位＋设施类型关联，复用现有媒体授权、来源、拍摄者、审核和清晰原图/缩略图能力。投稿上传时选择照片对应停车/洗手间/场地总览，审核后保留归属；图库只打开当前设施的适用图。图片是可选资料，不因无图删除已知设施事实。

卡片使用该设施缩略图，只有图像层轻微虚化并加浅色可读遮罩；文字/icon不滤镜。点击打开清晰原图，关闭返回同一点、档位和滚动位置；无图/失效则纯色卡且无假图片入口。图片区展示可用图的数量，取代重复的“查看图片”长按钮。设计预览素材均为示意，不进入生产媒体库。
